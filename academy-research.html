微软 GraphRAG 原始论文。问题定义极为清晰：传统 RAG（论文中称 vector RAG）"fails on global questions directed at an entire text corpus, such as 'What are the main themes in the dataset?'"，因为这类问题本质是 query-focused summarization (QFS) 而非显式检索任务；而以往 QFS 方法"do not scale to the quantities of text indexed by typical RAG systems"。方法为两阶段图索引：先用 LLM 从源文档抽取实体知识图谱（节点为实体，边为关系），再用 Leiden 算法做社区检测将图划分为层次化的紧密相关实体群组，为每组预生成社区摘要；查询时对各社区摘要做 map-reduce——map 阶段各社区摘要独立并行生成部分答案，reduce 阶段把所有部分答案再次摘要成最终全局答案。v2 版将方法正式命名为 GraphRAG，作者阵容为 Darren Edge、Ha Trinh、Newman Cheng、Joshua Bradley、Alex Chao、Apurva Mody、Steven Truitt、Dasha Metropolitansky、Robert Osazuwa Ness、Jonathan Larson（Microsoft Research / Strategic Missions and Technologies / Office of the CTO）。实验结论：在百万 token 量级数据集的全局 sensemaking问题上，相比 vector RAG 基线在 comprehensiveness（全面性）与 diversity（多样性）两方面均有显著提升。

Model Context Protocol Specification（当前最新版本 2026-07-28）

MCP 官方规范最新版本。规范明确：MCP 使用 JSON-RPC 2.0 消息在 Host / Client / Server 三者间通信——Hosts 是发起连接的 LLM 应用，Clients 是 host 应用内部的连接器，Servers 是提供上下文与能力的服务。设计灵感来自语言服务器协议（LSP）。Server 向 client 提供 Resources、Prompts、Tools；Client 向 server 提供 Elicitation。重要演进：2025-06-18 版为 stateful connections + 连接级能力协商，最新版 2026-07-28 已改为 stateless, self-contained requests + per-request capability negotiation，Sampling 与 Roots 已被移出核心特性清单。

2 官方文档 2025-06-18

MCP Transports 官方规范（stdio 与 Streamable HTTP）

定义两种标准传输：stdio 与 Streamable HTTP，并规定「客户端 SHOULD 在可能时支持 stdio」。stdio 的机制是 client 把 server 作为子进程启动，从 stdin 读 JSON-RPC、向 stdout 写；server MUST NOT 向 stdout 输出任何非 MCP 消息的内容。关键结论：Streamable HTTP 已取代 2024-11-05 版本的 HTTP+SSE 传输。安全警告：server MUST 校验所有入站连接的 Origin 头以防 DNS rebinding 攻击；本地运行时 SHOULD 仅绑定 127.0.0.1 而非 0.0.0.0。
