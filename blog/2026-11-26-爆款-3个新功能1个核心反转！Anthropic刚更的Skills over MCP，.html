别再只堆工具！4个能力看懂Skills over MCP，智能体开始交付完整工作流

工具越接越多，操作说明却散落在提示词和文档里；长任务耗时等待，关键步骤又缺少中途确认。2026 年 11 月 24 日，Anthropic 发布 Skills over MCP，并同步更新 Tasks、Elicitation 与 File Uploads 的进展，试图补上智能体工作流中的这几块拼图。

先搞懂核心变化：Skills over MCP 到底改了什么？

工具名称和描述能说明服务器“能做什么”，却未必包含特定场景下“怎样组合工具、遵循哪些步骤”。Skills over MCP 要补上的正是这层可复用的工作流知识；它不是替代 MCP 工具，而是让工具与操作指引一起分发。

它是在现有工具、资源等能力之外，增加技能发现与读取方式：

【官方事实】MCP 服务器可以把技能作为包含 SKILL.md 和可选支持文件的目录发布；客户端可发现技能元数据，并在需要时读取说明和支持文件。Anthropic 公告称，Claude 会按需加载技能，技能随服务器更新，用户无需另行安装。

可以把工具理解为厨具，把技能理解为菜谱：厨具说明介绍单个工具能做什么，菜谱则规定做一道菜的步骤与参考材料。两者配合，才能把一个服务能力变成可重复执行的工作流。

四个核心能力，把智能体工作流拆明白

这次公告涉及四项能力，但“公测”“正式发布”和“即将推出”不能混为一谈：

  1. Skills over MCP（公测）：服务器向客户端提供工作流说明和支持文件。MCP 规范中的 SEP-2640 已为 Final，但 SDK 与宿主支持仍在推进，实际覆盖需查看客户端支持矩阵。
  2. Tasks（已正式发布）：服务器可把耗时操作乃至完整的 agent loop 作为后台任务运行，Claude 继续处理其他工作，并在结果就绪后取回结果。
  3. Elicitation（已正式发布）：服务器可在调用过程中暂停，通过表单或链接向用户请求输入，再从中断处继续；官方举例包括付费操作和删除数据前的确认。
  4. File Uploads（尚未上线）：该扩展用于让 Claude 把 PDF、电子表格和图片等文件传给 MCP 服务器，而无需把文件内容放入上下文窗口；官方表述为 rolling out soon，不能写成当前已可用。

四项能力各有分工：Skills 提供流程说明，Tasks 承接耗时操作，Elicitation 补充中途输入，File Uploads 未来面向文件传输。它们彼此互补，但不代表所有客户端已经支持，也不意味着可以取消用户确认和权限控制。

对开发者和普通用户，有什么实际影响？

对普通用户而言，变化在于工作流说明可以随服务一起交付，减少手工整理提示词的负担。【假设场景，非官方客户案例】一个报销 MCP 服务器可以把发票核验、规则匹配和提交前确认整理成技能；用户是否能使用，仍取决于服务器实现、客户端支持和账号权限。

【作者建议】公测阶段先选择来源可信、权限边界清晰的 MCP 服务，验证技能是否按预期加载，不要向陌生服务器授予过高权限。File Uploads 与 Skills 是不同扩展，前者不是后者生效的前提。

对 MCP 服务器开发者而言，交付物可以从“工具集合”扩展为“工具 + 场景化工作流”。按照 MCP 官方规范，一个技能是包含 SKILL.md 的目录，并可附带支持文件；下面代码依据官方 code-review 示例简化：

【作者建议】开发者可以先梳理现有工具的高频流程，再依照规范制作技能，并在发布前检查 SDK 与客户端支持矩阵。规范要求宿主把技能内容视为不可信输入；代码执行和权限授予需要明确的逐技能用户批准，文件变更也会使既有批准失效并需要重新批准。

别踩坑：这三个误区要分清

第一，Skills over MCP 不是封闭私有协议。公告明确说明，这些功能属于开放 MCP 规范及其扩展，兼容客户端并非仅限 Claude；但规范开放不等于所有客户端已经支持，实际覆盖仍以支持矩阵为准。

第二，Skills 不是系统提示词的替代品。系统提示词管理对话的全局规则，Skills 提供服务器针对具体场景的工作流说明，两者可以同时存在。

第三，公告中的四项能力并非同一时间全量开放。Skills over MCP 处于公测；Tasks 和 Elicitation 在公告所列的 Pro、Max、Ultra 套餐上正式发布，并向 Team 和 Enterprise 组织逐步推出；File Uploads 仍是即将推出。

【作者建议】不要把“规范已发布”理解为“所有客户端已兼容”，也不要在生产工作流里直接假设某项能力可用；先核对账号、客户端和服务器支持，再做迁移。
