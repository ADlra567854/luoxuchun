开源项目逐个上手手册（安装 · 一键使用 · 打包下载 · 手机端）

把上一篇文章列出的项目，逐个讲「怎么装、怎么一键用」。命令以各仓库 README 为准，这里给最省事路径。

〇、先装两样地基

  1. Git：从 git-scm.com 装，clone 仓库要用。
  2. Docker：从 docker.com 装 Desktop 版，多数项目一条命令就能起。
  3. Ollama：ollama.com 下载装，本地跑模型的地基。

一、对话式「壳」：把模型变成网页软件（能对话、能打包下载）

Open WebUI（最主流）

作用：给 Ollama/DeepSeek/OpenAI 套一个漂亮的网页聊天界面，等于自建一个「本地 ChatGPT」。

# Ollama 和 Open WebUI 都在本机时：
docker run -d -p 3000:8080 \
  --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  --name open-webui --restart always \
  ghcr.io/open-webui/open-webui:main

打开 http://localhost:3000，注册第一个账号就是管理员，选模型即可对话。想要「一键打包下载」给别人，用 docker save 导出镜像，或把项目推到 GitHub 让别人 docker compose up。

备选：LobeChat、NextChat，用法几乎一样，都是「套壳 + 接模型」。

二、AI 编程 / Agent 类

1. Goose（开源 AI 程序员）

# macOS / Linux
brew install block/tap/goose
# 或 Python 3.10+
pip install goose-ai
# 先本地跑一个模型
ollama pull qwen3
ollama serve
# 启动，按提示选 Ollama provider
goose

2. Hermes Agent（会成长的 AI 助手）

# Linux / macOS / WSL2（Android 的 Termux 用同一条）
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
hermes

要求模型上下文 ≥ 64K，否则多步工具调用会内存不够。

3. OpenHands（AI 驱动开发平台）

docker run -it --rm --pull=always \
  -e SANDBOX_RUNTIME_CONTAINER_IMAGE=docker.all-hands.dev/all-hands-ai/runtime:0.54-nikolaik \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -p 3000:3000 docker.all-hands.dev/all-hands-ai/openhands:latest

打开 http://localhost:3000，填入你的模型 API Key（OpenAI 兼容，可接 DeepSeek）。

4. claude-code（终端 AI 编程 Agent）

npm install -g @anthropic-ai/claude-code
claude

5. deer-flow（字节 · 长时域 SuperAgent 框架）

git clone https://github.com/bytedance/deer-flow.git
cd deer-flow
make setup   # 生成配置文件
make dev     # 跑起来，默认 http://localhost:2026

推荐模型：Doubao-Seed-2.0-Code / DeepSeek v3.2 / Kimi 2.5。

6. trae-agent（字节）与 TradingAgents（金融多 Agent）

  • trae-agent：字节的通用软件工程 LLM Agent CLI，按 README 安装后以 CLI 方式运行。
  • TradingAgents：金融多 Agent 框架，适合做「AI 投研/交易策略」实验，git clone 后按 README 配 API Key 即可。

三、网络安全类

1. Shannon（全自动白盒 AI 渗透测试）

git clone https://github.com/KeygraphHQ/shannon.git
cd shannon
npx @keygraph/shannon setup          # 配置模型凭证
npx @keygraph/shannon start -u https://your-app.com -r /path/to/your-repo

它分析源码、找攻击面、执行真实利用并出报告。只测你自己或已授权的系统。

2. REDCELL（AI 红队平台）

docker compose -f docker-compose.dev.yml up -d

需要 Docker、uv、bun；在设置里填模型 API Key，并让它能拉取 Kali 镜像。

3. SecSuite / CyberSentinel AI

  • SecSuite：开源情报 + Web/API 扫描 + AI 分析一体化，git clone 后按 README 跑。
  • CyberSentinel AI：融合 33 款渗透工具 + 可离线推理（Ollama），适合一键部署成自己的安全台。

四、手机端怎么跑开源项目

路线 A：Termux + Ollama（Android）

  1. 装 Termux（终端模拟器）。
  2. 在 Termux 里装 Ollama：pkg install ollama（或按 Termux 官方步骤）。
  3. ollama pull qwen3:1.5b 之类的小模型，ollama serve。
  4. 装 PocketLLM，连 http://localhost:11434，手机本地离线对话。

路线 B：现成离线 App（零命令）

  • LocalMind：Android 端 100% 离线，用 llama.cpp 跑 GGUF，从 Hugging Face 下模型。
  • TinyAI：设备端推理（MediaPipe GenAI / LiteRT-LM）。
  • LLM-Hub：手机本地 AI 助手，CPU/GPU/NPU 加速，支持多格式模型。

iPhone 端受系统限制，通常用轻量本地模型 App，或直接连云端 API（DeepSeek / ChatGPT）。

五、一键打包下载你的作品

  1. 做成本地网站/App：用 Open WebUI 或自己写的前端。
  2. Docker 打包：写一个 Dockerfile，docker build -t 你的项目 .。
  3. 发 Release：推到 GitHub，在 Releases 里发编译好的安装包/镜像，别人一键下载。
  4. 一键脚本：写个 install.sh 或 install.ps1，把安装步骤全部自动化。

六、一人公司（OPC）怎么用这套开源栈

  • 用 Goose / claude-code / OpenHands 写产品代码；
  • 用 deer-flow / trae-agent 跑长时域自动化任务；
  • 用 Open WebUI 做内部工具和客服；
  • 用 Shannon / SecSuite 做产品安全自查；
  • 手机装 LocalMind/PocketLLM 随时演示给客户；
  • 全部开源免费，唯一的成本是你的时间 + 一台电脑。

这就是「一人公司」的技术底座：不雇人，雇一堆能对话的开源 Agent。

七、安全红线（必须看）

  1. 网络安全工具只用于自己的系统或拿到书面授权的目标，否则违法。
  2. API Key 别写进公开仓库，会被盗刷。
  3. 本地模型选适合显存的量化版本（8G 显卡用 Q4_K_M 这类）。
  4. 命令以各仓库最新 README 为准，版本更新快，跑前先扫一眼 Quick Start。

上手手册里哪些内容最易过期

具体版本号、安装命令、依赖 pin 的版本——这三样受项目迭代影响最大，写死了第二天就可能装不上。所以本页不写死，只给不会烂的方法。

四条稳定的上手纪律

  • 先跑通最小示例，再谈集成　官方 README 的 quickstart 跑不通就先别改代码，八成是环境问题，不是项目问题
  • 锁依赖版本　"昨天还能跑"几乎都是依赖漂移，pip 用 requirements.txt 加版本号，node 用 lockfile，别裸装 latest
  • 优先选有官方 Docker 镜像的项目　能省掉九成的环境折腾，也说明维护者在意可复现性
  • 先看 LICENSE 再动手　MIT / Apache-2.0 可商用，AGPL 会传染到服务端部署，闭源产品接入前必须确认

自托管场景的成本换算

开源模型自托管之后，成本结构从"按调用付费"变成"按显卡折旧"。判断划不划算只要比一件事：每月调用量对应的 API 账单 vs 显卡折旧 + 电费 + 运维人力。调用量小的个人场景，用 API 基本总是更便宜；调用量大且要求数据不出内网时，自托管才反过来划算。

这也是为什么本页保留下面的通用计费规则——自托管虽然不是按 token 计费，但要和 API 账单对比，就得先算清 API 那一侧是怎么收钱的。

通用计费规则（跨厂商稳定）

  • 输入与输出分开计价，输出通常是输入的 5 倍，各家旗舰档基本一致。
  • 缓存命中大幅打折，但写缓存本身可能溢价（Anthropic 5 分钟缓存 1.25 倍、1 小时 2 倍）。
  • 长 prompt 跳档加价：OpenAI 的分界在 272K tokens，Google 在 200K，Anthropic 的 1M 窗口按标准价。
  • 推理 token 按输出计费，思考越长账单越高，但不改变最终可见答案的长度。
  • 不同厂 tokenizer 不同，同样文字切出的 token 数可差约 30%，横向比价不能只看单价。
  • 批量（Batch）异步处理普遍约 5 折，适合离线评测，不适合交互式 Agent。
