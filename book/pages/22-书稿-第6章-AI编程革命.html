第 6 章 · AI编程革命：从Copilot到自主Agent

2021年GitHub Copilot发布时，很多人觉得它只是个「高级代码补全」。五年后回看，它开启的是一场编程范式的革命。

Copilot时代：AI辅助编程

GitHub Copilot基于OpenAI Codex，能够在IDE中实时补全代码。它的核心能力：

  • 代码补全：根据上下文自动生成代码
  • 注释生成代码：写注释，AI生成实现
  • 测试生成：自动生成单元测试
  • 文档生成：自动生成函数文档

GitHub 2022 年公布的一项对照实验称，使用 Copilot 的开发者完成同一任务的速度快约 55%（结论仅针对该实验任务，原文可查）

AI IDE：从辅助到主导

2024年后，新一代AI IDE（如Cursor、CodeBuddy、Windsurf）不再只是「补全代码」，而是主导整个开发流程：

  • 对话式开发：用自然语言描述需求，AI生成完整项目
  • 代码库理解：AI理解整个项目的架构和上下文
  • 自动重构：AI提出优化方案并自动执行
  • 多文件编辑：同时修改多个文件，保持一致性

自主编程Agent

2025-2026年，编程Agent开始走向自主：

  • Devin（Cognition Labs）：号称「第一个AI软件工程师」，能独立完成完整项目
  • SWE-agent：在SWE-bench上解决真实GitHub issue
  • CodeBuddy Agent：腾讯的自主编程Agent，集成在IDE中

这些Agent能做的事：读需求文档 设计架构 写代码 跑测试 修bug 提交PR，全流程自动化。

对程序员的影响

AI不会取代程序员，但会改变程序员的工作：

  • 初级程序员：AI替代重复性编码，需要更专注于设计和架构
  • 中级程序员：AI成为日常工具，效率大幅提升
  • 高级程序员：AI处理实现细节，人专注创新和决策

核心技能变化：

  1. 从「写代码」到「描述需求」
  2. 从「调语法」到「审架构」
  3. 从「单兵作战」到「人机协作」

那 55% 是怎么来的，以及它为什么不能当承诺

GitHub 在 2022 年公布过一个对照实验：一组开发者用 Copilot 完成指定任务（写一个 HTTP 服务器），另一组不用。结论是用 Copilot 的那组快约 55%。

这个数字被引用了无数次，但几乎每次都被扩大成「用 AI 能省一半时间」。原实验的任务单一、样本有限、参与者都是熟悉这门语言的人。而真实项目里，写代码只占一小部分时间——读别人的代码、想清楚到底要什么、把环境跑通、排查那个只在生产环境出现的 bug，这些才是大头。

更接近现实的结论是：在「已经很明确要写什么」的环节，AI 能显著加速；在「还没想清楚要写什么」的环节，AI 帮不上忙，甚至会因为你描述得含糊，生成一堆看着对、其实不对的代码，反而让你多花时间。

所以那个 55% 的正确读法是：它衡量的是「打字速度」，不是「交付速度」。

Cursor 这类工具真正的分水岭在哪

从「补全」到「主导」，中间那条线是上下文。

Copilot 早期只能看到当前文件附近几百行，它不知道你这个项目里已经有一个叫 formatDate 的工具函数，于是它又给你写一个。等你发现的时候，项目里已经有三个同名不同实现的日期格式化函数了，其中两个有 bug。

Cursor 这类工具跨过去的一步，是把整个仓库索引进去，让它知道你的项目长什么样。能力性质随之变了：它开始能做「跨文件的一致修改」——你改了接口签名，它把所有调用点一起改掉；你说「给这个列表加分页」，它会去动组件、动请求、动类型定义，而不是只丢给你一段孤立的代码。

但这条分水岭的另一面也要说清楚：它对「你的项目结构很烂」这件事无能为力。代码库越乱，它越容易在错误的地方模仿错误的写法。所以真正用好这类工具的前提，反而挺反直觉——你自己的工程规范得先过关。规范差的团队用 AI，只会更快地生产出更多烂代码。

自主 Agent：现在能干什么，不能干什么

Devin 在 2024 年 3 月发布时，演示里它自己读需求、自己开浏览器查文档、自己写代码、自己跑测试。SWE-bench 这个基准也是为这类能力设计的：给你一个真实 GitHub 仓库和一个真实 issue，看你能不能改对，改完测试能不能过。

这类 Agent 现在的甜点区很清楚：修边界明确的 bug、加小的功能、补测试、升级依赖、写一次性脚本。它们的共同点是有明确的对错信号（测试过不过），而且不需要产品判断。

不擅长的同样清楚：需求本身是矛盾的、需要跟人来回确认的、或者「你做完之后整个架构就不对了」这类事。它不会提醒你「这个需求做了会后悔」，它只会照你说的做，然后给你一个能跑但难维护的东西。这一点比它写错代码更危险，因为写错代码测试会挂，做错方向测试一样绿。

所以现在的现实分工是：Agent 干「已定义」的活，人干「下定义」的活。听着像空话，落到日常就是——你花在写清楚需求上的时间会变多，花在敲代码上的时间会变少。很多人不适应这个转变，因为它要求你把模糊的想法说成精确的话，这比敲代码累。

一个不客气的提醒

AI 写代码越快，读代码的能力就越值钱。因为审核它的产出，比你自己写要难——自己写的时候每一步都知道为什么，看机器写的代码，你得在几十秒里判断这段逻辑对不对、边界处理了没有、有没有埋一个「空数组就崩」的坑。

所以「从写代码到审架构」这句话，不是让你不写代码了，是让你把力气往上游挪：定义问题、划边界、定标准、做验收。这四件事，AI 目前替不了，也可能很长时间都替不了——因为它们要求的不是产出速度，是承担责任。

本章要点

  • AI编程经历了从「补全」到「主导」再到「自主」的演进
  • AI不会取代程序员，但会用AI的程序员会取代不会用的
  • 未来的核心竞争力是：问题定义能力、架构设计能力、AI协作能力
