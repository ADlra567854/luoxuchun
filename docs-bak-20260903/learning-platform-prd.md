## 一、背景与产品定位

AI 学院现有 30 章系统教程 + 12 栏目 + 书系 + lab 工科实验室，内容侧已相当扎实（B 线已完成 SEO/日历/书系资产/热榜/变现方案）。但**学习链路是断的**：用户读完章节 → 没有自测 → 没有进度感 → 没有凭证激励 → 流失。C 线目标是把「内容站」升级为「学习平台」：

> **北极星指标：学完 ≥1 章并完成 ≥1 次测验的用户占比（完成率）**
> 驱动指标：章节打卡率、测验参与率、认证考试通过率、学习进度保存量
> 健康指标：章节页底部打卡点击率、连续学习天数留存、证书打印/截图次数

**核心用户故事：**
- 作为学习者，我希望读完章节后能打卡记录进度，以便看到自己的成长轨迹。
- 作为求职者，我希望通过考试拿到可打印的能力凭证，以便写进简历。
- 作为长期学习者，我希望在路线图上看到每一周的完成状态，以便按计划推进。

### 3.2 产品规则

- **练习模式**：按知识域随机抽 10 题，即时判分 + 解析，≥60% 合格；记录最佳正确率与次数。
- **认证考试**：10 题全卷作答后统一判分，≥80% 通过；通过即发数字证书，写入 `ccowork.certs`。
- **多选计分**：需全部选对才得分（产品决策：从严，保证证书含金量）。
- **诚实原则**：题库未覆盖的域显示「题库扩充中」占位卡，不放假考试、不造虚证（CERT 01/04 考试暂缓）。
- **数据本地化**：所有记录存 localStorage（`ccowork.quiz.scores` / `ccowork.certs` / `ccowork.quiz.history` / `ccowork.learnerName`），无后端、无隐私外泄。
- **打印证书**：证书页输入姓名 → 打印/另存 PDF（`@media print` 只显示证书本体，含编号 CCOWORK-CERTxx-YYYYMMDD）。

### 4.2 产品规则

- **章节打卡**：30 个章节页底部自动注入打卡卡片（`module.js` 统一注入，零页面改动）；点击「打卡本章」写入 `ccowork.progress`，记录完成时间 + 累计连续学习天数。
- **连续学习天数**：每日首次打卡 +1 天；中断 1 天内保持，中断 ≥2 天重置为 1。
- **进度展示策略**：新用户（0 进度）**不显示**进度卡片，避免空状态干扰；有任意打卡记录后自动出现。
- **学院首页进度卡**：显示总体进度百分比 + 已完成章数 + 连续天数 +「继续学习」跳转（推荐下一个未完成章节）。
- **路线图页进度**：
  - 顶部进度总览条（有进度才显示）
  - 四阶段卡片各显示「x/y 完成」，已完成章节前加 ✅ 标记
  - 14 周计划表：全部章节完成的周次标绿 + ✓ 前缀
- **认证考试前置门槛（软门槛）**：
  - CERT02（智能体工程师）：建议先学 ≥5 章（16 章关联）
  - CERT03（RAG 应用工程师）：建议先学 ≥3 章（4 章关联）
  - 未达门槛时显示「📖 建议先学 N 章再考」提醒，但仍允许「直接挑战」（不强制阻止，引导为主）
  - 每科显示前置学习进度条

### 4.3 数据结构（localStorage）

```
ccowork.progress = {
  chapters: {
    "chapter-01": { title: "初识智能体", firstReadAt: timestamp, completedAt: timestamp },
    ...
  },
  streak: 3,              // 连续学习天数
  lastCheckIn: "2026-08-31", // 最近打卡日期
  totalCompleted: 5,      // 已完成章数
  startedAt: "2026-08-28"  // 首次打卡日期
}
```

### 4.4 全局 API

`window.CCOWorkProgress`（供所有页面调用）：
- `get()` → 返回完整进度对象
- `save(p)` → 保存进度
- `isChapterCompleted(chId)` → 布尔
- `getCompletedCount()` → 数字
- `TOTAL_CHAPTERS` → 30

### 4.5 产品决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 注入式实现（module.js），不改单页 HTML | 30 章统一注入，维护成本低；新增章节自动获得打卡能力 |
| D2 | 新用户不显示进度卡（渐进式呈现） | 空进度条反而制造焦虑；有第一次打卡后自然出现，惊喜感更强 |
| D3 | 软门槛而非硬阻断 | 避免挫败感；「建议先学」是引导不是限制；信任用户的自我判断 |
| D4 | 连续打卡天数用自然日（0 点重置） | 符合用户心智；比「24 小时制」更易理解、更易坚持 |
| D5 | 打卡 = 用户主动确认「我学完了」，不是自动检测阅读时长 | 诚实原则：不自作主张判断「是否学会」；把主权交给用户 |

### 4.6 验收标准

1. 章节页底部自动注入打卡卡片（含进度统计 + 打卡按钮）
2. 点击打卡 → localStorage 写入 `ccowork.progress` → UI 实时更新为「已完成」状态
3. 连续打卡天数计算正确（当日不重复 + 次日 +1 + 中断重置）
4. 学院首页：新用户不显示进度卡；有打卡后显示进度条 + 推荐下一章
5. 路线图页：阶段卡片显示完成数 + 已完成章节 ✅ 标记；整周完成的表格行高亮
6. 认证考试卡片显示前置进度条；未达门槛时显示温和提醒，但仍可进入考试
7. `window.CCOWorkProgress` API 在所有加载 module.js 的页面可用
8. 零 JS 错误；双主题适配

## 五、C3 详细设计（已完成，2026-08-31）

### 5.1 背景修正：不是「转 Python 脚本」，是「补齐脚本 + 打通路径」

盘点发现 lab/simulation 下**并无 .py 文件**（只有 3 个 HTML 讲解页），而 lab/index.html 却展示了 11 个 `python xxx.py` 命令卡片 —— **全部是死链**（老罗红线：真能下载/真能跑）。同时 `simlab.html` 已有 5 个纯前端 JS 仿真（PID/弹簧/抛体/RC/蒙特卡洛，欧拉积分 + SVG 图表），但没有纳入学习路径。

因此 C3 的落地 = **修死链（补真实脚本）+ 补在线化缺失环（实验打卡）+ 打通学院入口**，而非从零开发。

### 5.2 交付物

| 文件 | 职责 |
|---|---|
| `lab/simulation/01-10_*.py`（新增 ×10） | 真实可运行的 Python 仿真脚本：PID/弹簧/抛体/RC/蒙特卡洛/单摆/直流电机/热传导/Lotka-Volterra/波动方程。零第三方依赖，欧拉积分，输出与理论值对照，支持 `--csv` 导出 |
| `lab/simulation/test_simulation.py`（新增） | pytest 校验 10 脚本正确性（13 项断言：解析解/已知物理规律对照） |
| `lab/index.html`（增强） | 修复 11 个死链 → 每个脚本卡加「⬇ 下载脚本」真实链接 + 前 5 个「🖥 在线版」对照；修复 2 处缺 href 的坏链接；移除 1 处无链接死内容 |

### 5.3 产品规则

- **双通道**：网页版（simlab.html，滑杆调参实时出图）与脚本版（.py 可下载离线跑）互为对照 —— 网页版教「现象」，脚本版教「代码」。
- **实验打卡 = 学习路径一部分**：完成实验写入 `ccowork.progress.labs`，与章节打卡共用连续学习天数；学院进度体系不区分「读章节」与「做实验」。
- **幂等**：同一实验只记录一次（重复点击不重复计），已完成按钮置灰。
- **诚实原则延续**：脚本须真实可运行（13/13 测试通过），不放假仿真、不放装饰性代码。
- **稳定性注释**：热传导显式差分提示 r ≤ 0.5 稳定性条件；波动方程标注 CFL 条件 —— 学习者可自行「破坏参数」观察数值发散，理解数值方法边界。

### 6.2 产品规则

- **注入式实现**：module.js 检测章节页 URL（`/ai-academy/chapter-\d+.html`）后懒加载 ai-tutor.js；32 章统一获得助教能力，无需逐页修改。
- **不打扰原则**：浮动按钮常驻但不自动弹出、不自动追问；点击才展开面板（`pointer-events` 控制，不挡阅读）。
- **上下文感知**：打开面板时从 DOM 自动提取本章标题 + h2/h3 目录骨架（≤14 条）+ 正文摘要（≤700 字）注入 system prompt，AI 回答紧扣本章内容；快捷问题 chips 也按本章目录动态生成。
- **模型策略**：复用 ai-client.js 的提供商链 —— 智谱 GLM-4.7-Flash（免费，默认）→ DeepSeek → 火山方舟；本地 server.mjs 运行时自动走服务端密钥（零 Key），纯静态部署时用户自填 Key（存 localStorage，仅本机）。
- **首次使用引导**：无 Key 且无后端时，面板内温和提示配置入口（不强制弹窗，🔑 按钮常驻）；Key 设置卡内嵌面板（provider 选择 + 输入 + 保存）。
- **对话历史**：`ccowork.tutor`（{model, asked, lastAskAt, history}），最多保留 20 轮；发送时注入最近 6 轮作为上下文；面板可一键清除。
- **诚实原则**：回答标注「AI 生成，仅供参考」；system prompt 明确「不确定必须明说、绝不编造」。
- **学习路径联动**：提问计数（asked）展示在面板 footer 与学院首页进度卡（有互动才显示），并入学习活跃度但不计入章节完成度（避免刷数据）。

### 6.4 产品决策记录（C4）

| # | 决策 | 理由 |

### 7.2 产品规则（备份与恢复）

- **导出内容**：`ccowork.certs`（证书）、`ccowork.progress`（章节/实验打卡+连续天数）、`ccowork.quiz.scores`、`ccowork.quiz.history`、`ccowork.learnerName`（姓名）+ 版本号与导出时间；文件名 `ccowork-learning-backup-YYYYMMDD.json`。
- **隐私边界（关键决策）**：**不导出 AI 助教对话历史**（`ccowork.tutor.history`）——对话可能含个人提问，属敏感数据；仅导出 `asked`/`lastAskAt` 统计。备份文件只存用户手里，不上传任何服务器（纯静态站点无后端）。
- **导入合并策略**：对象类 key（certs/progress/quiz.scores）按子 key 深度合并、导入覆盖本地同名项，**不丢本地已有数据**（实测 1+2→3）；裸字符串（姓名）按原始格式恢复；版本不兼容时提示但兼容导入。
- **防御**：文件 >2MB 拒绝；非法 JSON 拒绝；缺 `data` 字段拒绝——均有明确中文错误提示（aria-live 播报）。
- **即时反馈**：导出/导入均显示结果状态条（✅/❌ + 数量明细）；导入后「我的认证」区自动刷新（renderMine 每次从 localStorage 重读）。
- **换设备路径**：旧设备「导出备份」→ 文件带走 → 新设备证书页「导入备份」→ 证书/进度/成绩/姓名全部恢复。

## 九、风险与边界

- **无用户系统**：学习数据为单机 localStorage；C5 已提供手动 JSON 导出/导入完成跨设备迁移，自动云同步需后端（纯静态现状不支持），列入 Next 评估。
- **题库质量**：现有 65 题答案客观，扩充时须保持「答案可查证、不编造」标准。
- **不要过度工程**：C 线以最小可用闭环推进，每步先可点可用再谈增强。
- **合规**：证书为「能力自证」性质，文案避免「官方认证/行业认可」等误导表述。
- **打卡诚实性**：打卡是用户自证行为，系统不做「是否真学会」的判断；产品定位为学习辅助工具而非能力评估机构。
- **数值仿真边界**：Python/JS 仿真均为教学级欧拉积分，参数极端化（热传导 r>0.5、波动 CFL>1）会数值发散——脚本内已注释说明，作为数值方法稳定性的教学点。
