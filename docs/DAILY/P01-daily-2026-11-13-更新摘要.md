## 三、本轮核心发现：线上纯静态形态回退（硬伤）

### 3.1 现象

线上没有 Node 进程在跑，退化成了纯静态托管：

```
$ curl -sI .../api/health
Content-Type: application/octet-stream     ← 静态文件，不是 application/json
Server: CloudStudio Gateway
Last-Modified: Tue, 10 Nov 2026 14:40:14 GMT

$ curl -o /dev/null -w "%{http_code}" .../api/chat   → 404  （Node 路由应 405）
$ curl -o /dev/null -w "%{http_code}" .../api/proxy  → 404  （Node 路由应 400）
```

`/api/health` 返回的 46 字节内容与本地静态桩 `deploy/api/health` **md5 完全一致**（`5795cbba67be885a02491fe76f2f6c48`）。

### 3.2 根因链

**后端没跑 → `server.mjs` 的 `DENY_FILE` 规则失效 → 沙箱里 10-29 的旧 `ai.config.json` 明文裸露。**

```
线上 GET /ai.config.json →
{
  "base": "https://maas-api.cn-huabei-1.xf-yun.com",
  "model": "spark-x2.6",
  "key": "ak-6YT****（已脱敏，原值见 .env）"     ← 明文讯飞 key
}
Last-Modified: Thu, 29 Oct 2026 13:46:53 GMT         ← 10-29 的旧字节
```

而本地 `deploy/ai.config.json`（11-13 10:50 重写）已是 `key: ""` 的**无密钥版** —— 说明 **11-12 那次安全修复的占位覆盖逻辑是对的，本地包已修好，缺的只是一次正确形态的重新发布**。

### 3.3 时间线

| 时间 | 事件 |
|---|---|
| 10-29 | 旧包发布，含明文 `ai.config.json` |
| 11-10 22:40 | 加入静态托管探测桩 `deploy/api/health` |
| 11-12 | 安全修复：静态发布 + 无密钥占位 `ai.config.json`（`prepare-deploy.mjs` 改 36 行，已提交 `367f677`） |
| **11-13 00:00** | **又一次构建发布（`site-official/` → `deploy/` 全量刷新）** |
| 11-13 10:50 | 本地 `deploy/` 的 `server.mjs` / `package.json` / `ai.config.json` 被重写（`--with-server` 路径），**这批从未发布** |

### 3.4 重要澄清：线上不是「旧包」

md5 比对 —— 线上 `index.html` / `api/health` / `legacy-redirects.mjs` 与本地 `deploy/` **三者 md5 全部一致**；线上 `/` 的 `Last-Modified: 11-12 16:00:49 GMT` == 本地 `deploy/index.html` mtime **完全吻合**。

**线上跑的就是今天 00:00 那一批，只是那一批是按「静态形态」发布的。** 线上 `server.mjs` md5 也与本地一致（`84b76b00...`）—— 文件同步上去了，**但进程没被拉起**。

### 3.5 处置方案（已写计划，待确认）

计划文档：`docs/PLANS/2026-11-13-P01-线上纯静态形态回退与密钥明文暴露.md`

| 方案 | 做法 | 效果 |
|---|---|---|
| **A（推荐）** | 把 `deploy/` 按 Node 常驻形态重新发布（`language: node`，`startCmd: node server.mjs`） | 一次性解决三件事：`DENY` 生效 → `ai.config.json` 变 404；`caps` 恢复完整；5 条旧路径恢复 301 |
| B（保守） | 维持静态形态，重新发布一次让无密钥占位覆盖线上旧字节 | 只解决密钥暴露；`caps` 与 301 在架构上永远不达标 |
| C（长期） | 改 `prepare-deploy.mjs` 默认带后端 + 补「构建→预检→发布→复测」一条龙脚本 | 杜绝「本地改了没发」与「发错形态」 |

`deploy/server.mjs` 已确认监听 `PORT` 且绑 `0.0.0.0`（第 563 行），符合平台单端口要求。
