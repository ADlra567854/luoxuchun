## 三、发现的问题（只报告，未改代码）

### 🔴 问题 1【高】首页与 `/feed/` 两套「今日」口径打架

- 首页快讯条读 `data/daily-brief.json`（每日 RSS 真实抓取，7 天窗口）→ 显示「今日新增 69 条」、区间 11-12 — 11-18。
- `/feed/` 页与 `data/feed.json` 读另一份人工精选 → 区间 11-09 至 11-16、今日 0 条。
- **同一站点两个「今日」数字，且相差 69 条。** 用户从首页「近 7 天」点进 `/feed/` 会发现条目对不上。
- 根因：首页 11-16 那次「快讯联动」改造后改用 daily-brief 动态渲染，而 `/feed/` 仍用 feed.json，两者无统一真源。

### 🔴 问题 2【高】`feed.updated` 落后真实最新条目

- `feed.json`：`updated = 2026-11-16`，但 items 最大 `d = 2026-11-17`。
- `scripts/gen-feed.py:195` 用 `data['updated']` 作「近 7 天」窗口右端锚点 → `/feed/` 页面区间文案被钉死在 `2026-11-09 至 2026-11-16`，**11-17 的 4 条不进窗口**。
- 11-15 轮已报同一问题（当时落后 4 天），本轮仍红，仅差距从 4 天收窄到 1 天。
- 根因同属「计数真源缺自动 bump」：`updated` 只在人工追加条目时才更新，流水线没有 bump 步骤。

### 🟠 问题 3【高·安全】明文密钥仍在 git 索引内，远端仓库仍为 public

- `git ls-files ai.config.json` → **命中**；`git check-ignore` → 未忽略（`.gitignore` 只忽略 `.env` / `.env.local`）。
- 源码根与 `deploy/ai.config.json` 均含 35 字符明文讯飞 key（**本归档文档已脱敏，不抄录原值**）。
- 远端 `github.com/ADlra567854/luoxuchun` → `private: false` / `visibility: public`（`pushed_at 2026-11-17`）。
- **尚未泄露**：远端 `main` 分支树里搜不到 `ai.config.json`，`raw.githubusercontent` 也取不到。
- 线上安全：`/ai.config.json` 404 生效（`server.mjs` 的 `DENY_FILE` 拦截，本地 8098 与线上双向实测）。
- 处置建议（按优先级）：① 轮换 key ② `git rm --cached ai.config.json` + 补 `.gitignore` ③ 仓库转 private ④ 净化历史。
