### 2.7 ⚠️ gh-pages 子路径资源 404（硬伤之三）

gh-pages 仓库 `ADlra567854/luoxuchun` 是**项目页**，站点挂在子路径 `https://adlra567854.github.io/luoxuchun/`。
但全站 HTML 大量使用**根绝对路径**（`href="/theme-cloud.css"`、`src="/ccowork.js"`），在子路径下会解析到 `https://adlra567854.github.io/…`（用户根，**该站点不存在，404**）。

- 统计：发布目录 **552 个 HTML 文件、12236 处根绝对路径引用**
- 首页实测 **12 个资源 404**（`site-nav.css` / `float-dock.css` / `feed.css` / `baiju-assistant.js` / `site-nav.js` / `home-fold.js` / `data/ai-projects.json` / `stats.js` / `data/wechat-pick.json` / `api/health` / `search.js` / `data/content-cite.json`）
- **`/about/changelog.html` 实测 14 个资源 404**，其中 `fetch('/data/changelog.json')` 直接 404 → 页面渲染出「**更新记录读取失败（HTTP 404）**」，`.cl-day` 分组数 **0**，console 错误 25 条
- 但首页的「近 7 天」条**正常**（因为 `index.html` 用的是相对路径 `fetch('./data/daily-brief.json')`），`.is-today` 6 张、日期 11-23 均正确

**根因判断**：这不是资源缺失，而是**访问入口不对**。一旦 `ccoworkbaiju.cn` 通过 CNAME 正确绑定到 GitHub Pages，站点在域名根下服务，所有 `/…` 绝对路径自然成立，404 与渲染失败会一并消失。域名 A 记录缺失是**上游**，子路径 404 是**表征**。
