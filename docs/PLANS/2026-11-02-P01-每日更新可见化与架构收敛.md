## 2. 目标与非目标

### 目标

1. 首页与 `/about/` 上**能一眼看出最近更新时间**，且「今天新增」有独立视觉标识
2. 新建 `/about/changelog.html` 更新日志页，由 `data/changelog.json` 驱动，每次发布自动追加一条
3. 5 个自动化收敛为 **1 主 1 辅**，消除覆盖竞争
4. 301 收敛层真正生效；sitemap 只吐新路径；导航 9 个入口改指新版
5. 规划文档制度落地，本计划文档三端归档

### 非目标（本轮明确不做）

- 不迁移任何物理文件（旧站 193 页文件原地保留）
- 不下线 blog / novel 独立分站
- 不改站点视觉风格（除更新标识外）
- 不动小程序、DSH 等其他项目

### 7.4 顺带修掉的两个真 bug

**① `/api/proxy` 路由缺失** —— `ccowork.js` 与 `ai-client.js` 一直在打这个地址，但 `server.mjs` 从来没实现过，AI 对话与生图在这个站上从未真正通过代理跑起来（必然 405）。已补上路由，并加了 SSRF 防护：必须 https + 主机命中 4 家厂商白名单 + 只透传 Authorization/api-key。实测：白名单内 → 401（请求真的转发出去了）、白名单外 → 400、GET → 405。

**② 前端盲目调用不存在的接口** —— `/api/health` 只回 `{ok,ai}`，前端 `ping()` 拿不到能力清单，评论/通知/账号接口（server 里根本没有）全部 404，还给用户显示「启动 node server.mjs 即变云端」的错误承诺。已改为：`/api/health` 返回 `caps` 能力清单，前端按 `hasCap('comments')` 等判断再决定是否调用。6 处调用点全部改完，提示语同步改为「💾 本地模式 · 评论只存在这台设备」。

### 7.5 厂商品牌标识（老罗点名要改的）

**原状**：厂商墙用「中文首字 + 随机渐变」（深、阿、字…）当图标 —— 既不是 logo 也认不出公司。

**改法**：**品牌色实底 + 英文缩写字母标**（DS / QW / BY / TX / ZP / BAAI…），43 家全覆盖，0 个兜底。

**为什么不用真 logo**：lucide 官方《品牌 Logo 声明》明确不收品牌 logo —— 商标版权 + 风格一致性 + 维护成本三重原因。43 家逐一抓 logo 既不可行也有法律风险。字母标 + 品牌色是业界通行做法（与 Simple Icons 同一思路），且与全站 24×24 描边式规范不冲突。来源：<http://lucide.dev/brand-logo-statement>
