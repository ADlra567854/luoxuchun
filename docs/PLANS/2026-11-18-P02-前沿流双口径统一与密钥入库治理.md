### P0-2 首页与 `/feed/` 两套今日口径

- 首页「近 7 天」条：`index.html:1439+` 的 IIFE 读 `data/daily-brief.json`（每日 RSS 真实抓取，7 天窗口），渲染 6 条最新 + 「今日新增 N 条」+ 区间。
- `/feed/` 页与 `data/feed.json`：`scripts/gen-feed.py` 用 `data['updated']` 作窗口右端，人工精选条目。
- **结果：首页说「今日新增 69 条」，`/feed/` 区间止于 11-16 今日 0 条；点进去对不上。**

**候选方案**

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 统一到 feed.json** | 首页改读 `feed.json`，daily-brief 只进 `/feed/` 的第二区块 | 单一真源，与 changelog 口径一致 | 首页「今日」会变成人工精选口径（可能常为 0），失去 RSS 实时感 |
| **B. 统一到 daily-brief.json** | `/feed/` 页改为读 daily-brief，feed.json 退化为「精选归档」 | 实时性强，首页与 feed 页一致 | feed.json 的人工价值（每条带核实出处、分类标签）会从主视图消失 |
| **C. 双视图显式标注（推荐）** | 首页保留 daily-brief 实时感，但文案明确写「实时资讯」；`/feed/` 页顶部加一行「本页为人工精选前沿流」+ 各自标注区间与来源 | 不丢任何一边的价值，两边都说清自己在讲什么 | 需要给两处文案加来源标识，改动量中等 |

**倾向 C**：两套数据本身都有价值（daily-brief 是「真实抓取的量」，feed.json 是「人工核实的质」），问题不在于有两个源，而在于**都叫「近 7 天」却没说自己是什么**。

### P1-1 `feed.updated` 不自动 bump

- `feed.json`：`updated = 2026-11-16`，但 items 最大 `d = 2026-11-17`。
- `scripts/gen-feed.py:195` 用 `data['updated']` 作窗口右端 → 11-17 的 4 条被排除在「近 7 天」外。
- 11-15 轮已报（当时落后 4 天），本轮仍红（落后 1 天）。
- **建议**：
  - `scripts/daily-update.mjs` 在写 changelog 前加一步：若 `max(items[].d) > data['updated']` 则更新 `updated` 并写回 `feed.json`。
  - `gen-feed.py` 内部改用 `max(items[].d)` 兜底做锚点（双保险，即使 `updated` 未 bump 窗口也不会失真）。

### P1-2 `changelog.repos` 恒为 0

`scripts/daily-update.mjs:229` 硬编码 `repos: 0`，实际仓库总数由 `totalRepos` 字段正确承载（当前 154）。建议改为「当日新增仓库数」或直接写 `repos.json` 实际总数并在 note 里区分。

### P1-3 学院章节数四套口径（跨轮未解）

磁盘实存 **43** 章；`module.js:657` `TOTAL_CHAPTERS = 41`；`learn/academy.html` 静态 43；`learn/roadmap.html` 32。

**后果**：回访用户学完 41 章后进度封顶，第 42、43 章永远学不完。

**根因**：静态 HTML 预置了值，`module.js` 加载后用 `API.TOTAL_CHAPTERS` 覆盖；新用户进度为 0 时走不到更新分支，才侥幸看到静态值。

**推荐方案 B「单一真源 + 运行时注入」**：以磁盘实际章节数（43）为唯一真源，由 `module.js` 统一注入到 academy / roadmap / 页脚徽章三处；静态 HTML 里的硬编码值删除或改为占位。
