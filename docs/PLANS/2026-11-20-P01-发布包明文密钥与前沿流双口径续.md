## 2.【高】首页 / `/feed/` 双口径问题

### 2.1 现状（2026-11-20 实测）

| 位置 | 数据源 | 今日 | 区间 | 计数 |
|---|---|---|---|---|
| 首页「近 7 天」条带 | `data/daily-brief.json`（RSS 原始流） | **78 条** | 11-14 — 11-20 | `.ff-today` = 「今日新增 78 条」 |
| `/feed/` 页 | `data/feed.json`（人工精选流） | **4 条** | 11-13 至 11-20 | 「近 7 天 19」 |

两边区间文案**各自自洽**，但**「点进去对不上」完全没变** —— 这是 11-18 轮就提出的问题，方案 C 至今未落地。

### 2.2 根因

两个 JSON 文件承担同一职责的不同粒度：
- `daily-brief.json` = 机器抓的**全量 RSS 流**（每日 78~120 条，含显卡/机箱等噪音）
- `feed.json` = 人工筛选的**前沿精选流**（每日 0~4 条，每条带来源 + 要点）

首页 JS（`index.html:1441`）读前者，`/feed/` 页（`feed/index.html`）读后者。
用户看到首页「今日新增 78 条」→ 点进 `/feed/` 只有「近 7 天 19」，**天然对不上**。

### 2.3 方案 C（推荐，11-18 轮已提出，本轮再确认）

**让首页改读 `feed.json`**，理由：
1. `feed.json` 是**人工精选**的高信噪比内容，与 changelog / IMA 归档口径一致
2. 同一份内容可同时驱动：首页条带、`/feed/` 页、`/about/changelog.html`、IMA 归档 → **一处真源，全站一致**
3. `daily-brief.json` 保留原位，作为「每日简报」全量流的独立入口（首页「今日新闻」文案仍可读它）

**改动点**（3 处，均在 `index.html`）：
```
① index.html:1441  fetch('./data/daily-brief.json') → fetch('./data/feed.json')
② 索引字段映射：daily-brief 用 {title, ts, source, url}
   → feed.json 用 {t, d, s, u}，需在 JS 内做一次字段归一
③ is-today 判定：mdOf(ts) === todayMd → i.d === '2026-11-20'（按 d 字段比）
```

**保留**：无 JS 时的静态兜底（`index.html:595-598`）本来就是 feed.json 口径 —— **改完反而静态与动态一致**，这是一致性上的净收益。

### 2.4 验收判据

- 首页 `.ff-today` 文案数字 == `/feed/` 页「今日 N 条」数字
- 首页 `.ff-range` 区间 == `/feed/` 页区间
- 首页 `.is-today` 卡片 **标题** == `/feed/` 页对应卡片标题（逐条一致）

> 比上轮多了一套 —— 上轮报的是四套（43/41/32/30），本轮发现 roadmap 自身的 tag 又是 24。

### 3.2 后果

- 回访用户看到「已学 3 / 41 章」→ 进度封顶，**第 42、43 章永远学不完**

### 3.3 根因

新用户进度为 0 时走不到更新分支，才**侥幸**看到静态值 —— 于是掩盖了问题。

### 3.4 方案（单一真源 + 运行时注入）

1. **确定唯一真源**：磁盘实际章节数 **43**（或某个 `data/chapters.json` 真源文件）
2. `module.js:657` 改为从真源读取，**不再硬编码 41**
3. `learn/roadmap.html:85` 的静态 `0 / 32 章` 改为 `0 / 43 章`（或干脆留空由 JS 填）
4. `learn/roadmap.html:98` 的 `14 周 · 24 章` 标签同步改为 `14 周 · 43 章`（或按真实周次算）
5. `module.js:599` 页脚徽章 `AI 学院 30 章` → `AI 学院 43 章`
6. `learn/academy.html` 静态 43 —— 已是正确值，**保留**

### 3.5 验收判据

Playwright 注入 `localStorage['ccowork.progress']`（已学 3 章），断言：

## 6.【低】`gen-feed.py` 缺 `max(items[].d)` 兜底

`scripts/gen-feed.py:195`：

```python
today = parse(data['updated'])
```

**风险**：若 `updated` 再次滞后于 `max(items[].d)`，就会复现 11-15 轮那个
「首页区间文案写 11-03—11-10，但卡片显示 11-14/11-13」的自相矛盾问题。

**改法**（1 行）：

```python
today = parse(max((i['d'] for i in data['items']), default=data['updated']))
```

**验收判据**：人为把 `updated` 改成昨天后重跑，区间右端仍为 `max(items[].d)`。

## 7.【低·本轮新发现】`/feed/`「近 7 天」实际跨度 8 天

`gen-feed.py:195-197`：

```python
today = parse(data['updated'])          # 2026-11-20
start = today - timedelta(days=7)       # 2026-11-13
items = [i for i in ... if parse(i['d']) >= start]
```

**含两端** → 实际窗口 `2026-11-13 至 2026-11-20` 共 **8 个日历日**，而页面标题写「近 7 天」。
计数 19 与实际窗口**一致**，仅**标签措辞**偏松。

**两个改法（二选一）**：
- **A（推荐）**：窗口收成 7 天 → `start = today - timedelta(days=6)`
- **B**：保留 8 天窗口，标题改「近 7 天」→「近 8 天」

**验收判据**：页面区间跨度的日历天数 == 标题宣称的天数。
