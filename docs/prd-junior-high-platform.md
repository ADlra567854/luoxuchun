## 1. 产品概述

### 1.1 产品定位

**一句话定位**：专为初中生打造的 AI 全生活成长伙伴——学习有方法、成长有记录、青春有陪伴、家校有连接。

**详细描述**：

「初中全生活智能平台」是白驹主站实战中心 K12 线的旗舰项目，聚焦初中三年（12-15岁）这一学业分化与青春期叠加的关键时期，以微信小程序为载体、AI 为内核，打造一款覆盖「学习辅助 + 成长记录 + 生活工具 + 家校共育」的全场景智能平台。

不同于作业帮、猿辅导等「提分工具型」产品，也不同于钉钉、企业微信等「管理工具型」产品，我们的核心定位是「成长伙伴」——不仅帮助学生提升学习效率，更陪伴他们度过青春期的心理波动，记录成长轨迹，连接家庭与学校，让每一位初中生都能被看见、被理解、被赋能。

产品以「轻量、温暖、高效」为设计理念，通过微信小程序实现零门槛触达，通过 AI 实现个性化陪伴，通过家长端联动实现家校共育。我们相信，初中三年不只有分数，更有成长的无限可能。

### 1.2 目标用户

| 角色 | 核心用户群 | 用户规模 | 使用场景 | 付费角色 |
|------|-----------|----------|----------|----------|
| **学生端** | 初一至初三学生（12-15岁） | 约4500万 | 日常作业辅导、错题整理、学习计划、成长记录、情绪倾诉 | 使用者 |
| **家长端** | 初中生家长（35-50岁） | 约9000万（父母双方） | 查看学情、管控使用、亲子互动、教育方法学习 | 付费决策者 |
| **教师端** | 初中班主任及任课教师 | 约350万 | 班级管理、作业布置、学情分析、家校沟通（P2阶段） | 生态合作者 |

**用户关系模型**：

```
学生端（核心使用者）
    ↑ 双向互动
家长端（付费决策者）
    ↑ 协同合作
教师端（生态赋能者，远期）
```

### 1.3 核心价值主张

#### 对学生的价值

1. **高效学习助手**：AI 全科答疑、错题智能整理、个性化学习计划，让学习更高效
2. **成长记录档案**：记录学习轨迹、心情变化、成就时刻，看见自己的成长
3. **青春陪伴伙伴**：AI 心理树洞、青春期话题交流，有地方说心里话
4. **生活管理工具**：番茄钟、待办清单、目标管理，培养自律能力

#### 对家长的价值

1. **学情透明可见**：实时了解孩子学习情况，减少焦虑
2. **成长共同见证**：查看成长记录，写亲子寄语，增进亲子连接
3. **科学管控放心**：使用时长管控、功能开关、内容安全，放心让孩子使用
4. **教育方法指导**：AI 育儿助手、青春期教育内容，提升教育能力

#### 对教师的价值（远期）

1. **高效班级管理**：一键发布作业、自动统计完成情况
2. **精准学情分析**：班级知识点掌握度、薄弱学生识别
3. **家校协同通道**：与家长高效沟通，形成教育合力

### 1.4 与白驹主站的关系

- **项目定位**：白驹主站「实战中心」K12 教育线的旗舰产品
- **战略意义**：
  - 验证 AI + 教育的产品化路径
  - 积累 C 端产品运营经验
  - 探索小程序生态的增长模式
  - 为后续 K12 其他学段产品打基础
- **资源协同**：
  - 共享白驹主站的技术基础设施
  - 复用 AI 能力接入体系
  - 借力主站流量与品牌
  - 形成实战案例反哺主站内容

### 1.5 差异化优势

| 对比维度 | 作业帮/猿辅导 | 科大讯飞学习机 | 钉钉/企业微信 | 我们的产品 |
|----------|--------------|---------------|--------------|-----------|
| **核心定位** | 提分工具 | 学习硬件 | 管理平台 | 成长伙伴 |
| **目标学段** | K12全学段 | K12全学段 | K12全学段 | 初中专属 |
| **产品形态** | App+硬件 | 学习平板 | SaaS+App | 微信小程序 |
| **场景覆盖** | 学习为主 | 学习为主 | 校园管理 | 学习+生活+心理+成长 |
| **AI角色** | 辅导老师 | 教学工具 | 效率工具 | 成长伙伴 |
| **家长角色** | 监督付费 | 监督管控 | 被动接收 | 共同成长 |
| **心理关怀** | 无 | 无 | 无 | AI心理陪伴 |
| **成长记录** | 无 | 弱 | 无 | 核心功能 |
| **使用门槛** | 下载App/千元硬件 | 千元硬件 | 学校推广 | 微信即用 |
| **交互调性** | 功利、严肃 | 科技、专业 | 工具化 | 温暖、活力、陪伴感 |

**核心差异化总结**：

1. **初中专属，三年深度陪伴**：不是 K12 大而全，而是聚焦初中三年，深度适配青春期特点、学业分化规律、中考备考节奏
2. **全生活覆盖，不止学习**：从「学习工具」升级为「成长平台」，覆盖学业、心理、生活、兴趣四大维度
3. **AI 成长伙伴，不是 AI 老师**：AI 定位从「辅导老师」转向「成长伙伴」，不仅解答学习问题，更陪伴情绪、规划成长、记录青春
4. **小程序载体，零门槛触达**：无需下载 App，微信即用，降低获客成本，提高传播效率
5. **家校共育，双向互动**：不是单向的「家长监控」，而是双向的「共同成长」，改善亲子关系，促进家校协同

## 2. 用户画像

### 2.1 学生端画像

#### 画像一：小明 —— 「努力型中等生」

| 维度 | 详情 |
|------|------|
| **年级** | 初二 |
| **成绩** | 班级中等（排名25/45），数学物理偏弱，语文英语中上 |
| **性格** | 内向、努力但方法不对、容易焦虑、自尊心强 |
| **家庭环境** | 父母重视教育，报了补习班但效果一般，亲子关系尚可 |

**核心痛点**：
- 上课听懂了但做题不会，尤其是数学物理的大题
- 错题整理太费时间，抄题就要半小时，坚持不下来
- 想提高成绩但不知道从哪下手，报了补习班效果不明显
- 不敢问老师怕被说笨，问同学又怕打扰别人
- 考试前特别焦虑，经常失眠

**使用场景**：
- 晚上写作业遇到不会的题，用 AI 答疑
- 周末把本周错题拍照录入，复习巩固
- 每天早上看今日学习计划，合理安排时间
- 考试前用错题本重点复习
- 压力大的时候去「树洞」吐槽一下

**核心期望**：
- 有人能耐心讲题，不批评、不嘲笑
- 错题整理能省时间，还能提醒复习
- 知道自己哪里薄弱，有针对性地提高
- 有个地方可以说心里话

## 4. MVP 功能规格

### 4.1 P0 - MVP 必须有

#### 4.1.1 AI 学习助手

**功能描述**：

AI 学习助手是产品的核心功能，为初中生提供全科（语文、数学、英语、物理、化学）AI 答疑服务。学生可以通过文字或图片输入问题，AI 提供知识点讲解、例题解析和思路引导。采用流式输出，提升对话体验。

**用户故事**：

- 作为初二学生，我写作业遇到不会的数学题时，可以拍照或输入题目，让 AI 帮我讲解解题思路，这样我不用等老师或家长，自己就能搞懂。
- 作为初一学生，我英语语法搞不懂时，可以问 AI 某个语法点，AI 用简单的语言和例子给我讲清楚，这样我能跟上课堂进度。
- 作为初三学生，我复习时遇到模糊的知识点，可以让 AI 系统地讲解相关知识体系，帮助我查漏补缺。
- 作为学生，我希望能保存对话历史，方便以后复习查看。

**交互逻辑**：

```
首页 → 点击「AI助手」入口 → 进入对话页面
  ↓
选择科目（语文/数学/英语/物理/化学）→ 默认上次选择
  ↓
输入方式：
  ├─ 文字输入：直接打字提问
  └─ 图片输入：拍照/相册选择 → OCR识别 → 确认/编辑题目
  ↓
发送问题 → 显示「思考中...」加载态
  ↓
AI 流式输出回答（支持 Markdown 渲染、公式渲染）
  ↓
回答底部操作栏：
  ├─ 「加入错题本」→ 保存到错题本
  ├─ 「再讲一遍」→ 重新生成回答
  ├─ 「换个例子」→ 提供新的例题
  └─ 「继续提问」→ 追问
  ↓
对话自动保存到历史记录
```

**详细交互说明**：

1. **对话页面**：顶部显示科目名称和切换按钮，中间是对话气泡区域，底部是输入框
2. **输入框**：左侧是「拍照」按钮，中间是文字输入框（支持多行），右侧是发送按钮
3. **AI回答**：
   - 首字延迟控制在1秒以内
   - 流式逐字输出
   - 支持 Markdown 格式（标题、列表、代码块、表格）
   - 数学公式使用 LaTeX 渲染
   - 回答结构：思路点拨 → 详细解答 → 知识点总结 → 举一反三（可选）
4. **对话历史**：按时间倒序排列，显示问题摘要和时间
5. **科目切换**：对话顶部可快速切换科目，切换后清空当前对话（提示保存）

**数据结构**：

```javascript
// 对话会话表 chat_sessions
{
  _id: String,           // 会话ID
  userId: String,        // 用户ID
  subject: String,       // 科目：chinese/math/english/physics/chemistry
  title: String,         // 会话标题（取第一个问题前20字）
  messageCount: Number,  // 消息数量
  lastMessage: String,   // 最后一条消息摘要
  lastTime: Date,        // 最后消息时间
  createdAt: Date,       // 创建时间
  updatedAt: Date        // 更新时间
}

// 对话消息表 chat_messages
{
  _id: String,           // 消息ID
  sessionId: String,     // 会话ID
  userId: String,        // 用户ID
  role: String,          // 角色：user/assistant
  content: String,       // 消息内容（Markdown格式）
  type: String,          // 消息类型：text/image
  imageUrl: String,      // 图片URL（type=image时）
  ocrText: String,       // OCR识别文字（图片消息时）
  model: String,         // 使用的AI模型
  tokens: Number,        // 消耗token数
  timestamp: Date        // 消息时间
}
```

**边界情况**：

| 场景 | 处理方式 |
|------|----------|
| 问题超出初中范围 | AI 友好提示「这道题超出了初中范围哦，要不要试试其他题目？」并引导回到初中知识点 |
| 问题涉及考试作弊 | 检测到整卷/整页拍摄时，提示「AI 助手是用来帮你理解知识点的，不是直接给答案的哦，我们一起来分析思路吧」 |
| 网络异常 | 显示网络错误提示，提供「重试」按钮，已输入内容保留 |
| AI 服务超时/失败 | 显示「AI 小助手开小差了，重试一下吧」，自动降级到备用模型 |
| 内容违规 | 触发内容安全检测时，拦截并提示「这个问题不合适哦，请换一个吧」 |
| 输入过长 | 文字输入限制 500 字，超出提示截断 |
| 对话历史过多 | 分页加载，每次加载 20 条，上拉加载更多 |
| 未成年人保护 | 所有对话经过内容安全审核，敏感话题（自杀、自残、暴力等）触发预警机制 |

**AI 回答规范**（教育原则）：

1. **不直接给答案**：先讲思路，再给过程，最后总结知识点，引导学生思考
2. **语言通俗化**：用初中生能理解的语言，避免过于学术化的表达
3. **鼓励为主**：回答中加入鼓励性语言，如「你能想到这一步很棒！」
4. **结构化输出**：使用清晰的标题和分段，便于阅读
5. **标注 AI 生成**：回答底部标注「以上内容由 AI 生成，仅供参考」

#### 4.1.2 错题本

**功能描述**：

错题本是学生学习的刚需功能，支持拍照录入和手动录入两种方式，自动按学科和知识点分类，提供错题重练和复习提醒，追踪掌握程度。

**用户故事**：

- 作为初二学生，我每次考试或作业的错题，可以拍照保存到错题本里，不用再抄题了，节省很多时间。
- 作为学生，我希望错题本能自动分类，按学科和知识点整理，复习的时候更有条理。
- 作为学生，我希望系统能提醒我复习错题，根据遗忘曲线安排复习时间。
- 作为学生，我希望能重做错题，检验自己是否真的掌握了。

**交互逻辑**：

```
错题本首页
  ├─ 顶部：学科筛选 Tab（全部/语文/数学/英语/物理/化学）

  │   ├─ 拍照录入
  │   └─ 手动录入
  └─ 错题列表（按时间倒序）
      ├─ 题目缩略图/摘要
      ├─ 学科标签
      ├─ 知识点标签
      ├─ 掌握状态（未掌握/学习中/已掌握）

    ↓

    ↓
  填写错误答案 → 填写错误原因（可选）
    ↓

录入流程 - 手动录入：
  点击「手动录入」→ 输入题目内容
    ↓
  选择学科 → 选择知识点
    ↓

    ↓
  保存

错题详情页：
  ├─ 题目内容（支持图片+文字）
  ├─ 我的错误答案
  ├─ 正确答案（默认折叠，点击展开）
  ├─ 解析（AI生成/手动填写）

复习提醒：
```

#### 4.1.4 每日计划

**功能描述**：

**用户故事**：

- 作为学生，我有一个待办清单，每完成一项就打勾，特别有成就感。

#### 4.1.5 家长端小程序

**功能描述**：

家长端是小程序内的家长角色入口，与学生端共用一个小程序（通过角色切换）。家长可以查看孩子的学习情况、成长记录，设置使用管控，发送亲子寄语。家长端是连接家庭教育的桥梁，也是付费转化的关键角色。

**用户故事**：

- 作为妈妈，我想知道孩子每天学了多久、做了什么，这样我心里有数，不会瞎焦虑。
- 作为爸爸，我担心孩子沉迷手机，我可以设置使用时长，到点自动锁定。
- 作为家长，我想给孩子写点鼓励的话，但当面说不好意思，通过小程序发寄语很合适。
- 作为家长，我想看看孩子的成长日记，了解他在想什么，但又不想让他觉得我在监视他。

#### 4.2.2 试卷分析

**功能描述**：

拍照上传整张试卷，AI 自动识别题目和答案，分析错题对应的知识点薄弱点，生成成绩趋势和提升建议。

**用户故事**：

- 作为初三学生，每次考试后我想知道自己哪些知识点没掌握，这样可以针对性复习。
- 作为学生，我想看到自己的成绩变化趋势，知道有没有进步。
- 作为家长，我想看到孩子每次考试的分析报告，了解孩子的薄弱环节。

**交互逻辑**：

```
试卷分析页
  ├─ 「上传试卷」按钮
  ├─ 历史分析记录列表
  └─ 成绩趋势图

上传分析流程：
  点击「上传试卷」→ 拍照/选择图片（支持多页）
    ↓
  OCR识别题目和答案 → 自动批改（客观题）
    ↓
  用户确认/修改得分 → 填写主观题得分
    ↓
  AI分析薄弱知识点 → 生成分析报告
    ↓
  报告展示：
    ├─ 总分 + 各题型得分
    ├─ 错题列表（带知识点标签）
    ├─ 薄弱知识点雷达图
    ├─ 成绩排名参考（同年级对比，可选）
    └─ 提升建议 + 推荐练习题
```

**边界情况**：

- 试卷图片不清晰 → 提示重拍
- 识别率低 → 支持手动编辑题目和答案
- 非标准试卷格式 → 灵活适配，支持手动标注
- 试卷内容安全 → 仅存储在用户个人空间，不用于训练

#### 4.2.3 作文批改

**功能描述**：

学生上传作文（图片或文字），AI 按中考作文评分标准进行多维度评分和逐句点评，提供改写建议和范文参考。

**用户故事**：

- 作为初一学生，我写了作文想知道写得怎么样，AI 可以帮我批改打分。
- 作为学生，我希望 AI 能指出我作文里的问题，比如哪里写得不好、怎么改进。
- 作为学生，我想看看范文是怎么写的，学习好的写作方法。

**交互逻辑**：

```
作文批改页
  ├─ 上传方式：拍照上传 / 文字输入
  ├─ 选择年级 + 作文类型（记叙文/议论文/说明文等）
  ├─ 「开始批改」按钮
  └─ 历史批改记录

批改结果页
  ├─ 总分（如 42/50）+ 等级（优秀/良好/中等/及格）
  ├─ 各维度评分
  │   ├─ 内容（立意、选材）
  │   ├─ 结构（布局、条理）
  │   ├─ 语言（表达、文采）
  │   └─ 书写（字迹、标点）
  ├─ 总评（整体评价）
  ├─ 逐句点评（原文标注，点击显示评语）
  ├─ 好词好句标记
  ├─ 改写建议（针对重点段落）
  └─ 同类范文推荐（1-2篇）
```

**AI 批改规范**：

- 参考中考作文评分标准
- 评分维度清晰，评语具体不空泛
- 以鼓励为主，指出问题同时肯定优点
- 标注「AI 批改仅供参考，建议结合老师意见」

#### 4.2.5 心理树洞（AI 心理陪伴）

**功能描述**：

针对初中生青春期心理需求的 AI 陪伴功能，提供情绪倾诉、压力疏导、青春期话题交流等服务，是产品差异化的重要功能。

**用户故事**：

- 作为初二学生，最近压力特别大，不想跟爸妈说，也不想跟同学说，可以跟 AI 树洞聊聊。
- 作为学生，我对青春期的一些变化很好奇，但不好意思问别人，可以问 AI。
- 作为学生，我跟爸妈吵架了，心情不好，想找个地方倾诉一下。

**交互逻辑**：

```
心理树洞入口（成长记录板块）
  ↓
树洞首页
  ├─ 今日心情选择（5个表情）
  ├─ 快捷话题入口
  │   ├─ 学习压力
  │   ├─ 人际关系
  │   ├─ 家庭亲子
  │   ├─ 自我认知
  │   ├─ 青春期困惑
  │   └─ 其他烦恼
  ├─ 「直接倾诉」按钮（自由对话）
  └─ 历史倾诉记录

对话界面（类似AI助手，但语气更温暖、更有同理心）
  ├─ AI 角色：温暖的大哥哥/大姐姐形象
  ├─ 对话风格：倾听为主、共情回应、引导思考、不评判
  └─ 底部：「结束倾诉」「心情记录」
```

**安全策略**（重点）：

1. **不替代专业心理咨询**：明确告知 AI 树洞不能替代专业心理咨询
2. **危机预警**：检测到自残、自杀等危险倾向时，立即触发预警
   - 展示心理援助热线
   - 通知紧急联系人（家长，需提前设置）
   - 引导寻求专业帮助
3. **隐私保护**：树洞对话默认仅自己可见，家长不可查看
4. **内容审核**：所有对话经过内容安全审核，但不存储明文（或加密存储）
5. **使用时长限制**：单日树洞使用不超过 30 分钟，防止过度依赖

## 6. 技术架构

### 6.1 小程序架构

#### 6.1.1 技术选型

| 层级 | 技术选型 | 版本 | 选型理由 |
|------|----------|------|----------|
| **前端框架** | 微信原生小程序 | 最新稳定版 | 性能最优、API最全、兼容性最佳、微信生态无缝集成 |
| **状态管理** | MobX / 小程序全局Data | - | MVP阶段功能不复杂，用全局Data即可，后续升级MobX |
| **UI组件库** | Vant Weapp + 自定义组件 | 最新 | 组件丰富、设计风格年轻化、社区活跃 |
| **后端服务** | 微信云开发（CloudBase） | - | 快速上线、零运维、成本低、前端可独立完成全栈开发 |
| **云函数** | Node.js | 16.x | 云开发原生支持，前端团队技术栈统一 |
| **数据库** | 云数据库（JSON文档型） | - | 云开发原生、Schema灵活、适合快速迭代 |
| **文件存储** | 云存储 | - | 图片/语音/文件存储，CDN加速 |
| **AI接入** | One API + 多模型 | - | 统一接口、多模型管理、灵活切换、成本可控 |
| **OCR识别** | 腾讯云OCR | - | 微信生态集成好，手写体识别准确率高 |
| **内容安全** | 微信内容安全API | - | msgSecCheck + imgSecCheck，免费额度充足 |

#### 6.1.2 选型理由详述

**为什么选微信原生小程序而不是 Uni-App/Taro？**

1. **性能优先**：原生小程序性能最好，AI 流式输出等场景对性能要求高
2. **生态完整**：云开发、内容安全、推送等原生能力无缝对接
3. **MVP 阶段聚焦**：先验证微信端市场，多端是后续需求
4. **学习成本**：团队专注一个框架，开发效率更高

**为什么选云开发而不是自建后端？**

1. **开发速度**：前端团队可独立完成全栈开发，节省后端人力
2. **零运维**：无需部署、监控、扩缩容，节省运维成本
3. **成本低廉**：MVP 阶段免费额度基本够用
4. **微信集成**：登录、支付、推送等能力原生支持
5. **快速验证**：先跑通产品，验证市场后再考虑迁移

**为什么选 One API 统一接入？**

1. **多模型策略**：不同场景用不同模型，效果和成本最优
2. **灵活切换**：某模型出问题可快速降级到备用模型
3. **统一管理**：额度管控、使用统计、安全审计统一管理
4. **标准接口**：OpenAI 格式，降低接入和切换成本

#### 6.1.4 双端关系设计

**方案：同一个小程序，双角色入口**

```
微信小程序「初中成长记」
│
├── 学生端（默认入口）
│   ├── 底部 Tab：首页 / 学习 / 成长 / 我的
│   ├── 24个核心页面
│   └── 功能完整
│
└── 家长端（通过「我的」→「切换到家长端」进入）
    ├── 底部 Tab：首页 / 管控 / 消息 / 我的
    ├── 10个核心页面
    └── 独立的页面和导航
```

**优点**：
- 一个小程序，推广成本低
- 数据天然互通，无需跨小程序同步
- 家长端和学生端切换方便
- 开发维护成本低

**角色切换机制**：
1. 首次登录时选择角色（学生/家长）
2. 学生可在「我的」页面切换到家长端（查看自己作为家长的视角？不，学生不能看家长端）
3. 家长可在「我的」页面切换到学生体验模式（预览学生端功能，不能操作实际数据）
4. 绑定关系建立后，家长端显示孩子数据，学生端显示已绑定家长

#### 6.2.2 本地缓存策略

| 缓存内容 | 存储方式 | 有效期 | 大小限制 |
|----------|----------|--------|----------|
| 用户信息 | wx.setStorageSync | 永久（登录失效时清除） | < 1KB |
| 最近对话 | 本地存储 | 7天 | < 100KB |
| 错题列表 | 本地缓存 + 云数据库 | 1天 | < 500KB |
| 学习记录统计 | 本地聚合 + 云端 | 1天 | < 50KB |
| 徽章列表 | 本地缓存 | 7天 | < 20KB |
| 日记列表 | 本地缓存（最近一个月） | 7天 | < 200KB |
| AI模型配置 | 本地缓存 | 1天 | < 10KB |
| 设置偏好 | 本地永久存储 | 永久 | < 10KB |

**缓存策略原则**：
1. **写入时双写**：重要数据写入云端同时更新本地缓存
2. **读取时优先本地**：先读本地缓存，再异步拉取云端最新数据
3. **离线可用**：核心功能（如查看错题、写日记）支持离线使用，上线后同步
4. **缓存淘汰**：LRU 策略，超出大小时淘汰最久未使用的数据

#### 6.2.3 数据安全与隐私

**未成年人数据保护**：

1. **数据最小化**：只收集必要的信息，不强制要求真实姓名、学校等敏感信息
2. **家长知情同意**：绑定家长时明确告知数据用途，家长可随时解除绑定
3. **数据加密**：
   - 传输加密：HTTPS 传输
   - 存储加密：敏感字段（手机号、日记内容）加密存储
   - 端到端加密：心理树洞对话端到端加密
4. **访问控制**：
   - 学生数据仅本人和已绑定家长可见
   - 家长权限由学生控制（隐私设置）
   - 运营人员无法直接查看用户明文数据
5. **数据留存**：
   - 用户注销后 30 天内删除所有数据
   - 日志数据留存不超过 6 个月
   - AI 对话数据不用于模型训练（明确告知用户）
6. **合规要求**：
   - 遵守《未成年人网络保护条例》
   - 遵守《个人信息保护法》
   - 遵守《儿童个人信息网络保护规定》
   - 设置青少年模式（默认开启）

#### 6.3.3 流式输出方案

**技术实现**：

```
小程序前端                      云函数                      AI API
   │                             │                           │
   │  wx.request({enableChunked: true})                       │
   │───────────────────────────>│                           │
   │                             │─── SSE 请求 ────────────>│
   │                             │                           │
   │                             │<──── 流式数据 ───────────│
   │                             │                           │
   │<──── 转发数据块 ────────────│                           │
   │  逐块渲染到页面              │                           │
   │                             │                           │
   │<──── 更多数据块 ────────────│                           │
   │  继续追加渲染               │                           │
```

**实现要点**：
1. 小程序端使用 `wx.request` 的 `enableChunked: true` 开启流式接收
2. 云函数通过 `request` 库发起 SSE 请求，监听 `data` 事件
3. 云函数使用 `cloud.getWXContext()` 等获取上下文
4. 前端收到数据块后，追加到对话气泡中
5. 首字延迟控制在 1 秒以内

#### 6.4.1 绑定机制

**绑定流程**：

```
学生端操作：                    家长端操作：
  我的 → 家长绑定                 我的 → 我是家长 → 绑定孩子
  → 生成绑定二维码/邀请码          → 扫码 / 输入邀请码
  → 设置昵称（爸爸/妈妈）          → 填写与孩子关系
  → 设置初始可见权限              → 发送绑定请求

                                      ↓

                                      ↓

                                拒绝 → 绑定失败
```

**绑定方式**：
1. **扫码绑定**：学生端生成二维码，家长扫码绑定（推荐，最便捷）
2. **邀请码绑定**：生成6位数字邀请码，家长输入绑定（备用）

**解绑机制**：
- 学生端可随时解除绑定
- 家长端可申请解除绑定（需学生确认）
- 解绑后家长端不再能查看数据
- 解绑数据保留7天（可恢复），7天后清除

| 数据类型 | 同步方式 | 延迟 | 说明 |

| 成长日记 | 学生手动同步 | 手动 | 学生设置可见的日记才同步 |

- 核心数据：学生端写入云数据库 → 云数据库触发器 → 推送通知给家长

## 8. 设计规范

### 8.1 设计语言

**关键词**：年轻、活力、清爽、不幼稚、有温度

**设计理念**：
- **年轻化但不幼稚**：面向 12-15 岁初中生，避免低龄化设计，体现成长感
- **活力但不浮躁**：色彩明快但不过度刺激，学习场景需要专注感
- **清爽简洁**：信息层级清晰，减少视觉噪音
- **温暖陪伴**：通过圆润的造型、柔和的色彩、友好的动效传递陪伴感
- **游戏化激励**：用徽章、进度、成就等游戏化元素提升使用动力

### 8.2 色彩系统

**底部 Tab Bar**：
- 高度：56px（含安全区）
- 图标：24px × 24px

- 未选中态：辅助灰色

**顶部导航栏**：
- 高度：44px

- 返回按钮：24px 图标

| 类型 | 样式 | 使用场景 |
|------|------|----------|
| 线性进度条 | 高度 6px，圆角 3px | 学习进度、任务完成度 |
| 环形进度条 | 圆环，可设置粗细 | 首页今日进度、番茄钟 |
| 步骤条 | 数字/圆点 + 连接线 | 多步骤流程 |

- **形状**：圆形/盾形/星形（不同稀有度不同形状）
- **尺寸**：48px / 64px / 96px 三种规格
- **已获得**：彩色渐变 + 光泽效果
- **未获得**：灰色 + 锁图标
- **稀有度配色**：
  - 普通：灰色渐变
  - 稀有：蓝色渐变
  - 史诗：紫色渐变
  - 传说：金色渐变 + 光环动效

### 8.4 针对初中生的交互设计要点

#### 8.4.1 简单直接

- **操作路径短**：核心功能不超过 2 步到达
- **大按钮大点击区**：按钮最小高度 44px，点击区域不小于 44×44px
- **清晰的视觉层级**：重要信息突出，次要信息弱化
- **减少文字输入**：优先选择、拍照、语音等输入方式

#### 8.4.2 游戏化激励

- **徽章成就系统**：完成任务获得徽章，收集欲驱动使用
- **连续打卡奖励**：连续打卡 7/30/100 天获得特殊徽章
- **进度可视化**：用进度条、统计图表展示学习成果
- **等级体系**：学习时长对应等级，从「萌新」到「学霸」
- **即时反馈**：每次完成任务都有积极反馈（动画、音效、鼓励语）

#### 8.4.3 成就感设计

- **每日回顾**：晚上推送今日学习成果摘要
- **周/月报告**：定期生成成长报告，量化进步
- **成长时间线**：用时间线方式展示学习和成长轨迹
- **对比展示**：与上周/上月对比，直观看到进步
- **里程碑庆祝**：达到重要里程碑时（如学习100小时），有庆祝动效

#### 8.4.4 情绪价值

- **鼓励式语言**：所有文案用鼓励、肯定的语气，不说教
- **共情式表达**：AI 助手和系统提示都带有温度
- **个性化称呼**：使用用户昵称，增加亲切感
- **节日/生日祝福**：特殊日期送上祝福
- **失败也温暖**：做错题目、未完成目标时，鼓励而非批评

### 8.5 家长端设计风格

#### 8.5.1 整体调性

- **稳重安心**：色彩偏沉稳，减少跳跃感
- **数据可视化**：多用图表展示数据，直观清晰
- **操作简洁**：家长时间宝贵，减少操作步骤
- **信任感**：专业、可靠的视觉感受

#### 8.5.2 关键页面设计原则

**学情概览页**：
- 数据卡片大而清晰，一眼看懂
- 图表信息密度适中，不过载
- 异常数据高亮提醒（如学习时长大幅下降）
- 趋势图比单天数据更有价值

**管控设置页**：
- 开关和滑块等控件大而好操作
- 设置项分组清晰，逻辑分层
- 重要设置（如时长限制）二次确认
- 设置变更有明确反馈

## 10. 风险与对策

### 10.1 技术风险

| 风险 | 影响 | 概率 | 应对策略 |
|------|------|------|----------|
| **云开发能力不足** | 业务复杂后云函数/数据库性能瓶颈，无法支撑复杂查询 | 中 | 提前规划架构，关键业务预留云托管迁移方案；MVP阶段控制功能复杂度 |
| **AI 服务不稳定** | 模型API故障或超时，影响核心功能使用 | 中 | 多模型降级策略（主模型+2个备用模型）；One API统一管理故障切换 |
| **AI 成本过高** | 用户增长后API费用激增，成本不可控 | 高 | 模型分级策略（简单问题用小模型）；结果缓存；免费用户限额；优化prompt减少token |
| **OCR 识别准确率低** | 手写体识别不准，影响错题录入体验 | 中 | 多OCR服务商对比选型；支持用户手动修正；持续优化识别效果 |
| **小程序包体积超限** | 功能增多后主包超2MB，影响加载速度 | 低 | 提前规划分包策略；图片和静态资源CDN化；按需加载 |
| **并发性能问题** | 高峰期（如晚上作业时间）用户集中使用导致响应慢 | 低 | 云函数自动扩缩容；数据库索引优化；热点数据缓存 |

### 10.2 内容风险（教育内容准确性）

| 风险 | 影响 | 概率 | 应对策略 |
|------|------|------|----------|
| **AI 回答错误** | AI给出错误的解题思路或知识点讲解，误导学生 | 高 | 明确标注「AI生成内容仅供参考」；关键知识点人工审核；建立用户反馈纠错机制 |
| **题库答案错误** | 题库中存在错误答案，影响学习效果 | 中 | AI生成题目需人工审核；建立UGC纠错机制；定期抽检题目质量 |
| **知识点讲解不准确** | 知识点讲解与教材不符，超纲或有偏差 | 中 | 对标人教版等主流教材；邀请一线教师审核；建立内容审核流程 |
| **作文批改评分不准** | AI评分与实际水平差距大，用户不信任 | 中 | 参考中考评分标准训练；多维度评分而非单一分数；强调「仅供参考」 |
| **误导性学习建议** | AI给出不合理的学习计划或建议 | 中 | 设定AI回答边界，不做绝对性判断；建议类内容标注「建议根据实际情况调整」 |

**内容质量保障体系**：

```
内容生产 → 内容审核 → 上线发布 → 用户反馈 → 持续优化
   │           │          │          │          │
   ▼           ▼          ▼          ▼          ▼
 AI生成/人工  教师审核   灰度发布   纠错入口   定期更新
  教研输入    交叉审核   数据监控   奖励机制   版本迭代
```

### 10.3 合规风险（未成年人保护、数据安全）

| 风险 | 影响 | 概率 | 应对策略 |
|------|------|------|----------|
| **未成年人保护合规风险** | 违反《未成年人网络保护条例》等法规，可能被处罚或下架 | 高 | 严格遵守相关法规；设置青少年模式；内容审核到位；家长管控功能完善 |
| **数据安全风险** | 用户数据泄露，特别是未成年人敏感信息 | 高 | 数据加密存储和传输；最小化数据收集；访问权限控制；定期安全审计 |
| **内容安全风险** | 用户上传违规内容或AI生成违规内容 | 高 | 多层内容安全过滤；人工审核补充；敏感词库更新；违规用户处置机制 |
| **沉迷风险** | 家长投诉孩子沉迷小程序，影响品牌形象 | 中 | 内置使用时长管控；休息提醒；夜间限制；家长远程监督；护眼提醒 |
| **教育政策风险** | 「双减」等政策变化影响产品定位 | 中 | 聚焦素质教育和成长记录，不碰学科培训红线；不提供有偿补课服务；关注政策动态 |
| **支付合规风险** | 未成年人误充值、打赏等问题 | 低 | 付费功能需家长确认；明显的价格提示；退款通道畅通；遵守支付监管要求 |

**未成年人保护专项措施**：

1. **青少年模式**：默认开启，功能受限，时长受限
2. **真实身份认证**：家长端需实名认证（通过微信支付验证）
3. **内容分级**：不同年龄段适配不同内容
4. **防沉迷系统**：时长限制、休息提醒、夜间禁用
5. **隐私保护**：数据最小化、加密存储、家长可控
6. **消费保护**：家长确认、限额、无障碍退款
7. **举报机制**：用户可举报违规内容和行为
8. **心理危机干预**：自伤自杀倾向预警和援助

### 10.4 用户增长风险

| 风险 | 影响 | 概率 | 应对策略 |
|------|------|------|----------|
| **获客成本高** | 教育产品获客成本高，用户增长慢 | 高 | 小程序社交裂变；家长社群传播；学校合作；内容营销；KOL合作 |
| **留存率低** | 用户新鲜感过后不再使用 | 高 | 游戏化激励体系；成长记录带来的情感连接；个性化推荐；定期新功能 |
| **付费意愿低** | 小程序用户习惯免费，付费转化难 | 中 | 先用免费功能积累用户；会员价值感要足够强；免费试用；增值功能付费 |
| **竞争挤压** | 作业帮等巨头进入类似赛道 | 中 | 聚焦初中垂直深度；差异化定位（成长而非提分）；轻量化优势；快速迭代 |
| **传播难度大** | 教育产品社交属性弱，裂变困难 | 中 | 打卡分享（成就徽章、学习报告）；亲子互动（寄语、共同任务）；班级集体使用 |

### 10.5 竞争风险

| 竞争对手 | 竞争点 | 我们的应对 |
|----------|--------|-----------|
| **作业帮/猿辅导** | 题量大、品牌强、资源多 | 差异化定位：不做提分工具，做成长伙伴；聚焦初中专属场景；小程序轻量化体验 |
| **科大讯飞/学而思学习机** | 硬件+内容一体化，AI技术强 | 不正面竞争硬件市场；做轻量SaaS化产品；心理和成长维度差异化 |
| **钉钉/企业微信** | 学校资源强，家校沟通基础好 | 不做B端管理工具，做C端成长平台；学生主动使用而非被动接收 |
| **新兴AI教育产品** | 创新速度快，AI能力强 | 快速迭代保持领先；深耕教育场景理解；建立内容和数据壁垒 |

**竞争壁垒构建路径**：

```
第一阶段（MVP）：产品体验壁垒
  → 优秀的产品设计和用户体验
  → 差异化的成长记录功能

第二阶段（V2.0）：数据壁垒
  → 学习数据积累越多，推荐越精准
  → 用户成长档案形成情感连接和迁移成本

第三阶段（V3.0）：生态壁垒
  → 学生+家长+老师三方联动
  → 内容生态（UGC+PGC）
  → 社交网络效应
```
