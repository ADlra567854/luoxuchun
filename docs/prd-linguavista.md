## 1. 产品概述

### 1.1 产品定位

**一句话定位：**
> 环球语堂 —— 基于AI的多语言全站式学习平台，一个账号畅学10+种语言，科学记忆 + AI对话双引擎驱动。

**详细描述：**

环球语堂是白驹实战中心旗下的外语学习产品，采用「纯HTML/CSS/JS + PWA」的轻量架构，与白驹主站共享设计语言与AI能力。产品以「多语种覆盖 + AI对话练习 + 科学记忆体系」为核心竞争力，为用户提供从词汇、语法到口语对话的一站式语言学习体验。

不同于多邻国的游戏化路线，环球语堂面向成人学习者，强调「学习实感」与「效率优先」：结构化课程确保体系完整，AI对话解决开口难题，SRS闪卡保证记忆效果。Web-first 的产品形态让用户打开浏览器即可学习，无需下载App，PWA技术保障离线可用。

### 1.2 目标用户

| 用户分层 | 年龄 | 特征 | 占比预估 |
|---------|------|------|---------|
| **职场提升族** | 22-35岁 | 一线/新一线城市白领，学外语为了职业发展、跳槽、海外业务 | 40% |
| **学生备考族** | 16-25岁 | 大学生/高中生，备考四六级、考研、日语能力考、TOPIK等 | 30% |
| **兴趣爱好者** | 18-40岁 | 因动漫、韩剧、旅游、文化等兴趣学习小语种 | 20% |
| **移民/留学预备** | 25-40岁 | 计划出国留学或移民，需要系统提升外语能力 | 10% |

### 1.3 核心价值主张

1. **多语种一站畅学**：一个账号学习英语、日语、韩语、法语、西班牙语等多种语言，无需切换平台，学习数据统一管理
2. **AI + 课程双引擎**：系统课程打基础（输入），AI对话练输出（口语），学练闭环
3. **科学记忆体系**：基于间隔重复算法（SRS）的闪卡系统，高效记忆词汇，告别"背了就忘"
4. **即开即用，离线可学**：Web-first + PWA，浏览器直接访问，支持安装到桌面/手机主屏幕，核心内容离线可用
5. **与白驹生态打通**：AI能力复用 ccowork.js，设计语言与主站统一，用户无需重复注册

### 1.4 与白驹主站的关系

**定位：** 环球语堂是白驹「实战中心」的重点项目之一，与AI学院、算法实验室、技能中心等同属白驹内容生态。

**统一设计语言：**
- 复用 `theme-cloud.css` 双主题体系（深空纪元 + 云顶天空）
- 复用 `site-redesign.css` 组件层（毛玻璃导航、渐变Hero、品牌页脚等）
- 复用 `site-industrial.css` 工业美学层（工程图纸、精密仪表、表格式排版）
- 全局渐变：`linear-gradient(120deg,#38e1ff,#5b8cff 45%,#8b5cf6)`

**AI能力复用：**
- 接入 `ccowork.js` 的AI对话能力，复用底层LLM接入
- 在 ccowork 工作台中新增「语言学习」入口
- 对话能力独立封装为 `linguavista-ai.js`，支持多场景prompt

**用户体系：**
- MVP阶段使用 localStorage 本地存储，无需注册即可使用
- 远期接入白驹统一账号体系，实现跨产品数据同步

### 1.5 差异化优势

| 维度 | 环球语堂 | 多邻国 Duolingo | 流利说 | Speak | Langotalk |
|------|---------|----------------|--------|-------|-----------|
| **核心定位** | 多语种AI全站学习 | 游戏化大众学习 | AI英语听说 | AI英语口语教练 | AI对话多语言 |
| **语种数量** | 2种起，目标10+ | 40+ | 1（英语） | 1-2 | 19 |
| **系统课程** | 有（CEFR体系） | 有（游戏化） | 有（跟读） | 无 | 无 |
| **AI对话** | 有（多语种文字） | 有（Max版付费） | 弱 | 有（英语语音） | 有（多语种） |
| **闪卡/SRS** | 内置（SM-2/FSRS） | 有（Words） | 无 | 无 | 无 |
| **Web体验** | Web-first，原生体验 | Web弱（App导向） | 弱 | Web弱 | 一般 |
| **离线能力** | PWA离线闪卡 | 无（App内） | 无 | 无 | 无 |
| **架构** | 纯HTML/CSS/JS | React Native | 原生App | 原生App | Web+App |
| **开源/透明** | 核心功能开源可自托管 | 闭源商业 | 闭源商业 | 闭源商业 | 闭源商业 |

**核心差异化总结：**
- 对多邻国：更成人化、更有学习实感、Web体验更好、AI对话更深度
- 对流利说：多语种、不是只有英语、学习方式更丰富
- 对Speak：多语种、有系统课程和词汇体系、价格更低
- 对Langotalk：有结构化课程和闪卡系统，学习更系统

#### 4.1.2 闪卡词汇学习（SRS 间隔重复算法）

**功能描述：**
核心学习功能。用户通过闪卡形式学习词汇，基于 SM-2 间隔重复算法智能安排复习时间，实现高效记忆。

**用户故事：**
- 作为词汇量不足的学习者，我希望用闪卡方式背单词，这样效率更高
- 作为容易忘词的用户，我希望系统能自动安排复习，这样不用自己规划
- 作为通勤学习的用户，我希望操作简单快捷，这样单手就能操作

**交互逻辑：**

1. **闪卡学习流程：**
   ```
   开始学习 → 显示卡片正面（单词+音标）
       ↓
   用户点击「翻面」或空格键 → 显示背面（释义+例句+词性）
       ↓
   用户选择评分：
   ├─ 不认识 → 卡片放入学习队列末尾，稍后重复
   ├─ 模糊 → 较短间隔后复习
   └─ 认识 → 较长间隔后复习
       ↓
   下一张卡片
   ```

2. **卡片正面：**
   - 大号单词（目标语言）
   - 音标/假名（小一号，灰色）
   - 词性标签（n. / v. / adj. 等）
   - 播放按钮（点击播放发音）
   - 进度指示：当前第几张 / 共几张

3. **卡片背面：**
   - 中文释义（多个义项，1-3个核心义项）
   - 例句（目标语 + 中文翻译）
   - 三个评分按钮：
     - 「不认识」（红色，左）
     - 「模糊」（黄色，中）
     - 「认识」（绿色，右）
   - 快捷键：1=不认识, 2=模糊, 3=认识, 空格=翻面

4. **学习会话结束：**
   - 完成今日所有卡片 → 显示完成页
   - 展示：学习了 X 张新词，复习了 Y 张，正确率 Z%
   - 获得 XP 奖励
   - 「返回首页」按钮

5. **SRS 算法（SM-2）：**
   - 每张卡片维护：EF（难度因子）、n（连续正确次数）、I（复习间隔）
   - 评分映射：不认识=0分, 模糊=3分, 认识=5分
   - 首次学习：I=1天（如果认识）或当天重复（如果不认识）
   - 后续复习：根据评分调整 EF 和间隔

**数据结构：**

```javascript
// linguavista.cards.{lang} — 词库卡片数据（静态，从词库文件加载）
// 每张卡片：
{
  id: "en_00001",
  word: "hello",                  // 目标语单词
  phonetic: "/həˈloʊ/",           // 音标（英语）/ 假名（日语）
  pos: "int.",                    // 词性
  meaning: "你好；喂",             // 中文释义
  examples: [                     // 例句数组
    {
      en: "Hello, how are you?",
      zh: "你好，你好吗？"
    }
  ],
  level: "A1",                    // CEFR等级
  tags: ["greeting", "core"]      // 标签
}

// linguavista.progress.{lang} — 每卡片的学习进度
{
  cardId: "en_00001",
  status: "learning",             // new/learning/mastered
  ef: 2.5,                        // 难度因子 Ease Factor
  repetitions: 3,                 // 连续正确次数
  interval: 6,                    // 当前复习间隔（天）
  dueDate: "2026-09-05",          // 下次复习日期 ISO字符串
  lastReview: "2026-08-30",       // 上次复习日期
  lapses: 0,                      // 遗忘次数
  totalReviews: 5,                // 总复习次数
  correctCount: 4                 // 正确次数
}

// linguavista.deck.{lang} — 词库配置
{
  name: "核心词汇 2000",
  totalCards: 2000,
  levels: ["A1", "A2", "B1"],
  newCardsPerDay: 20,
  description: "日常交流核心词汇"
}
```

**边界情况：**
- 待复习卡片为 0 → 显示「今日复习完成！」，可选择学习新词或休息
- 新卡片已全部学完 → 显示「恭喜！词库已全部学习」
- 学习中途退出 → 自动保存当前进度，下次继续
- 连续点击太快（<300ms）→ 忽略过快点击，防止误操作
- 卡片数据加载失败 → 显示错误提示，提供重试按钮
- 同一天重复复习同一张卡 → 只计算一次有效复习，不重复安排
- 评分后立即反悔 → 不支持撤销（保持SRS数据一致性），可在卡片详情中手动重置

#### 4.1.3 AI 文字对话练习

**功能描述：**
接入 ccowork.js 的 AI 对话能力，用户可以用目标语言与 AI 进行文字对话。AI 会在对话中适时纠正用户的语法和用词错误，提供更地道的表达建议。

**用户故事：**
- 作为不敢开口的学习者，我希望先从文字对话开始练习，这样压力更小
- 作为缺少对话环境的用户，我希望随时随地都能和 AI 聊天，这样练习机会更多
- 作为经常犯错的用户，我希望 AI 能指出我的错误并解释，这样我能边聊边学

**交互逻辑：**

1. **对话入口：**
   - 首页快捷入口「AI对话」
   - 点击进入对话模式选择页

2. **模式选择：**
   - **自由对话**：随便聊，AI 像语伴一样聊天
   - **场景对话**：选择场景（餐厅点餐、机场值机、购物砍价、面试自我介绍等，首批10个场景）
   - **语法答疑**：有语法问题直接问

3. **对话界面：**
   - 顶部：场景/模式名称 + 难度选择（简单/中等/困难）+ 返回按钮
   - 中间：消息气泡列表（左：AI，右：用户）
   - 底部：输入框 + 发送按钮
   - 输入框上方：快捷提示（「翻译这句话」「解释语法」「换个说法」）

4. **AI 纠错机制：**
   - 用户发送消息后，AI 回复包含两部分：
     1. 正常对话回复（目标语言）
     2. 纠错卡片（如果用户有错误）
   - 纠错卡片样式：
     - 原句（划线标注错误处）
     - 修改后的正确句子
     - 错误类型标签（语法/用词/拼写）
     - 简短解释
   - 纠错频率：不每条都纠正（避免打断对话流畅感），明显错误才纠正
   - 用户可在设置中调整纠错强度：严格 / 适中 / 宽松

5. **辅助功能：**
   - 点击任意 AI 消息 → 弹出菜单：播放语音 / 查看翻译 / 收藏句子
   - 卡壳时 → 输入框旁「提示」按钮，可用中文输入想表达的意思，AI 帮你翻译
   - 对话历史 → 自动保存到本地，可在「历史记录」中回看

6. **流式输出：**
   - AI 回复采用打字机效果，逐字显示
   - 显示过程中用户可打断（发送新消息），中断当前回复

**数据结构：**

#### 4.1.4 学习进度追踪 + 激励系统

**功能描述：**
追踪用户的学习数据，通过连续学习天数、经验值、等级等机制激励用户坚持学习。

**用户故事：**
- 作为难以坚持的用户，我希望有连续打卡激励，这样我会更有动力每天学习
- 作为喜欢成就感的用户，我希望有等级和经验值，这样我能看到自己的进步
- 作为目标导向的用户，我希望能设置每日目标并看到完成情况，这样有明确的反馈

**交互逻辑：**

1. **连续学习 (Streak)：**
   - 定义：每天完成当日目标即算连续一天
   - 首页大字号展示当前 streak 天数
   - 旁边小字显示历史最高 streak
   - 完成今日目标时有庆祝动画
   - 中断后 streak 归零，显示「可惜，你的连续记录中断了」
   - 特殊：周末可「冻结」streak（P2功能，MVP不做）

2. **经验值 (XP)：**
   - 学习新词：每张 +10 XP
   - 复习卡片：每张 +5 XP
   - AI 对话：每分钟 +5 XP

#### 4.1.5 PWA 基础（可安装、离线可用基础词汇）

**功能描述：**
将网站打包为 PWA，支持添加到主屏幕、离线访问已缓存的内容。MVP 阶段实现基础离线能力（闪卡内容可离线学习）。

**用户故事：**
- 作为通勤用户，我希望在地铁上没有网也能背单词，这样不浪费时间
- 作为重度用户，我希望把应用加到主屏幕，这样打开更方便
- 作为关注体验的用户，我希望应用启动快，这样体验更像原生App

**交互逻辑：**

1. **PWA 安装：**
   - 用户访问网站一段时间后 → 底部弹出「添加到主屏幕」提示
   - 用户点击 → 调用浏览器原生安装流程
   - 安装成功后 → 桌面出现图标，点击全屏打开
   - 也可在个人中心手动触发安装提示

2. **离线体验：**
   - 首次访问 → 缓存应用外壳（HTML/CSS/JS/字体/图标）
   - 用户学习过的词库 → 自动缓存到本地
   - 离线打开 → 显示应用外壳和已缓存内容
   - 未缓存的页面 → 显示离线提示页，引导用户去已缓存的闪卡学习
   - 个人中心显示「离线内容」管理入口

3. **缓存策略：**
   - 应用外壳：Cache First，预缓存
   - 词库数据：Cache First，版本更新时重新缓存
   - 学习记录：本地优先（localStorage/IndexedDB）
   - AI对话：Network Only（必须联网）
   - 图片：Stale-While-Revalidate

4. **离线内容管理：**
   - 个人中心 → 离线内容
   - 显示已缓存的词库、占用空间
   - 可手动下载更多词库
   - 可清除缓存

#### 4.1.7 首批语种内容：英语 + 日语

**功能描述：**
MVP 阶段提供英语和日语两个语种的基础词汇内容，每个语种约 1000-2000 核心词汇。

**内容规格：**

| 语种 | 词库名称 | 词汇量 | 分级 | 内容来源 |
|------|---------|-------|------|---------|
| 英语 | 核心词汇 2000 | 2000 | A1-B1 | Tatoeba + 人工整理 |
| 日语 | 核心词汇 1000 | 1000 | N5-N4 | Tatoeba + 人工整理 |

**每个词汇包含：**
- 单词（目标语）
- 音标 / 假名
- 词性
- 中文释义（1-3 个核心义项）
- 2-3 个例句（含中文翻译）
- CEFR / JLPT 等级标签
- 主题标签

**数据格式：**
- 每个语种一个 JSON 文件：`data/words-en.json`, `data/words-ja.json`
- 按需加载，不一次性全部加载
- 支持增量加载：先加载 A1 级别，用户学完后再加载 A2

## 6. 技术架构

### 6.1 前端架构

#### 6.1.1 技术选型：纯 HTML/CSS/JS + PWA

**选型理由：**

1. **与白驹主站架构统一**：白驹主站采用纯静态 HTML/CSS/JS 架构，环球语堂作为实战中心项目，沿用同一架构可保持开发规范一致，降低维护成本
2. **轻量快速**：无框架依赖，首屏加载极快，用户打开即用
3. **PWA 友好**：纯静态站点天然适合 PWA，Service Worker 管理简单
4. **MVP 阶段效率高**：无需构建工具链，直接编写即可运行，快速验证产品
5. **部署简单**：纯静态文件，CDN 即可部署，成本极低
6. **学习成本低**：团队成员熟悉原生 JS，无需额外学习框架

**为什么不用 Next.js / React：**

| 维度 | 纯 HTML/CSS/JS | Next.js / React |
|------|---------------|-----------------|
| **首屏性能** | 极快（纯静态） | 快（SSG/SSR） |
| **开发效率（MVP）** | 高（无构建） | 中（需搭建工程） |
| **维护成本** | 低（无依赖） | 中（版本升级等） |
| **状态管理复杂度** | 低（本地存储为主） | 中（需状态管理库） |
| **PWA 支持** | 好（原生支持） | 好（需插件配置） |
| **SEO** | 好（纯HTML） | 好（SSR/SSG） |
| **适合团队规模** | 小团队 / 个人 | 中大团队 |
| **用户量级** | MVP → 10万级 | 10万+ |

**升级路径：**
- 当用户量增长到需要更复杂状态管理、服务端渲染、或需要多人协作开发时，可逐步迁移到 Next.js
- 迁移策略：先重写核心页面，旧页面并行运行，逐步替换
- 预计触发迁移的条件：DAU > 1万 或 开发团队 > 3人

#### 6.2.2 Service Worker 与缓存策略

**Service Worker 核心逻辑：**

```javascript
// service-worker.js
const CACHE_NAME = 'linguavista-v1';
const APP_SHELL = [
  '/linguavista/index.html',
  '/linguavista/css/linguavista.css',
  '/linguavista/css/components.css',
  '/linguavista/js/app.js',
  '/linguavista/js/storage.js',
  // ... 其他核心资源
];

// 安装：预缓存应用外壳
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME).then((cache) => cache.addAll(APP_SHELL))
  );
});

// 激活：清理旧缓存
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((keys) =>
      Promise.all(keys.filter(k => k !== CACHE_NAME).map(k => caches.delete(k)))
    )
  );
});

// 请求拦截：按资源类型采用不同策略
self.addEventListener('fetch', (event) => {
  const url = new url(event.request.url);

  // AI对话API：Network Only（必须联网）
  if (url.pathname.includes('/api/chat')) {
    event.respondWith(fetch(event.request));
    return;
  }

  // 应用外壳：Cache First
  if (APP_SHELL.some(p => url.pathname.includes(p))) {
    event.respondWith(
      caches.match(event.request).then(res => res || fetch(event.request))
    );
    return;
  }

  // 词库数据：Cache First + 版本管理
  if (url.pathname.includes('/data/words-')) {
    event.respondWith(
      caches.match(event.request).then(res => {
        if (res) return res;
        return fetch(event.request).then(response => {
          const clone = response.clone();
          caches.open(CACHE_NAME).then(cache => cache.put(event.request, clone));
          return response;
        });
      })
    );
    return;
  }

  // 图片：Stale-While-Revalidate
  if (/\.(png|jpg|jpeg|gif|webp|svg)$/.test(url.pathname)) {
    event.respondWith(
      caches.match(event.request).then(cached => {
        const fetchPromise = fetch(event.request).then(response => {
          caches.open(CACHE_NAME).then(cache => cache.put(event.request, response.clone()));
          return response;
        });
        return cached || fetchPromise;
      })
    );
    return;
  }

  // 默认：Network First，离线回退到缓存
  event.respondWith(
    fetch(event.request).catch(() => caches.match(event.request))
  );
});
```

### 6.3 数据层

#### 6.3.1 存储方案：localStorage + IndexedDB

**为什么用 localStorage（MVP阶段）：**
- 简单直接，API 易用
- 学习数据主要是 JSON 结构，序列化方便
- MVP 数据量不大（几千条卡片进度，约几百 KB）
- 与白驹主站的存储方式一致

**为什么预留 IndexedDB（升级路径）：**
- localStorage 容量限制（5-10MB），未来内容增多可能不够
- IndexedDB 支持索引查询，性能更好
- 支持离线大数据存储
- 当数据量超过 2MB 或需要复杂查询时迁移

#### 6.3.4 远期云端同步方案预留

**数据同步策略（远期）：**

```
本地 IndexedDB ←→ 同步队列 ←→ 云端 API ←→ 服务端数据库
```

**同步机制：**
1. 所有写入操作先写本地 IndexedDB，立即更新 UI
2. 变更记录写入同步队列（pending_sync）
3. 网络可用时，后台批量同步到服务端
4. 拉取云端变更，合并到本地
5. 冲突解决：Last-Write-Wins（以最后修改时间为准）

**预留接口：**
- `storage.sync()` — 触发同步
- `storage.on('sync:complete')` — 同步完成事件
- `storage.getPendingChanges()` — 获取待同步变更

#### 6.4.3 流式输出方案

**技术方案：SSE (Server-Sent Events)**

- AI 回复通过 SSE 流式返回
- 前端逐字渲染，实现打字机效果
- 首字延迟 < 1s（目标）

**前端实现要点：**

```javascript
// ai-chat.js — 流式对话
async function streamChat(messages, onToken, onComplete, onError) {
  try {
    const response = await fetch('/api/chat/stream', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ messages })
    });

    const reader = response.body.getReader();
    const decoder = new TextDecoder();
    let fullText = '';

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;

      const chunk = decoder.decode(value);
      const lines = chunk.split('\n');

      for (const line of lines) {
        if (line.startsWith('data: ')) {
          const data = line.slice(6);
          if (data === '[DONE]') {
            onComplete(fullText);
            return;
          }
          try {
            const parsed = JSON.parse(data);
            const token = parsed.content || '';
            fullText += token;
            onToken(token, fullText);
          } catch (e) {
            // 非JSON数据，直接作为文本处理
            fullText += data;
            onToken(data, fullText);
          }
        }
      }
    }
  } catch (error) {
    onError(error);
  }
}
```

**打字机效果：**
- 每个 token 到达后立即追加到消息气泡
- 使用 CSS 动画模拟光标闪烁
- 支持用户打断（发送新消息时中止当前流）

### 10.1 技术风险

| 风险 | 影响 | 概率 | 对策 |
|------|------|------|------|
| **AI 对话成本高** | LLM + TTS 成本随用户量线性增长，可能亏损 | 中高 | ① 优化 prompt，减少 token 消耗；② 缓存常见问答；③ 控制免费用户每日对话次数；④ 引入会员制分摊成本；⑤ 多模型策略（简单问题用小模型） |
| **PWA 兼容性问题** | 部分浏览器（尤其是 iOS Safari）PWA 支持不完善 | 中 | ① 优雅降级，核心功能不依赖 PWA；② 针对 iOS 做专项适配；③ 引导用户使用 Chrome/Edge；④ 提供「添加到主屏幕」手动教程 |
| **localStorage 容量不足** | 多语种 + 多词库 + 对话历史可能超出 5MB 限制 | 中 | ① MVP 阶段控制数据量，只缓存必要内容；② 对话历史只保留最近 20 条；③ 提前规划 IndexedDB 迁移方案；④ 数据压缩存储 |
