# 全站内核说明（baiju-core）

> 2026-10-13 建立。内核解决四件事：**角色导入、登录体系、评论与提醒、版心骨架**。
> 设计前提：站点仍然是静态站（零依赖 `server.mjs`），所以内核的一条底线是
> **后端不可达就降级为本地模式，并在界面上写明，不假装云端已保存。**

## 一、文件清单

| 文件 | 作用 |
|---|---|
| `assets/baiju-core.js` | 内核逻辑：角色 / 登录 / 评论 / 提醒 / 导航收敛 / 溢出自愈 |
| `assets/baiju-core.css` | 内核样式 + 三种版心骨架 |
| `ccowork.js` | 全站注入点（覆盖 94.5% 页面），随站注入内核 |
| `scripts/inject-core.mjs` | 给剩下 ~6% 的裸页补注入（幂等） |
| `scripts/apply-skeleton.mjs` | 给页面落 `data-skeleton`（幂等） |
| `scripts/build-all.mjs` | 一键：生成内容 → 注入 → 骨架 → 体检 |
| `scripts/verify-core.mjs` | 真浏览器验收（Playwright） |
| `scripts/smoke-pages.mjs` | 全站抽样冒烟（手机 + 桌面） |
| `scripts/diag-overflow.mjs` | 横向溢出诊断，定位哪个元素撑宽页面 |
| `scripts/test-core-api.mjs` | 后端 API 自检 |
| `server.mjs` | 后端：账号 / 评论 / 提醒（JSON 落盘） |

## 二、三种版心骨架

`<body data-skeleton="...">` —— 只作用于带声明的页面，未声明的保持原样（零破坏）：

- `article` `<article|main|.wrap|.container|.content>` → **`max-width: 68ch`**（约 680px，长文最舒服）
- `cards` 同类容器 → **`1240px`**（卡片墙 / 索引页）
- `desk` → **`1440px`**（工作台，需要横向空间）

```bash
node scripts/apply-skeleton.mjs --dry   # 先看会动哪些页面
node scripts/apply-skeleton.mjs
```

## 三、数据存放

| 位置 | 内容 |
|---|---|
| `localStorage` `baiju.role` | 当前身份（teacher / student / developer / engineer / toolbox / everyone） |
| `localStorage` `baiju.user` / `baiju.token` | 账号资料与登录凭据 |
| `localStorage` `baiju.comments.<path>` | 本页面的本地评论 |
| `localStorage` `baiju.notify.readAt` | 提醒已读水位线 |
| `data/users.json` | 服务端账号（口令只存 salt + sha256，无明文） |
| `data/comments.json` | 服务端评论与提醒 |

## 四、后端 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 探活，前端靠它判断云端 / 本地模式 |
| POST | `/api/auth/login` | `{nick, pass, role}` → `{user, token}`（不存在即注册） |
| POST | `/api/auth/me` | 更新身份 / 昵称（需 token） |
| GET | `/api/comments?path=` | 取某页评论 |
| POST | `/api/comments` | 发表（限流：单 IP 10 秒 3 条） |
| POST | `/api/comments/like` | 点赞 / 取消 |
| POST | `/api/comments/delete` | 删除（只能删自己的） |
| GET | `/api/notify` | 我的提醒 |
| POST | `/api/notify/read` | 全部标为已读 |

前端探测到 `/api/health` 返回非 JSON（静态托管）时自动进入本地模式，评论只存本机。

## 五、每日公众号精选

```bash
node scripts/daily/build-wechat-pick.mjs          # 先抓再挑（约 30-90 秒）
node scripts/daily/build-wechat-pick.mjs --no-collect  # 用现有数据重挑
```

产出 `data/wechat-pick.json`（今天挑的 8 条）和 `website/wechat-pick.html`（一键复制公众号排版 / Markdown）。

挑选规则（可解释，不做 AI 改写）：标签权重 + 新鲜度 + 中文源 + 标题信息量 + AI 相关度，
再叠加三个配额：**单标签最多 3 条、同源最多 3 条、综合源必须命中 AI 词**，
历史推过的 URL 记在 `data/wechat-pick-history.json` 里不再重复推。

## 六、常用命令

npm run verify    # 内核真浏览器验收
npm run smoke     # 全站抽样冒烟
