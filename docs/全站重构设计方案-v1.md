### 五个必须解决的问题

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **版心宽度十几种** | `.wrap` 在每个页面各自定义，实测 1120/1160/1180/1280… | 切页面时内容宽度跳变，这是"凌乱"的物理来源 |
| 2 | **导航是 48~51 张卡片墙** | hub.html | 远超米勒定律 7±2，研究证实 8+ 项使任务完成率降 40% |
| 3 | **交互零统一** | 811 处手写交互、`<dialog>` 0 个、`tabindex` 1 个 | 键盘用户几乎无法导航；弹层行为各页不同 |
| 4 | **命名同义重复** | roadmap / journey / content-roadmap 三重名；ai-academy-* 前缀占 12 个 | 用户分不清差别 |
| 5 | **12 个页面无 h1** | _corpus / agent / chat / assistant / reader / start / workstation 等 | 标题栏与搜索结果全是空白 |

## 二、四端适配规范（调研结论，可点开核对）

### 断点（4 档，比业界少 2 档）

```
phone    320–639px    基础样式，不写 media query（移动优先）
tablet   640–1023px
desktop  1024–1599px
wide     1600px+      大屏 / 电视投屏
```

依据：Tailwind（640/768/1024/1280/1536）、Bootstrap5（576/768/992/1200/1400）、Material UI 已收敛的事实标准。业界共识 **3~5 个断点足够**，十几个断点的维护成本大于精度收益。

### ★ 电视投屏：这是最容易被做错的一环

**核心事实：观看距离差约 10 倍。** 手机 25~35cm，电视 2.4~3.7m。把手机页面直接投屏过去，等于把报纸贴在墙上。

| 项 | 手机 | 电视（硬规范） |
|---|---|---|
| 正文字号 | 14~16px | **最小 28px，推荐 32~36px** |
| 菜单字号 | 14px | **32~44px** |
| 标题 | 20~28px | **48~80px** |
| 对比度 | ≥4.5:1（WCAG） | **正文 ≥7:1，小元素 ≥10:1** |
| 安全区 | — | **四边各留 5%**（老电视过扫描会裁掉边缘） |
| 单屏信息量 | 密集可行 | **宁少勿多**，5~7 张卡一行 |
| 行宽 | 45~75 字符 | **≤10 词/行，段落 ≤90 词切小段** |
| 交互 | 触摸 | **方向键（D-pad）**，无悬停态 |

**两条特别警告**（来自实测文章）：
- **纯白 `#FFFFFF` 在暗环境产生光晕**，电视上应用 `#F1F1F1` 或深灰
- **极细描边和发丝边框在电视上会消失**（运动模糊 + 压缩伪影）
- 高分辨率投影的 DPR 可达 2~3 但 viewport 按逻辑像素缩放 → **字体发虚**，需显式声明 `@media (min-resolution: 192dpi)`

## 三、小程序：个人主体范围（老罗说"规避一下"，正解在这）

### ★ 一条硬约束直接改变方案

> **微信明确规定：个人主体禁止评论区、论坛、私信、投稿、树洞、告白墙等一切 UGC 互动功能。仅可开发纯工具与无用户自主内容发布的单机类功能。**

**所以：评论功能不能进小程序，只能做在网页端。** 这不是我保守，是平台红线。

### 个人主体能做什么（避坑版）

| 能做 | 不能做（明文禁止） |
|---|---|
| 工具：信息查询 / 计算器 / 便签 / 日历 / 记账 / 图片处理 | ❌ 评论区 / 论坛 / 私信 / 投稿 |
| 教育信息展示（**不含**视频播放与课程销售） | ❌ 微信支付（需营业执照 + 对公账户） |
| 资讯信息展示 | ❌ 加载外链 H5 / 套壳（个人主体不可用） |
| 云开发数据库（免费 2GB）+ CDN（5GB/月） | ❌ 视频号 / 直播 / 卡券 / 流量主广告 / 手机号快捷获取 |

### 过审的四个高频雷区

1. **类目错配**：以「工具查询」申报实际做社交 → **直接永久封禁主体**
2. **UGC 未接内容安全 API `msgSecCheck`** → 100% 驳回
3. 空页面 / 死链 / 无响应按钮 → 驳回
4. 强制分享解锁、强制授权 → 驳回

### 我的建议范围

小程序只做**纯展示 + 纯工具**：题库练习、工具真库浏览、地图查看、全球生态。四项都不需要后端写入或交易，个人主体能过审，且与网页端数据同源。

## 四、命名体系（状态隐喻风格，83 页全覆盖）

### 心理学期限（你提的"不要一眼望穿、要有因果"）

| 原理 | 主张 | 对命名的影响 |
|---|---|---|
| **加工流畅性悖论** | 越顺口的名字传播越快，但存进长期记忆的概率越低 | 目标是「**一秒转念、转念后立刻懂**」——多一次加工，记忆才牢 |
| **双重编码理论** | 抽象概念要图像+语言双通道才记得牢 | 禁用抽象容器词（库/站/中心/平台），改用能生成画面的具象词（图谱/阶梯/清单/脉搏） |
| **因果推理链** | 人天生为观察到的事物寻找原因 | 每个名字必须能填满「**因为{真���}，所以{名字}**」 |

### 六组导航（米勒定律 7±2 → 6 组）

| 组 | 页数 | 这组的因果（会写在页面上） |
|---|---|---|
| **认识** | 10 | AI 每天都在变，你需要实时更新的图谱，而不是去年的书 |
| **学会** | 16 | 看完不等于做到，所以每章配题库与错题本 |
| **去做** | 16 | 工具的意义在于用它做出东西 |
| **生活** | 10 | 技术最终要落到具体的人和具体的日子上 |
| **观察** | 11 | 变化太快，需要有人替你盯着 |
| **上手** | 11 | 工具本身不产生价值，被用起来才产生价值 |

### 命名示例（旧 → 新 + 因果）

| 旧名 | 新名 | 因为 |
|---|---|---|
| 全球 AI 生态，一张地图看完 | **AI 生态正在生长** | 每周都有新厂商进来，静态榜单几天就过期 |
| AI 工具真库 | **工具正在被验证** | 宣传语谁都会写，我们只收能被点开验证的 |
| 章节测验 · 认证考试 | **会了才算学会** | 读懂和答对之间隔着一道坎 |
| 每日简报 | **今天发生了什么** | 资讯的价值在于时效，我们每天直抓真实源 |
| 从零开始构建智能体 | **一级一级往上走** | 智能体不是一门课而是一座阶梯 |
| 交警手势 vs 红绿灯 | **规则到底怎么算** | 罚则条目常被引错条文号，我们对回原文 |
| 总站导航台 | **全部入口** | 289 个页面不该靠记忆寻找 |

（完整 74 个页面命名见 `data/design/naming-system.json`）

## 五、三种页面骨架 + 统一交互层

### 骨架（所有页面归入三种，不再各写各的）

| 骨架 | 适用 | 版心 | 特征 |
|---|---|---|---|
| **长文型** | 43 章 + blog + 深度整理 | **68ch**（约 680px） | 单栏、行宽受控、左侧固定目录、右侧留白 |
| **卡片墙型** | 生态库、真库、题库 | **1240px** | 3/4 列自适应、卡片等高、筛选吸顶折叠 |
| **工作台型** | 工作台、设置、聊天 | **1440px** | 侧栏 + 主区 + 辅助栏三栏、可折叠 |

**每个页面必须声明 `data-skeleton="article|cards|desk"`**，样式层据此套用对应骨架。**版心只有这 3 个值**，彻底消灭"十几个宽度"。

### 交互层（统一挂 `module.js`，233 个页面已引入）

- **所有弹层改 `<dialog>`**：原生焦点陷阱、ESC 关闭、`:modal` 背景，替代现在 811 处手写
- **键盘可达**：`tabindex` 从 1 个补到全站可用，焦点环统一
- **焦点可见**：`:focus-visible` 全站统一样式
- **动效克制**：统一时长与缓动，`prefers-reduced-motion` 全站尊重
- **焦点态**：电视端必须可见（缩放 + 阴影 + 边框叠加）

## 六、题库系统（引入间隔重复）

### 算法选型

| 算法 | 逻辑 | 优势 | 劣势 |
|---|---|---|---|
| **SM-2**（1987，Anki 用到 2023） | Ease Factor（起始 2.5）+ Interval；评分<3 则重置为 1 天 | 简单透明、零训练数据、第一次复习就有效、40 年实战验证 | 乘数通用，不适配个人；无显式留存目标 |
| **FSRS**（2022，Anki v23.10 起默认） | DSR 模型：难度/稳定度/可检索性 | 5 亿+ 复习记录基准上，**少 20~30% 复习量**达同等留存 | 需约 1000 次复习才拟合出个人模型 |

**建议**：默认 SM-2（可预测、可手算、易调试），题量过千后切 FSRS。这是 Anki 自己走过的路径。

### 出卡规则（五条，最重要的一条是第一）

1. **一张卡只考一个知识点** —— 考多个要素就无法诚实评分，算法也区分不出掌握程度
2. **问题必须有唯一答案** ——「讲讲笛卡尔」不可预测，「《方法论》1637 年作者是谁」可预测
3. **不考易变事实** —— 价格/排名/统计数字除非有更新机制
4. **抽象概念配助记或图像** —— 算法只管何时出现，编码质量靠内容
5. **新卡当天先过一遍** —— 捕捉表述错误，别让它进长期轮转

**每日新卡上限 10~20 张**是可持续的关键；50+ 张会在三周内积压到做不完而放弃。
