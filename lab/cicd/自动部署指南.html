自动部署指南：从「本地文件夹」到「手机上能访问的网址」

目标：把项目里的 website/ 目录（纯静态 HTML）变成一个手机浏览器也能打开的网址。 全程免费，只用一个 GitHub 账号。零门槛，跟着一步步做即可。

配套文件：deploy-github-pages.yml（复制到仓库 .github/workflows/ 即用）。

总览：我们要走哪几步

本地文件夹 website/
        │
        │  ① git init + 推送到 GitHub（让代码上云）
        
GitHub 仓库（云端代码）
        │
        │  ② 放入 workflow 文件（告诉 GitHub "怎么自动部署"）
        │  ③ Settings  Pages  选 GitHub Actions（开启发布开关）
        
GitHub Pages 自动构建 + 发布
        │
        │  ④ 拿到网址 https://用户名.github.io/仓库/
        
手机浏览器打开网址

补充：如果不想折腾 Git，第 ⑤ 节有 Vercel / Netlify 拖拽上传 的替代方案，3 分钟也能上线。

① 把本地文件夹推到 GitHub（git init + push）

1.1 先建好远程空仓库（网页操作）

  1. 打开 https://github.com，登录后点右上角 ＋ New repository。

    【截图位：GitHub 首页右上角 + 号 New repository】

  2. Repository name 填一个英文名，例如 my-site（仓库名会出现在最终网址里）。
  3. 可见性选 Public（公开仓库免费使用 GitHub Pages；私有仓库的 Pages 需要付费计划）。
  4. 不要勾选 "Add a README / .gitignore / license"（保持空仓库，方便推送）。
  5. 点 Create repository，记下页面上显示的仓库地址，形如：
    https://github.com/你的用户名/my-site.git

    【截图位：新建仓库页面，红框标出仓库名、Public、仓库地址】

1.2 在项目根目录执行 git 命令（本机操作）

在项目根目录（C:\Users\35683\CodeBuddy\20260815143624，也就是有 website/、lab/ 的这层）打开终端，依次执行：

# 1) 初始化 git 仓库（首次做一次）
git init
# 2) 把所有文件加入暂存区
git add .
# 3) 提交第一个版本
git commit -m "init: 初始提交（网站 + 实验室内容）"
# 4) 默认分支改名为 main（GitHub 默认分支名）
git branch -M main
# 5) 关联远程仓库（把下面的地址换成你自己的）
git remote add origin https://github.com/你的用户名/my-site.git
# 6) 推送到 GitHub
git push -u origin main

【截图位：终端执行 git push -u origin main 成功，显示 Branch 'main' set up to track】

推送时若提示输入账号密码：GitHub 已不支持密码登录，需在 GitHub Settings Developer settings Personal access tokens 生成一个 Personal Access Token 当密码用；或直接用 GitHub Desktop / VSCode 登录推送，更省事。

推送成功后，刷新 GitHub 仓库页面，就能看到 website/、lab/ 等目录出现在网页上了。

【截图位：GitHub 仓库首页显示代码文件树】

② 把 workflow 放进 .github/workflows/

GitHub Actions 靠 .github/workflows/ 目录下的 .yml 文件来决定「什么时候、干什么」。

  1. 在仓库根目录新建两个文件夹层级：.github 里面再建 workflows。
  2. 把本目录的 deploy-github-pages.yml 复制进去，最终路径必须是：
    .github/workflows/deploy-github-pages.yml

注意：.github 开头带点，是隐藏文件夹。Windows 文件资源管理器里看不到时， 打开「查看 隐藏的项目」勾选即可。

两种操作方式，任选其一：

  • 方式 A（终端，最快），在项目根目录执行：

    # Windows PowerShell / macOS / Linux 通用
mkdir -p .github/workflows
cp lab/cicd/deploy-github-pages.yml .github/workflows/deploy-github-pages.yml
git add .github/workflows/deploy-github-pages.yml
git commit -m "deploy: 接入 GitHub Pages 自动部署"
git push

  • 方式 B（网页，直观）：在 GitHub 仓库页面点 Add file Create new file， 文件名框输入 .github/workflows/deploy-github-pages.yml， 把 deploy-github-pages.yml 的内容粘贴进去，直接点 Commit new file。

    【截图位：网页新建文件，文件名框已填 .github/workflows/deploy-github-pages.yml】

推送到 main 分支后，GitHub 会自动触发这次部署（因为 workflow 里的 paths 包含了本工作流文件本身）。

③ 开启 GitHub Pages（Settings Pages GitHub Actions）

这一步是「总开关」，只需设置一次：

  1. 打开 GitHub 仓库页面，点顶部 Settings 标签。
  2. 左侧菜单点 Pages。
  3. 找到 Build and deployment 区域，把 Source 从默认的 Deploy from a branch 改成 GitHub Actions。

    【截图位：Settings Pages 页面，红框标出 Source 下拉框选 GitHub Actions】

  4. 页面会自动保存，无需其它操作。

如果你已经先推了 workflow 再开这个开关也没关系——开好后，去 Actions 标签页 找到刚才那次失败的运行记录，点右上角 Re-run all jobs（或手动触发一次）即可。 或者到 Actions 左侧选中该 workflow 点 Run workflow 按钮手动跑一次。

④ 拿网址，手机访问

4.1 确认部署成功

  1. 打开仓库 Actions 标签页，选中左侧的「部署 website 到 GitHub Pages」workflow。

    【截图位：Actions 运行列表，两条任务 build + deploy 均显示绿色 】

  2. 点进最新一次运行，deploy 任务成功后，页面顶部会有一个 可直接点击的站点链接（来自 environment.url）。
  3. 部署成功后回到 Settings Pages，页面顶部也会显示一行绿字：

    Your site is live at https://用户名.github.io/仓库名/ 【截图位：Pages 页面顶部 "Your site is live at ..." 绿字横幅】

4.2 最终网址的规律

仓库类型 网址格式 例子
用户/组织主页仓库（仓库名 = 用户名.github.io） https://用户名.github.io/ https://alice.github.io/
普通项目仓库（本项目这种） https://用户名.github.io/仓库名/ https://alice.github.io/my-site/

本项目属于第二种，网址形如：

https://你的用户名.github.io/my-site/

4.3 手机访问

  • 手机连任意网络（WiFi / 4G/5G），打开浏览器，输入上面的网址即可访问。
  • 因为 GitHub Pages 是公网服务，所以手机不需要和电脑在同一 WiFi，走到哪都能打开。

常见坑：打开后是 404 或空白。

  1. 等 1~2 分钟，Pages 首次发布有缓存延迟。
  2. 确认 Settings Pages 的 Source 是 GitHub Actions（不是 branch）。
  3. 确认 upload-pages-artifact 的 path 写的是 website（子目录），不是仓库根。
  4. 确认网址里带了 /<仓库名>/ 这一层（普通项目仓库必须有）。
  5. 确认 website/index.html 里的链接是相对路径（如 ./chat.html、../lab/...）， 而不是以 / 开头的绝对路径——否则在子路径下会跳错。

进阶：想让网址不带 /仓库名/，可以到 Settings Pages 配置 Custom domain （绑定你自己的域名），或把仓库改名为 用户名.github.io。

⑤ 替代方案：Vercel / Netlify（拖拽或 CLI 一键）

不想装 Git、不想管 Actions？用「拖拽上传」或「CLI 一键」，3 分钟也能上线，还自带全球 CDN。

方案 A：Vercel（推荐，最省事）

方式一：网页拖拽（零命令）

  1. 打开 https://vercel.com，用 GitHub 账号一键登录。
  2. 点 Add New Project Import 导入你的 GitHub 仓库；没有仓库就选 Deploy 后用 Upload 直接上传 website/ 文件夹。

    【截图位：Vercel 导入页面，红框标出 Import 与拖拽上传区】

  3. 关键配置：Root Directory 填 website（让它只发布网站目录），框架选 Other。
  4. 点 Deploy，约 30 秒出结果，得到一个 https://xxx.vercel.app 网址，手机直接访问。
  5. 之后每次 git push 到 main 都自动重新部署。

方式二：CLI 一键（命令行）

# 1) 全局安装 Vercel CLI
npm i -g vercel
# 2) 进入 website 目录，一键部署（首次会引导你登录）
cd website
vercel            # 预览部署
vercel --prod     # 生产部署（正式网址）

方案 B：Netlify（同样免费，拖拽极简）

方式一：网页拖拽（最快）

  1. 打开 https://app.netlify.com 登录。
  2. 进入 Sites 页面，把 website/ 文件夹直接拖进虚线框。

    【截图位：Netlify Sites 页面的拖拽上传虚线框】

  3. 松手即开始上传，几秒后生成 https://xxx.netlify.app 网址，手机即可访问。
  4. 想改内容：重新拖拽覆盖，或关联 GitHub 仓库实现自动部署。

方式二：CLI 一键（命令行）

# 1) 全局安装 Netlify CLI
npm i -g netlify-cli
# 2) 进入 website 目录，一键部署（首次会引导你登录/授权）
cd website
netlify deploy --prod --dir .

三个平台怎么选

平台 上手难度 优点 何时选
GitHub Pages 中（要懂点 git） 全在 GitHub 生态、免费、稳定 已有 GitHub 账号、想练 CI/CD
Vercel 低 拖拽/CLI 皆可、CDN 快、PR 预览 想最快上线、要全球加速
Netlify 最低 拖拽上传最傻瓜 只想拖个文件夹立刻出网址
