智能体基础

Agent 概念
什么是智能体（Agent）？与传统程序有什么区别？
智能体是能够感知环境 自主决策 采取行动以达成目标的实体。区别：传统程序按预设逻辑执行，是确定性的；LLM 智能体以大模型为「大脑」，能理解自然语言指令、规划任务、调用工具、根据反馈动态调整，具备自主性、工具使用、记忆与反思能力。核心转变是「从写代码控制流程，到用提示词引导模型自主完成」。
对应章节：chapter-01、chapter-04
LLM 智能体的基本工作循环是什么？
典型循环：观察（Observation） 思考（Thought） 行动（Action） 再观察。智能体把任务交给 LLM，模型输出推理与要执行的工具调用，系统执行工具返回结果，再喂回模型，循环直到任务完成或达到终止条件。这与 ReAct 范式的「推理 + 行动交替」一致。
什么是工具调用（Tool Calling / Function Calling）？为什么重要？
工具调用让模型输出结构化调用指令（函数名 + 参数），由系统执行真实 API/函数，把结果返回给模型继续推理。它把 LLM 的「只会说」变成「能做」：查天气、执行代码、读写数据库、发邮件等。重要性：这是智能体与现实世界交互的执行器，也是 MCP 协议的底层能力。

ReAct 范式

推理 + 行动
解释 ReAct 范式，为什么有效？
ReAct = Reasoning + Acting。模型交替输出「思考（Thought）」和「行动（Action）」，行动结果作为「观察（Observation）」反馈回来。有效性：① 思考让模型把复杂任务拆解并推理，减少幻觉；② 行动让模型获取外部信息（搜索、查库），弥补知识时效；③ 交替循环形成可追踪的推理轨迹，便于调试。是 Chain-of-Thought 与工具使用的结合。
Plan-and-Solve 和 ReAct 有什么区别？
Plan-and-Solve 先一次性规划整个任务步骤，再逐步执行（计划前置）；ReAct 是边想边做，每一步先思考再行动。前者适合任务结构清晰、可预先拆解的场景（更省 token）；后者适合需要动态调整、信息逐步获取的场景（更灵活）。实践中常混合：先规划，执行中按需 ReAct 修正。

RAG

检索增强生成
什么是 RAG？解决什么问题？
RAG（Retrieval-Augmented Generation）= 检索 + 生成：先从知识库检索相关文档，再把文档拼进提示词让模型基于它们回答。解决两大原生缺陷：①幻觉——模型知识有限且可能编造；②知识时效——训练数据有截止日期。企业私有文档（内部资料、产品手册）尤其依赖 RAG，因为模型没学过这些内容。
RAG 的三环节是什么？
①索引（Index）：文档切分（chunking） 向量化（Embedding） 存入向量数据库；②检索（Retrieve）：把用户问题向量化，用相似度（余弦/点积）召回 Top-K 相关片段，可配合重排（Rerank）；③生成（Generate）：把检索结果 + 用户问题组装成提示词，交给 LLM 生成带依据的回答。
如何抑制 RAG 的幻觉？
多层手段：①检索质量：优化切分策略、混合检索（关键词 + 向量）、重排模型提准率；②提示约束：要求模型「只依据给定材料回答，找不到就说不知道」；③引用溯源：输出带来源片段，便于人工核验；④评估：用忠实度（faithfulness）、答案相关度（answer relevance）指标持续迭代。

MCP 与通信协议

协议层
什么是 MCP？解决什么问题？
MCP（Model Context Protocol）是「AI 应用的 USB-C 接口」：一套标准化协议，让 LLM 应用统一连接外部工具、数据源、服务。以前每个工具都要单独对接（私有格式、安全各做各的），MCP 定义了 Server/Client 结构、工具发现与调用规范、资源与提示词交换，一次接入到处复用，解决工具碎片化与集成成本。
A2A 协议和 MCP 的分工？
MCP 解决「智能体 工具/数据」的连接；A2A（Agent-to-Agent）解决「智能体 智能体」的协作——跨系统智能体如何发现彼此、通信、编排任务。两者互补：A2A 负责智能体之间的互操作，MCP 负责智能体与底层能力的互操作，共同构成智能体生态的通信底座。

多智能体协作

编排
多智能体协作有哪些典型模式？
①流水线（Pipeline）：任务按角色串行传递（如策划 调研 写稿 校对）；②层级（Hierarchy）：主控智能体派发子任务给专家智能体（如主管 + 程序员/测试）；③辩论（Debate）：多智能体各自给方案再交叉评审，提升决策质量；④市场（Marketplace）：任务竞价分配。模式选择取决于任务复杂度与角色耦合度。
多智能体相比单智能体的优劣？
优：任务并行、角色专精、可隔离复杂逻辑、天然支持人类介入环节。劣：token 成本更高、通信与状态同步复杂、错误可能级联放大、编排调试难。经验：能用单智能体就别上多智能体，复杂度不是越花哨越好。

提示词工程

Prompt
提示词的组成要素有哪些？
四要素：①指令（Instruction）——让模型做什么；②上下文（Context）——背景信息与约束；③输入数据（Input Data）——待处理内容；④输出格式（Output Format）——期望的结构（JSON/表格/长度）。核心原则：明确、具体、给示例、定义边界。
什么是思维链（Chain-of-Thought）？
CoT 引导模型先展示推理过程再给结论（「一步步思考」或提供推理示例），显著提升复杂推理任务的准确率，尤其数学、逻辑题。进阶形态：Self-Consistency（多次采样投票）、ToT（树状搜索多条推理路径）、ReAct（推理 + 工具）。

微调与部署

模型定制
LoRA 是什么？为什么流行？
LoRA（Low-Rank Adaptation）是参数高效微调：冻结原模型权重，只训练注入的低秩矩阵（约千分之一参数量）。优点：显存占用小、训练快、可随时切换多个微调版本、几乎不牺牲效果。特别适合在消费级 GPU 上微调大模型，也是社区 LoRA 模型（绘画/风格）的基础。
微调 vs RAG vs 提示词，怎么选？
三者的本质：提示词是「现场指导」（零成本、即改即用）；RAG 是「带资料上场」（解决私有/时效知识）；微调 是「改变说话方式与专有能力」（格式、风格、领域语言）。经验法则：先提示词，知识问题加 RAG，长期固定的行为/风格问题才微调——微调成本最高，最后考虑。
私有化部署大模型的常见路径？
①Ollama：一键本地跑 Qwen/Llama 等开源模型，适合个人与验证；②vLLM / TensorRT-LLM：生产级推理引擎，吞吐高，支持量化；③Docker + GPU 集群：企业私有化，配负载均衡与监控；④关键点：模型量化（GGUF/INT8/INT4）压显存、KV Cache 优化、并发与成本控制。详见 chapter-20。

大模型基础

Transformer
Transformer 的核心机制是什么？
核心是自注意力（Self-Attention）：每个 token 通过 Query/Key/Value 计算与其他 token 的相关度（注意力权重），加权聚合信息。多头注意力让模型并行关注不同子空间。加上位置编码（Positional Encoding）保留语序、前馈网络与层归一化。它的突破是并行计算 + 长距离依赖建模，取代了 RNN 的串行短板。
什么是 Token？上下文窗口？
Token 是模型处理文本的最小单元（中文常 1 字≈1-2 token）。上下文窗口是模型一次能「看到」的最大 token 数（如 32K/128K）。窗口越大可读入更多资料，但成本与延迟随之上升，因此上下文工程（压缩、摘要、按需注入）成为实用技能。详见 chapter-09。

综合实战

场景题
设计一个企业智能客服，讲清架构。
推荐架构：入口（渠道接入） 意图路由 分支处理。①FAQ 类走 RAG（文档知识库检索回答）；②工单/操作类走 工具调用（查订单、改状态）；③复杂问题升级人工（Human-in-the-loop）。存储层：向量库（文档）+ 业务库（订单）。质量层：回答引用溯源 + 兜底话术 + 会话日志回流优化。要点：先解决「80% 常见问题」，再逐步扩展。
如何评估一个智能体的好坏？
分层评估：①任务成功率（能否完成目标）；②中间过程质量（规划合理性、工具调用正确率、失败重试）；③输出质量（相关性、忠实度、格式合规）；④效率（token 消耗、步数、延迟）；⑤鲁棒性（边界输入、恶意输入）。方法：构建评测集（golden set）+ 自动化指标 + 人工抽检，持续回归。详见 chapter-12。
