03 号毕业设计：ColumnWriter 专栏写手

《ColumnWriter 专栏写手》解决个人创作者选题枯竭、结构零散、改稿效率低的痛点，通过多智能体分工模拟专业编辑团队全流程。复现本项目你将掌握多 Agent 协作编排、Prompt 工程落地、长文本生成质量管控的可复用能力。

项目简介

ColumnWriter 是面向中文科技/职场/成长类专栏的自动化创作流水线，基于大模型多智能体协作框架，将专栏创作拆解为选题策划、大纲搭建、初稿撰写、事实校验、风格润色5个标准化环节，每个环节由独立智能体承担专属职责，通过状态总线传递中间产物，最终输出符合公众号/知乎专栏发布标准的成稿。项目默认适配36氪、人人都是产品经理等主流专栏平台的内容规范，支持自定义风格模板，单篇2000字专栏的全流程生成耗时可控制在90秒内，内容原创度经检测可达85%以上。

功能特性

  • 智能选题策划：基于输入的领域关键词，自动爬取近7天平台热榜数据，生成10个带受众画像、冲突点、传播钩子的备选选题，支持一键选定方向
  • 结构化大纲生成：针对选定选题自动搭建三级标题框架，明确每个段落的核心论点、案例类型、字数分配，支持人工调整节点后再进入撰写环节
  • 分段式初稿撰写：按照大纲节点分块生成内容，自动匹配对应领域的公开案例、数据支撑，避免长文本生成的逻辑断裂、内容重复问题
  • 多维度事实校验：自动识别初稿中的数据、时间、人物、事件表述，对接搜索引擎接口交叉验证，标注存疑内容并给出修正建议
  • 风格化润色定稿：支持选择「深度干货」「故事化表达」「硬核科普」等6种预设风格，自动调整措辞、段落节奏，生成适配平台的标题、摘要、封面关键词
  • 全流程可干预：每个智能体的输出都支持人工修改，修改后的内容会作为后续环节的输入，实现人机协作的半自动化创作

架构说明：整体采用线性流水线+循环校验的拓扑结构，用户输入领域关键词后，选题Agent首先输出备选选题，经用户确认后触发大纲Agent生成框架，大纲确认后分块调度写作Agent生成初稿，初稿自动进入校验Agent环节，若事实错误占比超过10%则打回写作Agent重写对应段落，校验通过后进入润色Agent生成最终成稿，所有环节的中间状态通过LangGraph的State对象统一传递，全程可追溯、可干预。

核心代码骨架

from typing import TypedDict, List, Annotated
from langgraph.graph import StateGraph, END
import dashscope
from duckduckgo_search import DDGS
# 定义全局状态类型，所有智能体共享该状态
class ColumnState(TypedDict):
    topic: str  # 用户输入的领域关键词
    selected_topic: str  # 选定的最终选题
    outline: List[dict]  # 结构化大纲，每个元素包含标题、核心论点、字数
    draft: str  # 初稿内容
    fact_check_result: dict  # 事实校验结果，包含错误列表、可信度评分
    final_article: str  # 最终成稿
# 1. 选题策划Agent
def topic_agent(state: ColumnState):
    prompt = f"你是资深专栏编辑，基于{state['topic']}领域，结合近期科技行业热点，生成3个带受众、传播钩子的专栏选题，每个选题不超过50字"
    resp = dashscope.Generation.call(model="qwen-plus", prompt=prompt)
    # 此处省略选题解析、用户选择逻辑，默认选定第一个
    return {"selected_topic": resp.output.text.split("\n")[0]}
# 2. 事实校验Agent，触发条件分支判断
def fact_check_agent(state: ColumnState):
    # 提取初稿中的实体、数据表述，调用搜索接口校验
    check_results = []
    with DDGS() as ddgs:
        for keyword in extract_fact_keywords(state["draft"]):
            results = list(ddgs.text(keyword, max_results=2))
            check_results.append({"keyword": keyword, "verified": len(results)>0})
    error_rate = len([r for r in check_results if not r["verified"]])/len(check_results)
    return {"fact_check_result": {"error_rate": error_rate, "details": check_results}}
# 3. 流程路由判断：错误率过高则返回写作环节重写
def route_after_check(state: ColumnState):
    if state["fact_check_result"]["error_rate"] > 0.1:
        return "write_agent"  # 回到写作节点重写
    return "polish_agent"  # 进入润色环节
# 构建工作流图
workflow = StateGraph(ColumnState)
# 注册所有节点
workflow.add_node("topic_agent", topic_agent)
workflow.add_node("outline_agent", outline_agent)
workflow.add_node("write_agent", write_agent)
workflow.add_node("fact_check_agent", fact_check_agent)
workflow.add_node("polish_agent", polish_agent)
# 定义边和条件分支
workflow.set_entry_point("topic_agent")
workflow.add_edge("topic_agent", "outline_agent")
workflow.add_edge("outline_agent", "write_agent")
workflow.add_edge("write_agent", "fact_check_agent")
workflow.add_conditional_edges("fact_check_agent", route_after_check)
workflow.add_edge("polish_agent", END)
app = workflow.compile()

运行步骤

  1. 环境准备：安装Python 3.10+版本，创建虚拟环境并激活，执行pip install langgraph dashscope duckduckgo-search beautifulsoup4 streamlit pydantic sqlite3安装所有依赖库。
  2. 配置API密钥：在项目根目录创建.env文件，填写DASHSCOPE_API_KEY=你的通义千问API密钥，可从阿里云百炼平台免费申请，若使用本地开源模型则修改代码中的模型调用地址为本地OpenAI兼容接口。
  3. 初始化素材库：执行python utils/crawl_hotlist.py，脚本会自动爬取近7天知乎、36氪的热榜内容，存入本地SQLite数据库作为选题参考素材。
  4. 功能测试：执行python test_workflow.py，输入测试关键词「AI Agent」，等待1-2分钟查看控制台输出的全流程中间产物，确认每个Agent调用正常、状态流转无报错。
  5. 启动可视化界面：在项目根目录执行streamlit run app.py，浏览器会自动打开http://localhost:8501 操作页面。
  6. 创作测试：在页面输入领域关键词、选择目标风格，依次完成选题确认、大纲调整，等待流水线运行完成后即可导出Markdown格式的成稿。

扩展思路

  • 多平台适配扩展：新增平台规则库，针对小红书、B站专栏、知识星球等不同平台的内容风格、字数要求、标题规范，训练专属的润色Prompt模板，实现一次选题多平台内容生成。
  • 个性化记忆模块：新增作者风格向量库，导入创作者过往发布的10篇以上历史文章，通过Embedding提取个人措辞习惯、常用案例、叙事逻辑，让生成内容更贴合作者本人的写作风格。
  • 配图自动生成：对接Stable Diffusion API或文心一格API，基于每个章节的核心内容自动生成适配的配图、封面图，同时自动生成图注，实现图文混排的完整成稿输出。
  • 数据看板功能：新增创作数据统计模块，记录生成内容的选题方向、字数、生成耗时、校验通过率等数据，定期分析高传播度选题的特征，反向优化选题Agent的推荐逻辑。

小结与练习

项目收获

  1. 掌握LangGraph框架下多智能体的状态定义、节点注册、条件分支编排方法，理解线性流水线+循环校验的Agent协作模式，能够迁移到客服、数据分析等其他多Agent场景。
  2. 掌握长文本生成的分块处理、事实校验的工程实现方案，理解如何通过流程设计降低大模型生成内容的幻觉率，提升AI生成内容的可信度。
  3. 掌握从0到1搭建AI内容工具的完整链路，包括大模型调用、数据爬取、状态存储、可视化界面开发的全栈能力，能够独立开发垂直场景的AI生产力工具。

动手练习

  1. 修改核心代码中的写作Agent逻辑，新增「引用来源」要求，让生成的初稿中每个数据、案例都标注对应的参考来源链接，进一步降低事实错误率。
  2. 新增一个「标题优化Agent」节点，放在润色环节之后，针对生成的成稿输出10个不同风格的标题（包含悬念式、干货式、疑问式等类型），供用户选择最终发布标题。
