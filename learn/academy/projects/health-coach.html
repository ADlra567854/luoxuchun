23 号毕业设计：HealthCoach 健身教练

很多健身新手缺乏科学的计划指导、饮食搭配和持续的打卡动力，难以坚持达成健身目标。本项目带你从零搭建私教Agent，掌握LLM应用开发、RAG知识库构建与用户状态管理的落地能力。

项目简介

HealthCoach 健身教练是一款面向健身新手与进阶爱好者的垂直领域私教Agent，基于大语言模型与健身领域知识库，为用户提供个性化训练计划生成、科学饮食建议、打卡激励与进度追踪服务，解决传统健身App计划僵化、反馈滞后、缺乏互动激励的痛点，相当于用户口袋里的24小时在线私教。项目采用轻量架构设计，无需复杂算力支持，普通个人电脑即可部署运行，适合AI应用开发初学者作为垂直领域Agent的入门实践项目。

功能特性

  • 个性化训练计划生成：根据用户填写的身高、体重、健身目标（增肌/减脂/塑形/康复）、可用器械、每周可训练时长，自动生成分阶段的周度训练计划，包含动作组数、次数、休息间隔与动作要点提示
  • 科学饮食建议：结合用户基础代谢率、训练目标与饮食偏好，生成每日三餐+加餐的食谱方案，标注热量、宏量营养素（蛋白质/碳水/脂肪）占比，支持外卖/食堂场景的食物替换建议
  • 智能打卡激励：支持用户上传训练/饮食打卡内容（文字/图片描述），自动识别完成度，给出针对性反馈，连续打卡触发成就徽章与正向激励话术，断卡时发送温和提醒
  • 健身知识库问答：基于专业健身教材、权威运动指南构建RAG知识库，解答动作标准性、运动损伤预防、补剂选择等常见问题，避免网络健身谣言误导
  • 进度数据追踪：自动记录用户体重、围度、训练重量等核心指标，每周生成进度复盘报告，动态调整后续训练与饮食方案，适配平台期用户需求
  • 场景化提醒：根据用户设置的作息时间，推送训练提醒、餐前饮食建议、睡前拉伸提示，贴合用户日常使用习惯

技术架构

组件技术选型作用
大语言模型Qwen2-7B-Instruct（本地部署）/ 通义千问API核心推理引擎，负责计划生成、对话交互、内容理解
向量数据库Chroma存储健身领域知识库的向量切片，支撑RAG检索增强生成
后端框架FastAPI提供HTTP接口，处理用户请求、业务逻辑调度
前端界面Gradio快速搭建可视化交互界面，支持对话、打卡、数据查看
知识库构建LangChain + BGE-small-zh文档切片、向量嵌入、检索链路编排，优化中文语义匹配效果
用户数据存储SQLite轻量化存储用户基本信息、打卡记录、进度数据，无需额外部署数据库服务
工具调用LangChain Tools集成代谢率计算、热量查询、日历提醒等外部工具，增强Agent实用能力

架构说明：项目采用经典的Agent分层架构，最上层为用户交互层，通过Gradio界面接收用户输入并展示结果；中间层为业务调度层，由FastAPI承接请求，通过LangChain编排大模型、工具、知识库的调用链路，判断用户意图后路由到对应功能模块；底层为数据与能力层，分别提供大模型推理、向量检索、结构化数据存储、工具能力支撑。所有组件优先选择轻量化开源方案，最小化部署门槛，同时保留替换为云服务的扩展空间。

核心代码骨架

# 核心模块：健康教练Agent主逻辑
from langchain.agents import AgentExecutor, create_openai_tools_agent
from langchain_community.vectorstores import Chroma
from langchain_community.embeddings import HuggingFaceBgeEmbeddings
from langchain.tools import tool
from langchain_core.prompts import ChatPromptTemplate
from langchain_community.llms import Tongyi
import sqlite3
# 1. 初始化基础组件
llm = Tongyi(model_name="qwen2-7b-instruct", temperature=0.3)
# 加载中文嵌入模型，初始化健身知识库向量库
embed_model = HuggingFaceBgeEmbeddings(model_name="BAAI/bge-small-zh")
vector_db = Chroma(persist_directory="./fitness_kb", embedding_function=embed_model, collection_name="fitness")
db_conn = sqlite3.connect("./healthcoach.db", check_same_thread=False)
# 2. 定义Agent工具集
@tool
def calculate_bmr(weight: float, height: float, age: int, gender: str) -> float:
    """计算用户基础代谢率，传入体重(kg)、身高(cm)、年龄、性别(男/女)"""
    if gender == "男":
        return 10*weight + 6.25*height - 5*age + 5
    else:
        return 10*weight + 6.25*height - 5*age - 161
@tool
def search_fitness_knowledge(query: str) -> str:
    """检索健身知识库，解答动作、损伤、补剂等专业问题"""
    docs = vector_db.similarity_search(query, k=3)
    return "\n".join([doc.page_content for doc in docs])
@tool
def save_checkin_record(user_id: str, content: str) -> str:
    """保存用户打卡记录，返回连续打卡天数"""
    cursor = db_conn.cursor()
    cursor.execute("INSERT INTO checkin (user_id, content, date) VALUES (?, ?, date('now'))", (user_id, content))
    cursor.execute("SELECT count(*) FROM checkin WHERE user_id = ? AND date >= date('now', '-' || ? || ' days')",
                   (user_id, 6))
    streak = cursor.fetchone()[0]
    db_conn.commit()
    return f"打卡成功！当前连续打卡{streak}天，继续保持哦"
# 3. 构建Agent执行链路
tools = [calculate_bmr, search_fitness_knowledge, save_checkin_record]
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是专业的健身私教HealthCoach，回答要科学、接地气，多给用户正向激励，所有专业问题必须先调用知识库检索再回答，用户打卡必须调用打卡记录工具。"),
    ("user", "{input}"),
    ("placeholder", "{agent_scratchpad}")
])
agent = create_openai_tools_agent(llm, tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

运行步骤

  1. 环境准备：安装Python 3.10+版本，执行pip install fastapi uvicorn gradio langchain langchain-community chromadb bce-python-sdk dashscope sqlite3安装所有依赖库，提前申请通义千问API Key（或本地部署Qwen2-7B模型替换）。
  2. 知识库初始化：收集《运动营养学》《健身教练职业资格培训教材》等公开健身文档，保存为txt格式到./raw_docs目录，执行python build_kb.py完成文档切片、向量嵌入，生成Chroma向量库到./fitness_kb目录。
  3. 数据库初始化：执行python init_db.py，自动创建SQLite数据库文件与用户表、打卡记录表、训练计划表三张核心表。
  4. 配置环境变量：在项目根目录创建.env文件，写入DASHSCOPE_API_KEY=你的API密钥，本地部署模型的同学修改代码中llm初始化部分为Ollama加载本地模型的配置。
  5. 启动后端服务：执行uvicorn main:app --host 0.0.0.0 --port 8000，启动FastAPI后端服务，接口文档可通过http://localhost:8000/docs查看。
  6. 启动前端界面：新开终端执行python ui.py，启动Gradio交互界面，访问终端输出的本地地址（默认http://localhost:7860）即可进入产品页面。
  7. 功能测试：首次进入填写个人身高、体重、年龄、健身目标等基础信息，测试生成训练计划、提问健身问题、提交打卡等核心功能，确认返回结果符合预期。

扩展思路

  • 多模态打卡识别：接入Qwen-VL多模态模型，支持用户上传餐食照片、训练动作视频，自动识别餐食热量、判断动作标准度，给出更精准的反馈，替代纯文字打卡的体验。
  • 可穿戴设备对接：集成华为健康、小米运动等开放平台API，自动同步用户每日步数、睡眠时长、运动心率等数据，无需用户手动输入即可动态调整训练强度。
  • 社交互动模块：增加打卡广场、好友PK、组队挑战赛功能，引入社交激励机制，进一步提升用户坚持运动的动力，同时沉淀UGC内容丰富知识库。
  • 个性化模型微调：收集真实私教对话、用户反馈数据，对基础大模型做LoRA微调，让生成的计划、建议更符合国内用户的饮食与运动习惯，减少通用模型的常识错误。

小结与练习

核心收获

  1. 掌握垂直领域Agent的完整开发流程：从领域知识库构建、工具定义、Prompt工程到前后端联调，理解RAG与工具调用结合的Agent实现逻辑。
  2. 学会轻量化AI应用的部署方案：使用Chroma、SQLite等轻量组件降低部署门槛，能够根据场景灵活选择云API或本地开源模型平衡成本与效果。
  3. 理解产品化思维在AI项目中的应用：从用户真实健身场景出发设计功能，通过激励机制、动态调整提升用户留存，而非单纯堆砌大模型能力。

动手练习

  1. 扩展现有工具集：新增一个food_calorie_query工具，对接公开食物热量数据库，支持用户输入食物名称+重量返回对应热量与营养成分，替换原有大模型生成的估算值，提升饮食建议准确性。
  2. 优化打卡激励逻辑：修改打卡记录工具的返回逻辑，当连续打卡满7天、30天时，自动生成专属成就徽章与个性化激励文案，当用户连续2天未打卡时，在对话中主动触发温和提醒。
