11 号毕业设计：LegalAssistant 法律咨询助手

普通用户遇到法律问题时，常面临法规检索门槛高、条款解读不专业、文书起草成本高的痛点，本项目基于开源大模型与法律知识库搭建法律咨询助手，完成后可掌握RAG检索增强、领域Prompt工程、法律垂类应用落地的全流程能力。

项目简介

LegalAssistant 法律咨询助手是面向C端个人用户与基层法律服务从业者的轻量化AI工具，聚焦高频民事法律场景（劳动纠纷、婚姻家事、民间借贷、交通事故），整合国家公开现行有效法律法规、司法解释、指导性案例作为专属知识库，解决通用大模型法律回答 hallucination（幻觉）、引用法条失效、文书格式不规范的核心问题，所有输出均标注法条来源与适用边界，不替代执业律师但可提供合规的初步法律参考。项目全程采用开源技术栈，无商业API依赖，单张16G显存消费级显卡即可部署运行。

功能特性

  • 精准法规检索：支持自然语言提问匹配现行有效法条，自动过滤已废止法规，返回结果标注《XX法》全称、条款序号、官方发布原文链接
  • 通俗条款解读：对专业法条做“白话翻译”，结合常见场景举例说明适用条件、举证要求与法律后果，避免晦涩术语造成误解
  • 规范文书起草：支持12类高频民用法律文书（劳动仲裁申请书、起诉状、借条、离婚协议、强制执行申请书等）生成，自动填充要素、对齐法院官方格式
  • 案情初步评估：用户输入事实经过后，自动梳理争议焦点、匹配类似指导性案例、给出维权路径建议与证据清单
  • 多轮对话澄清：针对用户描述模糊的案情，主动追问关键信息（如时间节点、证据留存情况、地域管辖），避免给出片面结论
  • 风险提示前置：所有回答末尾自动标注法律建议局限性，提醒用户复杂案件咨询执业律师，规避AI生成内容的使用风险

技术架构

组件技术选型作用
大语言模型Qwen2-7B-Instruct（AWQ 4bit量化版）核心推理引擎，负责对话生成、条款解读、文书组织，本地部署无数据泄露风险
向量数据库ChromaDB存储法律文本向量切片，支持毫秒级相似性检索，轻量无额外服务依赖
嵌入模型BAAI/bge-large-zh-v1.5中文通用嵌入模型，对法律长文本的语义匹配精度优于通用开源模型
知识库来源国家法律法规数据库公开爬虫、最高法指导性案例公开集所有知识来源权威，提前做废止法条清洗、版本对齐
前端框架Streamlit快速搭建交互式Web界面，支持对话窗口、表单输入、文书下载功能
检索增强链LangChain编排检索-重排-生成全流程，实现引用溯源、多轮上下文记忆

架构说明：整体采用经典RAG三层架构，第一层为数据层，定期同步国家法律法规数据库的更新内容，做256token滑窗切片、元数据标注（效力级别、发布时间、适用地域）后存入向量库；第二层为引擎层，用户提问后先做query改写，检索Top6相关法条片段，经过bge-reranker-base重排后保留最相关3段送入大模型上下文；第三层为应用层，对不同功能做Prompt路由，严格约束大模型仅基于检索到的内容生成回答，无相关内容时直接告知无法解答，禁止编造法条。

核心代码骨架

# 核心RAG链定义 文件名: legal_rag.py
from langchain.vectorstores import Chroma
from langchain.embeddings import HuggingFaceBgeEmbeddings
from langchain.chat_models import ChatOpenAI
from langchain.chains import ConversationalRetrievalChain
from langchain.prompts import PromptTemplate
# 1. 初始化嵌入模型与向量库
embed_model = HuggingFaceBgeEmbeddings(
    model_name="BAAI/bge-large-zh-v1.5",
    model_kwargs={'device': 'cuda'},
    encode_kwargs={'normalize_embeddings': True}
)
db = Chroma(
    persist_directory="./legal_db",
    embedding_function=embed_model,
    collection_metadata={"hnsw:space": "cosine"}
)
retriever = db.as_retriever(search_kwargs={"k": 3}) # 检索Top3相关片段
# 2. 加载本地量化大模型（通过vllm启动OpenAI兼容接口）
llm = ChatOpenAI(
    model_name="Qwen2-7B-Instruct-AWQ",
    openai_api_base="http://localhost:8000/v1",
    openai_api_key="EMPTY",
    temperature=0.1, # 低温度保证法律回答严谨性
    max_tokens=2048
)
# 3. 法律领域专属Prompt，严格约束幻觉
LEGAL_PROMPT = PromptTemplate.from_template("""
你是专业中国法律咨询助手，必须严格遵守以下规则：
1. 所有回答必须基于下方提供的参考法条，不得编造未提及的法律规定
2. 引用法条必须标注具体法律名称与条款号，不得模糊表述
3. 若参考内容无法回答问题，必须直接说明“根据现有公开法规无法解答该问题，建议咨询执业律师”
4. 回答末尾必须标注风险提示：本内容为AI生成的法律参考，不构成正式法律意见。
参考法条：
{context}
历史对话：
{chat_history}
用户问题：{question}
回答：
""")
# 4. 初始化多轮对话链
legal_chain = ConversationalRetrievalChain.from_llm(
    llm=llm,
    retriever=retriever,
    combine_docs_chain_kwargs={"prompt": LEGAL_PROMPT},
    return_source_documents=True # 返回引用来源，用于前端展示溯源
)
# Streamlit前端入口 文件名: app.py
import streamlit as st
from legal_rag import legal_chain
st.set_page_config(page_title="LegalAssistant 法律咨询助手", page_icon="")
st.title(" LegalAssistant 法律咨询助手")
# 初始化对话历史
if "chat_history" not in st.session_state:
    st.session_state.chat_history = []
# 对话窗口
for query, ans in st.session_state.chat_history:
    with st.chat_message("user"):
        st.write(query)
    with st.chat_message("assistant"):
        st.write(ans)
if query := st.chat_input("请输入你的法律问题或文书需求"):
    with st.chat_message("user"):
        st.write(query)
    with st.chat_message("assistant"):
        with st.spinner("正在检索相关法规..."):
            res = legal_chain({"question": query, "chat_history": st.session_state.chat_history})
            st.write(res["answer"])
            # 展示引用来源
            with st.expander("参考法条来源"):
                for doc in res["source_documents"]:
                    st.write(f" {doc.metadata['law_name']} 第{doc.metadata['article']}条")
    st.session_state.chat_history.append((query, res["answer"]))

运行步骤

  1. 环境准备：安装Python 3.10、CUDA 12.1，执行pip install torch==2.3.1 vllm==0.5.1 langchain==0.2.6 chromadb==0.5.3 sentence-transformers==3.0.1 streamlit==1.36.0安装所有依赖。
  2. 模型下载：从ModelScope下载Qwen2-7B-Instruct-AWQ量化版与bge-large-zh-v1.5嵌入模型，执行modelscope download --model qwen/Qwen2-7B-Instruct-AWQ --local_dir ./models/qwen2-7b-awq、modelscope download --model BAAI/bge-large-zh-v1.5 --local_dir ./models/bge-large-zh。
  3. 知识库构建：从国家法律法规数据库下载《民法典》《劳动合同法》《民事诉讼法》等20部高频民事法律文本，运行python build_kb.py完成文本切片、向量生成与Chroma库持久化存储。
  4. 启动大模型推理服务：新开终端执行python -m vllm.entrypoints.openai.api_server --model ./models/qwen2-7b-awq --quantization awq --gpu-memory-utilization 0.7 --port 8000，等待服务加载完成（约1分钟）。
  5. 启动应用服务：回到项目主目录执行streamlit run app.py --server.port 8501，终端会输出本地访问地址。
  6. 功能测试：打开浏览器访问http://localhost:8501，测试“被公司违法辞退怎么要赔偿”“帮我写一份民间借贷借条”等问题，验证引用法条准确性与文书格式规范性。

扩展思路

  • 接入本地法院管辖规则库：根据用户所在城市、案件类型自动匹配管辖法院、诉讼费计算标准、立案材料清单，提升案情评估的落地性。
  • 增加文书智能审查功能：支持用户上传自有合同、借条等文书，自动识别不公平条款、风险点，给出修改建议与风险等级标注。
  • 对接语音输入输出：集成FunASR语音识别与CosyVoice语音合成，支持方言语音咨询，方便老年用户等打字不便群体使用。
  • 引入多轮案情要素抽取：针对特定纠纷类型（如劳动仲裁）设计结构化提问表单，自动生成可直接打印的完整申请书与证据目录。

小结与练习

核心收获

  1. 掌握垂类RAG应用的完整搭建流程，包括权威知识库清洗、切片策略优化、领域Prompt约束、引用溯源实现，理解如何降低大模型在专业领域的幻觉率。
  2. 学会开源大模型的本地量化部署方法，掌握vllm推理加速、AWQ量化技术，能够在消费级显卡上运行7B参数级别的生产可用模型。
  3. 理解法律垂类AI的合规边界，掌握风险提示前置、输出内容约束的产品设计方法，避免专业领域AI的不当使用风险。

动手练习

  1. 扩展知识库：在现有法律条文库基础上，新增10篇最高法发布的劳动争议指导性案例，重新构建向量库，测试提问“公司末位淘汰合法吗”时是否能匹配到对应案例的裁判规则。
  2. 功能迭代：在现有对话功能基础上，新增“文书下载”按钮，将生成的法律文书自动转换为docx格式，对齐法院官方文书的字体、行距格式要求，支持用户直接下载使用。
