09 号毕业设计：MeetingMinutes 会议纪要官

传统会议纪要依赖人工逐句记录、手动梳理待办，耗时易错且遗漏关键决策，本项目基于大模型与语音识别能力搭建端到端会议纪要Agent，完成后可掌握多模态输入处理、Agent结构化输出、办公场景工作流落地的全流程开发能力。

项目简介

《MeetingMinutes 会议纪要官》是面向中小团队办公场景的轻量化AI Agent，定位为会议全流程记录助手，支持上传本地会议录音、实时麦克风录入两种输入方式，自动完成语音转写、口语顺滑、议题分段、核心决策提炼、待办事项抽取与责任人分派，最终输出可直接分发的结构化会议纪要文档，可对接飞书、企业微信等办公工具自动推送，解决人工记录效率低、信息遗漏、待办追踪难的痛点。项目整体代码量控制在800行以内，无重度依赖，适合个人开发者快速复现与二次定制。

功能特性

  • 多源语音输入：支持wav/mp3/m4a格式本地录音上传、实时麦克风流录入两种模式，自动完成音频降噪、长音频分段切分，适配10人以内1-2小时常规会议场景。
  • 高精度语音转写：集成阿里通义千问ASR/OpenAI Whisper large-v3模型，支持中英文混合、方言识别，自动过滤语气词、重复口语，输出带时间戳的顺滑转写文本。
  • 智能议题提炼：基于GPT-3.5-turbo/通义千问14B大模型，自动识别会议中的不同议题板块，提炼每个议题的核心讨论内容、最终决策结论，避免无关内容干扰。
  • 待办自动分派：通过规则+大模型抽取转写文本中的待办事项，自动匹配对应责任人、截止时间，生成带优先级的待办清单，支持标记待办关联的议题上下文。
  • 多格式纪要导出：支持Markdown、Word、PDF三种格式导出，自动生成会议基本信息头（会议时间、参会人、时长），可自定义模板适配不同团队的纪要规范。
  • 纪要一键推送：内置飞书/企业微信机器人webhook对接能力，生成纪要后可自动推送到指定群聊，支持@对应待办责任人。

技术架构

组件技术选型作用
语音处理层ffmpeg、OpenAI Whisper、pyaudio完成音频格式转换、降噪、实时流采集、语音转文字，输出带时间戳的初始转写稿
文本处理层LangChain、jieba、re正则完成转写稿口语顺滑、长文本分块、参会人姓名识别、待办关键词初筛
Agent核心层GPT-3.5-turbo / Qwen-14B-Chat、Function Calling基于预设Prompt完成议题分段、决策提炼、待办抽取与结构化输出，调用工具完成导出、推送动作
交互层Streamlit、python-docx、reportlab搭建Web操作界面，完成多格式文档生成、文件上传下载、参数配置功能
对接层requests、飞书开放平台SDK对接办公IM机器人，实现纪要自动推送、待办同步到团队协作工具

架构说明：项目采用分层解耦设计，语音层与大模型核心层完全独立，可灵活替换ASR或大模型后端；核心处理流程采用流水线模式，音频输入后依次经过转写、清洗、结构化抽取、生成导出四个阶段，每个阶段输出可缓存、可人工干预修正，避免大模型单次处理长文本出现的幻觉问题；Agent仅负责结构化信息抽取与工具调用，不做冗余生成，保证纪要内容100%来自会议原始转写内容。

核心代码骨架

# 核心处理流水线：meeting_core.py
import os
from whisper import load_model
from langchain.chat_models import ChatOpenAI
from langchain.prompts import ChatPromptTemplate
from docx import Document
class MeetingMinutesAgent:
    def __init__(self, asr_model="large-v3", llm_model="gpt-3.5-turbo"):
        # 加载ASR模型与大模型，可替换为本地开源模型
        self.asr_model = load_model(asr_model, device="cuda" if os.getenv("USE_CUDA") else "cpu")
        self.llm = ChatOpenAI(model=llm_model, temperature=0, base_url=os.getenv("OPENAI_BASE_URL"))
        # 结构化抽取Prompt，严格约束输出格式避免幻觉
        self.extract_prompt = ChatPromptTemplate.from_messages([
            ("system", """你是专业会议纪要助手，基于给定的会议转写文本，输出JSON格式结果，包含3个字段：
            1. topics: 议题列表，每个议题含topic_name、discussion、decision三个子字段
            2. todos: 待办列表，每个待办含content、owner、deadline、priority四个子字段
            3. participants: 参会人列表，严格从文本中提取，不得编造
            所有内容必须完全来自输入文本，不得添加原文没有的信息"""),
            ("human", "会议转写内容：{transcript}")
        ])
    def audio_to_transcript(self, audio_path):
        """第一步：语音转写，输出带时间戳的顺滑文本"""
        result = self.asr_model.transcribe(audio_path, word_timestamps=True, language="zh")
        # 过滤语气词、重复片段，拼接通顺文本
        return "".join([seg["text"].replace("嗯", "").replace("啊", "") for seg in result["segments"]])
    def extract_structured_info(self, transcript):
        """第二步：大模型抽取结构化议题与待办"""
        chain = self.extract_prompt | self.llm
        response = chain.invoke({"transcript": transcript})
        return eval(response.content) # 实际生产建议用json.loads加异常捕获
    def export_docx(self, structured_info, output_path="meeting_minutes.docx"):
        """第三步：导出Word格式纪要"""
        doc = Document()
        doc.add_heading("会议纪要", 0)
        # 写入参会人、议题、待办模块
        doc.add_heading("参会人员", level=1)
        doc.add_paragraph("、".join(structured_info["participants"]))
        doc.add_heading("议题与决策", level=1)
        for topic in structured_info["topics"]:
            doc.add_heading(topic["topic_name"], level=2)
            doc.add_paragraph(f"讨论内容：{topic['discussion']}")
            doc.add_paragraph(f"决策结论：{topic['decision']}")
        doc.add_heading("待办事项", level=1)
        for todo in structured_info["todos"]:
            doc.add_paragraph(f"【{todo['priority']}】{todo['content']} | 责任人：{todo['owner']} | 截止时间：{todo['deadline']}")
        doc.save(output_path)
        return output_path

运行步骤

  1. 环境准备：安装Python 3.10+、ffmpeg（Windows需配置环境变量，Mac执行brew install ffmpeg，Ubuntu执行sudo apt install ffmpeg），创建项目虚拟环境：conda create -n meeting-agent python=3.10 && conda activate meeting-agent。
  2. 安装依赖：执行命令安装核心库：pip install openai-whisper openai langchain streamlit python-docx reportlab pyaudio jieba requests，注意Whisper会自动依赖PyTorch，无GPU环境可提前安装CPU版PyTorch减少安装体积。
  3. 配置环境变量：在项目根目录创建.env文件，写入大模型与ASR配置：OPENAI_API_KEY=你的API密钥、OPENAI_BASE_URL=https://api.openai.com/v1（可替换为第三方中转或通义千问接口地址）、USE_CUDA=0（无GPU设为0）。
  4. 编写Streamlit交互页面：创建app.py，实现文件上传组件、实时录音按钮、结果展示区域，调用上述MeetingMinutesAgent类的三个核心方法串联处理流程。
  5. 启动服务：在项目根目录执行streamlit run app.py --server.port 8501，浏览器自动打开http://localhost:8501即可访问操作界面。
  6. 功能测试：上传一段10分钟以内的测试会议录音（可先用手机录制一段模拟会议音频导出为mp3格式），等待转写与结构化处理完成，验证议题、待办抽取准确性，测试导出与推送功能。

扩展思路

  • 本地模型适配：将ASR替换为Faster-Whisper、大模型替换为Qwen2-7B-Instruct/GLM-4-9B本地部署版本，实现全流程离线运行，满足企业数据不出域的隐私要求。
  • 说话人分离：集成pyannote-audio说话人日志模型，自动区分不同参会人的发言，在转写稿中标记发言人，提升待办分派的准确率，无需提前录入参会人声纹。
  • 待办闭环追踪：对接飞书多维表格、Notion数据库，将抽取的待办自动同步到团队任务系统，支持后续查询待办完成状态，实现会议从记录到落地的全链路闭环。
  • 会议摘要多粒度生成：支持自定义摘要长度，可生成100字以内的会议速览、300字的核心摘要、完整详细纪要三个版本，适配不同角色的信息获取需求。

动手练习

  1. 基于现有代码骨架，新增说话人标记功能：在转写阶段通过正则匹配“我是XXX”“XXX你负责”这类表述，给对应发言片段标记发言人，替换原有参会人抽取逻辑，提升待办责任人匹配准确率。
