先跑起来：一个网页其实就是三个文件

你电脑上新建一个文件夹，里面放三个文件，双击其中一个，浏览器就会打开一个真正的网站——不需要装任何东西，不需要联网。

网页 零基础 2026-11-26

新建文件夹，命名随意，别用中文和空格。里面建三个文件：index.html、style.css、script.js。

index.html 是骨架，浏览器只认它。最小可用写法：写 <!DOCTYPE html>，然后 html、head、body 三层，body 里放一句 <h1>我的第一个网页</h1>。保存，双击 index.html，你会看到那行字。这一步成功，说明你的电脑已经能做网站了。

style.css 是长相。在 index.html 的 head 里加一行 <link rel="stylesheet" href="style.css">。然后在 style.css 里写 body { background: #F4F7FC; font-family: system-ui; }。刷新页面，底色变了，说明样式接上了。

script.js 是动作。在 body 末尾加 <script src="script.js"></script>，在 script.js 里写 console.log('跑起来了')。按 F12 开控制台，看到这行字就对了。

三个文件接通的顺序不能乱：先 html 能打开，再 css 生效，最后 js 有输出。哪一步没反应就停在那一步查，不要三个一起写——一起写会不知道错在哪。

页面一片白 → 文件名必须是 index.html，不是 index.html.txt。Windows 默认隐藏扩展名，去资源管理器「查看」里勾上「文件扩展名」再改名。
样式没生效 → href 路径要和文件同目录。文件名区分大小写，Style.css 和 style.css 是两个文件。

成本：全部免费。编辑器用 VS Code（免费），浏览器用系统自带即可。

让页面能被人看到：三条免费的发布路子

网页在自己电脑上只有你能看见。要发给别人，你得把它放到一台 24 小时开着的机器上——这件事现在有三种完全不花钱的做法。

网页 零基础 2026-11-26

第一种，静态托管。把你的文件夹整体传到 GitHub，在仓库 Settings 里打开 Pages，选分支，几分钟后拿到一个 github.io 的地址。适合纯 HTML/CSS/JS，不需要后端。免费额度对个人站完全够用。

第二种，云开发平台托管。国内访问速度比 GitHub Pages 稳，绑定自有域名也方便。缺点是备案：绑定中国大陆服务器和域名必须备案，个人也能备，只办域名备案即可，不需要营业执照。

第三种，本地起服务给别人临时看。装 Node.js 后在文件夹里敲 npx serve，会给你一个 127.0.0.1 的地址。这个只能自己看，要给别人看得用内网穿透，属于临时演示，不是正式发布。

选哪条看目的：只想有个链接发朋友，第一条；想长期做个站，第二条加备案；只是自己调试，第三条。别一上来就买服务器，个人站完全用不上。

GitHub Pages 打开是 404 → 仓库里必须有 index.html 在根目录（或你指定的发布目录）。文件名错了、或者文件在子文件夹里，都会 404。
绑了域名打不开 → 先去域名商加 A 记录或 CNAME，等解析生效（可能几十分钟）。不要同一天反复改，改一次等一次。

成本：GitHub Pages 免费；云托管有免费额度；备案本身不收费，但域名要钱（一年几十块）。

不用框架也能做出像样的排版：Flex 三行就够

很多人卡在「排不整齐」这一步，然后就去学一整套框架。其实 90% 的排版问题，三行 Flex 就能解决。

网页 入门 2026-11-26

把父容器设成 display: flex，子元素默认横排、等高、自动挤在一起。这一行解决导航栏、卡片行、按钮组。

要竖排就加 flex-direction: column。要居中就写 justify-content: center（主轴）配 align-items: center（交叉轴）。这两行解决「怎么都居不中」这个经典问题。

要平均分就给孩子加 flex: 1。三张卡片各占三分之一，不用算百分比，窗口变了也自动适配。

要换行就加 flex-wrap: wrap，配 gap: 16px 控制间距。这样手机上自动堆成一列，不用写媒体查询。

记住一个判断：一排东西 → flex；一堆东西里的网格 → grid。两个都只是 display 的一个值，不是框架，不用装任何东西。

设了居中但没反应 → flex 写在父元素上，不是子元素。90% 的「没生效」都是写错了层级。
子元素被压扁 → 给子元素加 flex-shrink: 0，或设 min-width。默认允许收缩，内容一多就压没了。

成本：CSS 是浏览器内置能力，零成本。

第一个小程序：从注册到手机上能看到

小程序不用下载安装，微信里点开就能用。但从注册到看见自己的作品，中间有五道必须过的门，少一道就卡住。

小程序 零基础 2026-11-26

第一步，注册账号。去微信公众平台，选「小程序」，用没注册过公众号的邮箱。个人主体可以注册，不需要营业执照。注册完拿到 AppID，这串东西后面要用。

第二步，装开发者工具。搜「微信开发者工具」下稳定版，用微信扫码登录。新建项目时填 AppID，选「不使用云服务」先跑通最简版。

第三步，认目录。pages 放页面，每个页面四个文件：.wxml 是结构（类似 HTML）、.wxss 是样式、.js 是逻辑、.json 是配置。app.json 里登记所有页面路径，没登记的打不开。

第四步，改第一行字。打开 pages/index/index.wxml，把里面的文字改成你自己的。保存，左边模拟器立刻变——小程序开发不用刷新，改完就生效。

第五步，手机上真机预览。工具右上角点「预览」，出二维码，用微信扫。这一步能过，说明项目结构没问题了。

想上线还要提交审核，个人主体能提交，但要选对服务类目。第一次别急着上线，先在真机上跑通再谈发布。

新建项目报「AppID 无效」 → AppID 要从小程序后台「开发管理」里复制，不是公众号的。复制时别带空格。
页面打不开 / 白屏 → 去 app.json 的 pages 数组里确认路径登记了。新增页面必须登记，这是最常见的白屏原因。
预览二维码扫了打不开 → 确认扫码的微信和你登录工具的是同一个账号，且已被加为项目成员。

成本：注册免费，开发工具免费，个人主体可发布。云开发有免费额度，超出才收费。

小程序里最常见的一件事：列表和点击

小程序 80% 的页面都是一个列表加一个点击。学会这两件事，你就能做出记事本、清单、商品列表这类东西。

小程序 入门 2026-11-26

列表用 wx:for。在 wxml 里写 <view wx:for="{{list}}" wx:key="id">{{item.title}}</view>，list 是 js 里 data 的一个数组。数组里有几条就渲染几行，不用自己循环拼字符串。

点击用 bindtap。同一个 view 上加 bindtap="onTap" data-id="{{item.id}}"，然后在 js 里写 onTap(e) 拿 e.currentTarget.dataset.id。data- 后面的名字会被转成小驼峰，data-item-id 取的时候是 dataset.itemId。

改数据必须用 setData。直接写 this.data.list.push(x) 页面不会变，要写 this.setData({ list: newList })。这是新手第一大坑，改完没反应十有八九是这个。

列表要更新某一条时，用 this.setData({ ['list[' + i + '].done']: true })，只改那一项比重设整个数组快。

整套逻辑就这些。真要存住数据，先用 wx.setStorageSync 存本地，不用后端也能做出能用的工具。

改了数据页面不变 → 必须走 setData。this.data 直接赋值只改了内存，不触发渲染。
wx:key 报警告 → wx:key 要写数组里唯一且稳定的字段名（如 id），不要写 item.id 也不要写索引。

成本：本地存储免费无限量（单 key 上限 1MB，总 10MB）。

要让别人也能用：备案这件事到底怎么办

小程序能自己用和能让别人用，中间隔着一道备案。这道门很多人以为要公司才能过，其实个人也能。

小程序 进阶 2026-11-26

先说结论：个人主体可以备案，不需要个体工商户，不需要营业执照。这是很多人卡住的地方——以为必须注册公司，其实不用。

备案分两种。小程序备案在微信公众平台里提交，按提示填主体信息和负责人信息。域名备案要在服务器提供商那边提交（比如腾讯云、阿里云），因为备案是绑在服务器上的。

要准备的材料：身份证正反面、本人手持身份证照片、手机号、邮箱。个人备案不需要公章、不需要租赁合同。

时间上，提交后一般几个工作日到二十天不等，取决于管局审核速度。备案期间网站不能对外提供服务，所以先备案再上线，别反过来。

一个提醒：域名备案和小程序备案是两件事，别以为备了一个另一个就不用。两边都要，而且主体信息要一致。

备案被驳回说「网站内容不符」 → 备案时网站不能有经营性内容（卖货、付费服务）。个人备案只能做非经营性站点，先把付费入口藏起来。
不知道在哪提交 → 域名备案在服务器商的控制台找「备案」入口；小程序备案在微信公众平台后台「设置」里。两处分别办。

成本：备案本身不收费。域名一年几十块，服务器另算；纯静态站用免费托管就不用买服务器。

做出能读的长文页：只需要管住三件事

教程、书稿、长文，最怕的是读者看两行就关掉。问题通常不在内容，在排版的三件事上。

网页 入门 2026-11-26

第一件，行宽。一行太长眼睛会跳行，太短读着累。正文容器最宽设到 720px 左右，超过就居中留白。这一条改完，阅读体验立刻不一样。

第二件，行高和段距。line-height 设 1.7 到 1.8，段间距用 margin 而不是空 <br>。中文正文行高低于 1.6 会挤成一坨。

第三件，字号层级。正文 16~17px，小标题 1.3 倍，大标题 1.6 倍以上。层级只靠字号和粗细区分，不要靠颜色堆——颜色一多就散。

再加一条可选的：深色模式用 prefers-color-scheme 媒体查询，把底色和字色两套变量切一下就行，不用做两套页面。

这三件事都不用装库。写在 style.css 里不到二十行，效果比换个花哨主题明显得多。

手机上字太小 → head 里必须有 <meta name="viewport" content="width=device-width, initial-scale=1">，否则手机会按桌面宽度缩放着看。
长文页两侧贴边 → 给容器加 padding: 0 20px，再配 max-width 和 margin: auto。三者缺一个都会贴边。

成本：纯 CSS，零成本。

上线前必查的七项：省掉正式发布后才发现的问题

我自己的站在正式发布目录里掉过一次队——草稿版有 50 条内容，正式版一条都没有。这类问题上线前查一遍就能拦住。

网页 入门 2026-11-26

查一：所有链接点一遍。站内相对路径最容易错，特别是在子目录里的页面引用上上级资源时。

查二：移动端。浏览器按 F12 切到手机视图，或者直接用手机打开。横向滚动条出现就说明有元素超宽。

查三：图片是否都加载了。路径大小写、扩展名（.jpg 和 .jpeg）、中文文件名都是常见坑。

查四：控制台有没有报错。F12 里红色的一行都不能留，尤其是 404 和 JS 报错。

查五：草稿版和正式发布版是否一致。这条最容易被忽略。如果两套目录分别发布，一定要比对文件内容，不要只看文件名在不在。

查六：有没有把内部文件一起传上去。配置草稿、密钥文件、临时台账，这些不该出现在公开目录。

查七：深色模式下文字还看得清吗。浅色底上写的灰色字，切到深色可能变成隐形。

本地正常，线上 404 → 多半是大小写或路径层级。本地 Windows 不区分大小写，服务器区分。全改小写最稳。
线上看到的是旧版本 → 浏览器缓存。给资源加版本参数（如 style.css?v=2），或强制刷新 Ctrl+F5 验证。

成本：全部零成本，只是多查十分钟。
