Agent 应用平台分类

它解决的是哪一步

先把定位说清楚，再决定要不要装
可视化编排 Agent、知识库、工作流，配好之后直接发布成 API 或者一个可分享的网页。它更接近「开源版 Coze」的定位：给不想从零搭后端的人一条捷径。中文文档齐全，自建的坑比同类少。

上手三步

按顺序走，卡住基本都在第一步
1
docker compose 起一套

官方仓库给了 compose 文件，起完进 80 端口做初始化。生产环境记得把默认密码和 SECRET_KEY 换掉。

2
先做一个最小工作流

别一上来就搭多分支。先「输入 → 提示词 → 输出」跑通，确认能发布，再往里加知识库和工具。

3
发布拿 API Key

发布后在「访问 API」里生成 key，你的前端或脚本直接调，这一步是它比手搓后端省事的关键。

适合与不适合

不适合的部分比适合更值得看

适合你，如果

  • 要给业务方交付一个 AI 应用，但没有前端资源
  • 需要把流程固化成可复用、可版本管理的编排
  • 想快速比较不同模型在同一个流程下的效果

换别的，如果

  • 需要极致定制的交互和视觉
  • 超大规模、要自己做深度性能优化的服务
  • 注意许可带附加条款，商用前要读一遍
