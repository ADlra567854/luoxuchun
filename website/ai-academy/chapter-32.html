本章将带你掌握 Google 官方生产级端侧大模型推理框架 LiteRT-LM 的核心原理与落地方法，学完后你可以独立完成手机、嵌入式设备上的离线大模型部署，搭建零API成本、数据完全不出设备的本地AI助手，覆盖Android/iOS/Linux/Web全平台场景。

为什么需要端侧大模型推理

端侧大模型推理的核心价值是将大模型的计算流程完全运行在用户本地设备（手机、平板、嵌入式板卡、浏览器）上，无需将任何用户输入上传到云端服务器，首先解决的是隐私合规痛点：所有对话记录、个人文档输入、设备状态数据完全留在本地，天然满足《个人信息保护法》《GDPR》对敏感数据不出域的要求。其次是体验优势：无网络传输延迟，弱网、断网场景下完全可用，也不会产生云端API调用成本，适合智能输入法、离线翻译、车载助手等对可靠性要求极高的场景。

和本教程第20章介绍的Ollama服务端私有化部署相比，两者是互补而非替代关系：Ollama面向x86/ARM服务器、桌面PC场景，适合运行7B/70B等中大型参数模型，为局域网内多设备提供推理服务；LiteRT-LM面向单设备端侧场景，针对1B-8B参数小模型做了极致的内存、功耗优化，直接调用设备NPU/GPU硬件加速，不需要额外部署服务进程。

两者的核心差异可以参考下表：

部署目标手机、嵌入式、浏览器单设备PC、服务器、局域网节点

适用场景个人本地助手、离线功能团队共享服务、本地开发测试

验证方式：可分别在手机和本地PC上运行同参数级Gemma模型，对比断网下的可用性与内存占用。

什么是 LiteRT-LM

LiteRT-LM是Google在2025年推出的生产级端侧大语言模型推理编排层，其底层运行时LiteRT是原TensorFlow Lite的官方演进版本，专门针对生成式AI场景做了全链路优化，负责在端侧设备上高效完成大模型的加载、分词、推理、解码全流水线调度。项目采用Apache-2.0开源协议，官方GitHub仓库为google-ai-edge/LiteRT-LM，截至2026年8月最新稳定版本为v0.16.1（版本号请以GitHub Releases页为准），官方文档地址为ai.google.dev/edge/litert。

和早期的实验性端侧推理框架不同，LiteRT-LM是Google官方面向生产环境的方案，已经在Google Assistant、Gboard智能输入法、Pixel设备端侧AI功能中大规模落地，不是玩具级Demo项目。框架本身不绑定特定模型格式，同时支持.tflite、.task两种官方优化格式，也兼容部分GGUF格式模型的转换导入，开发者不需要深入理解底层算子实现，就可以快速集成端侧大模型能力。

验证方式：执行git clone https://github.com/google-ai-edge/LiteRT-LM.git拉取官方仓库，查看RELEASE.md文件确认版本信息。

核心架构与硬件加速能力

LiteRT-LM的核心架构分为三层：最底层是LiteRT跨平台运行时引擎，负责对接不同设备的硬件加速接口；中间层是模型转换与优化流水线，支持将主流开源大模型权重转换为端侧优化格式，内置KV-Cache量化、算子融合、 speculative decoding 等生成式推理优化，可将端侧推理速度提升2-4倍；最上层是各平台的API封装层，提供Java/Kotlin、Swift、C++、JavaScript多语言接口，覆盖Android/iOS/Linux/嵌入式/Web全平台执行环境。

硬件加速是LiteRT-LM的核心优势：框架原生支持设备专用NPU的无缝调用，在搭载Google Tensor、高通骁龙8 Gen3及以上、联发科天玑9300及以上芯片的Android设备上，可自动调度NPU执行推理，不需要开发者编写硬件适配代码；同时支持GPU Delegate，可调用设备GPU完成并行计算；针对Linux ARM64嵌入式设备，提供实验性YNNPACK Delegate，优化CPU推理性能。根据社区公开测试数据，同参数同量化等级下，LiteRT-LM的NPU推理速度相比llama.cpp有30%以上的领先（实际性能请以具体设备实测为准）。

Linux平台下可通过以下命令验证硬件加速支持：

# 下载LiteRT-LM CLI工具（Linux arm64版本，版本以官方Release为准）
wget https://github.com/google-ai-edge/LiteRT-LM/releases/download/v0.16.1/litert-lm-cli-linux-arm64
chmod +x litert-lm-cli-linux-arm64
# 查看当前设备支持的硬件加速后端
./litert-lm-cli-linux-arm64 list-backends

支持模型与跨平台实战路径

LiteRT-LM官方优先支持Google自家开源的Gemma全系列模型，包括Gemma 3、端侧专用Gemma 3n、Gemma 4全尺寸权重，官方提供预转换好的INT4/INT8量化版本，开发者不需要自行转换就可以直接部署；同时也支持Llama 3.2、Qwen 2.5等主流开源开放权重模型，完整支持列表请以官方Model Garden页面为准。

官方提供了四条开箱即用的跨平台集成路径，覆盖主流端侧场景：

  • Android端：提供Java/Kotlin原生API，可直接在Android Studio中通过Gradle依赖集成，官方自带agent-skill示例工程，可快速实现端侧Agent能力
  • iOS/macOS端：提供官方Swift包，支持CocoaPods与Swift Package Manager（SPM）两种集成方式，最低支持iOS 16系统
  • Linux命令行：提供独立CLI工具，内置OpenAI兼容接口的本地Server，启动后其他程序可直接用OpenAI SDK调用本地模型
  • Web端：基于2026年7月Google发布的LiteRT.js（信息以官方博客为准），可在浏览器内完成大模型推理，不需要服务端支持

Linux端启动OpenAI兼容本地服务的命令如下：

# 下载预转换的Gemma 3n 2B INT4模型（路径以官方Model Garden为准）
wget https://www.kaggle.com/api/v1/models/google/gemma-3n/litert/int4/2b-it/1/download -O gemma3n-2b-int4.task
# 启动本地服务，端口8080，兼容OpenAI接口
./litert-lm-cli-linux-arm64 serve --model gemma3n-2b-int4.task --port 8080
# 验证：用curl调用本地接口
curl http://localhost:8080/v1/chat/completions -H "Content-Type: application/json" -d '{"model":"gemma3n-2b","messages":[{"role":"user","content":"你好"}]}'

模型转换与端侧Agent实践

如果官方预转换模型不满足需求，开发者可以通过LiteRT-LM提供的转换工具完成自定义模型部署，完整链路为：原始开源权重（Hugging Face格式） 权重量化（INT4/INT8，支持AWQ、GPTQ等量化算法） LiteRT格式转换（算子融合、KV-Cache优化） 部署到目标设备。转换过程的具体命令与参数请以官方转换文档为准，官方已提供Gemma、Llama、Qwen系列模型的一键转换脚本，不需要手动编写算子适配代码。

端侧Agent是LiteRT-LM的特色能力，官方Android示例中的agent-skill模块可以让本地运行的大模型直接调度设备原生能力，完成多步复杂任务：比如用户输入“帮我把昨天拍的风景照发给微信好友张三”，本地模型会自动拆解为“查找相册中昨天的风景照片打开微信搜索好友张三发送选中照片”的步骤，全程不需要联网，所有数据都在设备本地处理。

Android端集成LiteRT-LM依赖的Gradle配置如下：

// Android build.gradle 模块级配置
dependencies {
    // 引入LiteRT-LM Android依赖，版本以官方Maven仓库为准
    implementation "com.google.ai.edge.litert:litert-lm:0.16.1"
    // 引入Agent Skill能力包
    implementation "com.google.ai.edge.litert:litert-lm-agent:0.16.1"
}

选型对比与注意事项

端侧推理和云端推理没有绝对优劣，需要根据场景选择：端侧模型受设备内存、功耗、发热约束，参数规模通常在8B以下，推理质量不如云端GPT-4o、Gemini Advanced等旗舰模型，但胜在隐私安全、零成本、离线可用，适合隐私敏感问答、离线翻译、本地智能助手、智能输入法联想等场景；云端模型适合需要复杂推理、多模态大参数量、对生成质量要求极高的场景。

和同类端侧推理方案相比，LiteRT-LM的定位差异非常清晰，开发者可根据需求选择：

方案定位核心优势适用场景
LiteRT-LMGoogle官方生产级端侧推理编排层原生NPU加速、全平台支持、生产级稳定消费级App端侧AI功能落地
Ollama桌面/服务端本地推理工具模型生态全、部署简单本地开发、PC端个人助手
llama.cpp社区级轻量推理引擎极致轻量化、GGUF生态完善嵌入式设备DIY、二次开发
MediaPipe LLMGoogle面向快速集成的GenAI API封装度高、代码量少简单Demo、快速原型验证

使用LiteRT-LM时也需要注意几个局限：一是官方支持的模型列表仍在扩充中，部分小众开源模型需要自行转换适配；二是Android设备NPU硬件碎片化严重，中低端设备可能无法启用NPU加速，推理速度较慢；三是模型首次加载需要占用3-10秒时间，运行时内存占用根据模型大小在1GB-6GB之间，需要对低端设备做兼容性适配。

小结与练习

核心收获

  1. 端侧大模型推理具备隐私优先、零延迟离线可用、无API成本三大核心优势，和Ollama服务端私有化部署是互补关系，分别面向单设备端场景和局域网服务场景。
  2. LiteRT-LM是Google官方推出的生产级端侧推理框架，基于演进后的LiteRT运行时，原生支持NPU/GPU硬件加速，覆盖Android/iOS/Linux/Web全平台，可快速部署Gemma等开源小模型。
  3. LiteRT-LM内置端侧Agent能力，支持本地模型调度设备原生能力，天然满足数据不出域的合规要求，适合消费级App的离线AI功能落地。

动手练习

  1. 在Linux ARM64设备（或树莓派5、Android Termux环境）下载LiteRT-LM CLI工具，启动Gemma 3n 2B INT4模型的OpenAI兼容服务，用curl命令完成一次本地对话调用。
  2. 在Android Studio中导入官方agent-skill示例工程，在测试机上安装运行，测试“打开相册选中第一张照片”的本地Agent指令。
  3. 对比同模型在LiteRT-LM NPU加速和CPU模式下的生成速度，记录每秒钟生成的token数量。
