NVIDIA Nemotron 3.5 Lightning：面向长时 Agent 的混合架构开源模型实战

本章将带你掌握NVIDIA 2026年8月发布的开源长时Agent专用执行模型Nemotron 3.5 Lightning的核心架构、优化逻辑与全场景部署方法，学完可独立搭建「前沿模型做规划、Lightning做高吞吐执行」的分层Agent系统，落地成本比纯前沿模型方案有明显下降（幅度取决于任务拆分与并发规模，需自测）。

模型定位与发布背景

2026年8月11日NVIDIA正式开源Nemotron 3.5 Lightning系列模型，本次发布的核心版本为nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-NVFP4，采用OpenMDW-1.1商业友好开源许可，官方技术说明可在NVIDIA开发者博客（developer.nvidia.com/blog/Nvidia-nemotron-3-5-lightning-delivers-fast-accurate-specialized-task-execution-for-long-running-agents）查阅，所有参数请以官方文档为准。该模型为30B总参数、单token仅激活3B参数的MoE架构，核心定位是长时自主Agent的执行层：由 GPT-6 系列、Nemotron 4 Ultra 这类前沿推理模型负责高层任务规划与复杂决策编排，Lightning负责高吞吐、低延迟的工具调用、结果校验、状态回写等高频重复操作。

本章节是白驹AI学院Agent技术栈的核心拼图：与第34章NVIDIA NOOA对象导向Agent框架构成姊妹篇——一个是Agent框架范式，一个是专为Agent执行层设计的开源模型；同时衔接第20章Ollama私有化部署、第32/33章端侧模型部署、第36章Orchard Agent训练基础设施，完整覆盖「Agent模型+框架+训练+部署」全链路能力。你可以通过Hugging Face模型卡（huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-NVFP4）核验模型基本信息与许可协议。

核心混合架构拆解

Nemotron 3.5 Lightning没有采用纯Transformer架构，而是使用Mamba-2 + MoE + 稀疏Attention的混合设计，所有架构参数以官方技术说明为准：其中Mamba-2状态空间模型负责处理长序列的线性扫描，将1M上下文的长序列处理开销控制在O(n)级别，避免纯Transformer注意力O(n²)的显存爆炸问题；MoE路由层为每token动态选择最相关的专家子网络，实现30B总参规模下单token仅激活3B参数，兼顾大模型的知识容量与小模型的推理速度；稀疏注意力层仅对任务依赖的关键token（如工具返回结果、系统提示词）做注意力计算，处理跨段关键依赖。

模型在预训练阶段原生嵌入了Multi-Token Prediction（MTP）层，无需额外微调即可支持投机解码，从架构层面降低推理延迟。官方公布的上下文长度为1M token：单卡H100 80GB可稳定运行256K上下文，满1M上下文需8×H100配置TP8+EP并行，或Blackwell架构的GB200/B200单节点即可承载，具体并行配置请以官方部署文档为准。你可以通过NVIDIA NeMo官方仓库的架构说明文档核验设计细节。

架构模块核心作用性能收益
Mamba-2长序列线性扫描1M上下文显存占用降低70%（以官方为准）
MoE路由单token激活3B专家推理速度达到同精度稠密模型的3-4倍（以官方为准）
稀疏Attention关键依赖建模工具调用准确率提升12%（以官方为准）
原生MTP层多token并行预测投机解码接受率提升至85%以上（以官方为准）

推理优化三板斧

Nemotron 3.5 Lightning从架构、量化、训练三个维度做了端到端推理优化，第一板斧是原生投机解码支持：依托预训练阶段嵌入的MTP层，模型可同时预测后续多个token，官方配套两个草稿模型适配不同场景——DSpark适配DGX Spark与低并发数据中心场景，DFlash适配Blackwell架构的高并发场景，用户可根据并发量动态选择最优草稿长度，最高可将单token生成延迟降低60%，具体参数配置请以官方推理文档为准。

第二板斧是NVFP4量化支持：官方同时发布BF16与NVFP4双精度权重，其中NVFP4是NVIDIA推出的4位浮点量化格式，配套专用内核可支持Blackwell、Hopper、Ampere三代GPU，同一NVFP4权重文件可从数据中心H200/GB200直接运行到桌面级DGX Spark、消费级RTX 5090，无需二次转换。第三板斧是Agent Harness定向优化：模型预训练与SFT阶段针对主流Agent工具调用框架做了专项训练，工具调用格式错误率比通用MoE模型降低40%，端到端任务执行延迟降低30%，具体基准以官方公布为准。你可以通过TensorRT-LLM官方仓库的NVFP4支持说明核验量化兼容性。

NeMo Switchyard 分层路由方案

长时Agent运行时如果全部调用前沿大模型，不仅成本高，还会因为高延迟导致任务超时；如果全部调用小模型，复杂规划能力不足。NVIDIA为此开源了NeMo Switchyard路由组件（GitHub: NVIDIA-NeMo/Switchyard），核心逻辑是基于任务类型自动做模型路由：将复杂任务拆解、跨工具依赖规划、异常逻辑处理这类规划类任务路由到 Nemotron 4 Ultra、GPT-6 系列这类前沿模型，将工具调用参数生成、返回结果格式校验、任务状态更新这类高频执行类任务路由到Nemotron 3.5 Lightning，实现token成本与任务效果的最优平衡。

Switchyard可配合NemoClaw开源安全与管理堆栈使用，为always-on长时运行Agent提供权限管控、调用审计、故障自动恢复能力，避免长时运行过程中的权限泄露、任务卡死问题。官方提供了最小可运行路由示例，你可以直接通过以下命令拉取官方示例代码验证：

# 克隆Switchyard官方仓库
git clone https://github.com/NVIDIA-NeMo/Switchyard.git
cd Switchyard
# 安装依赖（要求Python 3.10+）
pip install -e .
# 运行最小路由示例（需提前配置NVIDIA API Key）
python examples/minimal_routing.py --planner-model nemotron-4-ultra --executor-model nemotron-3.5-lightning

自定义微调与性能基准

Nemotron 3.5 Lightning开箱支持LoRA高效微调与全量SFT训练，用户可通过NeMo Automodel组件一键加载模型，配合NeMo Megatron Bridge实现分布式训练；强化学习阶段可通过NeMo RL + NeMo Gym搭建Agent交互环境，官方同步开源了Nemotron-RL Agentic Terminal Pivot数据集，包含12万条终端工具调用的Agent交互轨迹，可直接用于微调终端场景的专用Agent版本，数据集地址以NVIDIA NeMo官方仓库为准。

官方公布的性能基准显示，该模型在Artificial Analysis Intelligence Index上定义了小模型精度-速度Pareto前沿，在PinchBench 10000项Agent任务基准中，端到端执行速度比Qwen3.6 35B快30%，任务完成精度与后者相当，所有基准数据请以官方模型卡公布为准，第三方独立测试结果可待社区后续发布。你可以通过Hugging Face模型卡的Benchmark章节核验官方基准数据。

微调场景的官方推荐配置如下（以官方文档为准）：

  • LoRA微调：单卡RTX 5090 32GB即可运行，适配垂直场景工具调用格式定制
  • 全量SFT：8×H100 80GB集群，适配行业专属Agent能力训练
  • RL训练：16×H200集群，配合NeMo Gym环境做长时任务策略优化

全场景部署实战

Nemotron 3.5 Lightning提供了从在线体验到生产级服务化的全路径部署方案，所有命令以官方文档为准：第一类是零代码体验路径，可直接通过build.nvidia.com的在线Demo体验效果，或通过OpenRouter API免费调用，模型ID为nvidia/nemotron-3.5-lightning；第二类是本地一键部署路径，支持Ollama、LM Studio、llama.cpp、Unsloth等主流推理框架，以Ollama为例，仅需一行命令即可启动本地服务：

# 拉取并运行NVFP4量化版本（要求Ollama 0.6.0+版本）
ollama run nemotron-3.5-lightning:30b-a3b-nvfp4

第三类是生产级服务化部署路径，支持vLLM、SGLang、TensorRT-LLM等高性能推理框架，官方在GitHub仓库提供了完整的Jupyter Notebook cookbook，包含动态批处理、投机解码配置、多卡并行等最佳实践；第四类是分层Agent部署路径，可基于前文中的NeMo Switchyard搭建自动路由系统，对接NOOA框架实现完整的长时Agent能力。部署完成后可通过curl http://localhost:11434/api/generate -d '{"model":"nemotron-3.5-lightning:30b-a3b-nvfp4","prompt":"写一个调用计算器计算123*456的工具调用JSON"}'命令验证本地服务是否正常。

硬件成本、生态适配与选型边界

硬件要求方面，NVFP4量化版本可在单卡RTX 5090（32GB显存）、DGX Spark、Jetson AGX Orin 64GB等边缘/桌面设备上运行128K上下文，数据中心侧可通过H100/H200/Blackwell集群搭建高并发服务，按token计费的成本仅为前沿推理模型的1/10到1/20（以官方云服务定价为准）。生态适配方面，推理层已经接入Ollama、LM Studio、Exo、Unsloth等主流框架；Agent Harness层已经适配Cline、OpenClaw、OpenHands、LangChain、OpenCode、Pi等主流Agent开发框架；云服务侧已经在SageMaker JumpStart、Together AI、Fireworks AI、CoreWeave等平台上线，可直接调用API。

选型上需要遵循System of Models的分层理念：不要用Lightning做复杂数学推理、长链逻辑规划、创意生成这类需要强推理能力的任务，这类场景交给前沿模型做大脑；也不要用前沿模型做高频工具调用、格式校验、状态回写这类重复性执行任务，这类场景交给Lightning做手脚，才能实现成本、速度、效果的最优平衡。目前模型的局限包括：30B总参的NVFP4版本仍需要至少20GB显存，无法在移动端运行；Mamba-2架构的推理生态成熟度仍不如纯Transformer，部分老旧推理框架可能需要升级版本才能支持；官方公布的基准为内部测试结果，生产场景使用前建议做独立业务验证。你可以通过Ollama官方模型库核验模型的硬件要求与支持版本。

小结与练习

核心收获

  1. Nemotron 3.5 Lightning是NVIDIA推出的30B总参/3B激活MoE模型，采用Mamba-2+MoE+Attention混合架构，原生支持1M上下文与投机解码，核心定位是长时Agent的高吞吐执行层。
  2. 模型通过原生MTP投机解码、NVFP4跨代GPU量化、Agent Harness定向优化三板斧实现了精度与速度的平衡，配合NeMo Switchyard路由组件可搭建「前沿模型规划+Lightning执行」的分层Agent系统，成本比纯前沿模型方案有明显下降（幅度取决于任务拆分与并发规模，需自测）。
  3. 模型支持从本地消费级GPU到数据中心集群的全场景部署，已经接入主流推理框架、Agent开发工具与云平台，开箱即可对接现有Agent工作流。

动手练习

  1. 本地部署验证：安装最新版Ollama，执行ollama run nemotron-3.5-lightning:30b-a3b-nvfp4命令启动本地模型，测试3次工具调用生成任务，统计平均响应延迟。
  2. 路由系统搭建：克隆NeMo Switchyard仓库，配置NVIDIA API Key，运行官方最小路由示例，分别测试规划任务与执行任务的路由效果，对比两类任务的单token成本差异。
  3. 基准测试：使用PinchBench的开源Agent测试子集，分别测试本地部署的Lightning与你常用的7B/14B开源模型的工具调用准确率与速度，对比性能差异。
