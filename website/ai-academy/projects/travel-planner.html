15 号毕业设计：TravelPlanner 行程规划师

本项目解决传统旅行规划需跨平台查攻略、拼交通、算预算且遇突发情况难调整的痛点，带你从零搭建多约束旅行Agent，掌握工具调用、约束求解、ReAct推理等工程化能力，可直接落地为实用出行工具。

项目简介

TravelPlanner 行程规划师是面向个人出行场景的垂直领域 Agent 应用，基于大模型推理能力整合多源出行数据，支持在时间、预算、出行人数、偏好标签等多重约束下自动生成可执行的每日行程，同时可根据实时交通、天气、景点临时关闭等事件动态调整方案。项目从真实出行需求出发，覆盖从用户意图解析、多工具信息检索、约束满足编排到行程可视化输出的全链路，所有组件均采用开源可部署方案，无需依赖付费闭源生态即可完整复现。

功能特性

  • 多约束行程编排：支持输入出行日期、总预算、同行人群（亲子/情侣/独自）、步行耐受度、偏好标签（人文/自然/美食）等8类约束，自动生成小时级 granularity 的每日行程，自动规避跨城通勤时间冲突
  • 多源景点/餐饮推荐：对接高德开放平台POI、大众点评公开评分、小红书热门标签数据，基于用户偏好做混合召回，自动过滤评分低于4.2、近期有差评预警的点位
  • 实时行程调整：接入和风天气实时API、12306余票/延误信息、景点临时闭园通知，遇到突发情况自动生成替代方案并同步更新全链路时间、预算变动
  • 预算自动核算：分交通、住宿、门票、餐饮、伴手礼5个类目实时统计花费，超预算时自动给出高性价比替换选项（如将收费景点替换为同类型免费点位）
  • 行程导出分享：支持生成Markdown格式行程单、高德地图可导入的路书KML文件，可直接分享给同行人协同编辑
  • 自然语言交互：支持用户用口语化指令调整行程（如“把第三天的爬山换成室内展馆”“预算砍20%”），无需重新填写表单

技术架构

组件技术选型作用
大模型推理层Qwen2-7B-Instruct（本地部署）/ GPT-3.5-turbo（云端可选）负责意图解析、约束抽取、行程推理、自然语言交互
Agent框架LangChain v0.2 + LangGraph实现ReAct推理循环、工具调用编排、多轮对话状态管理
约束求解模块Google OR-Tools解决时间窗口、路径最短、预算上限等多约束组合优化问题，避免大模型生成逻辑冲突的行程
工具层高德地图Web服务API、和风天气API、12306非官方查询接口、Chroma向量数据库提供POI检索、路径规划、天气查询、余票查询、本地攻略知识库检索能力
前端层Streamlit快速搭建可交互Web界面，支持行程可视化、参数调整、文件导出
数据存储SQLite存储用户历史行程、POI缓存数据，减少重复API调用

架构说明：整体采用分层设计，用户输入首先进入大模型推理层做意图识别与约束抽取，结构化参数传入约束求解模块做初始行程框架生成，再由Agent循环调用工具层接口填充点位、交通、天气等实时数据，生成的初步行程经冲突校验（如景点开放时间、通勤时长）后返回前端，若用户触发调整或系统检测到实时事件变动，则重新进入推理循环做局部更新，所有外部API返回结果均做24小时缓存以降低调用成本。

# 核心模块1：多约束行程编排主逻辑（langgraph节点定义）
from langgraph.graph import StateGraph, END
from ortools.constraint_solver import pywrapcp
from tools import amap_poi_search, weather_query, route_plan

class TravelState(TypedDict):
    user_constraints: dict  # 解析后的用户约束：时间、预算、偏好等
    poi_candidates: list   # 候选景点/餐饮列表
    schedule: list         # 最终行程
    budget_calc: dict      # 预算统计
    error_msg: str

def constraint_extract_node(state: TravelState, llm):
    """节点1：从用户自然语言输入中抽取结构化约束"""
    prompt = f"从以下用户需求抽取出行约束，输出JSON：{state['user_input']}"
    state["user_constraints"] = llm.invoke(prompt, response_format="json")
    return state

def poi_recall_node(state: TravelState):
    """节点2：基于约束召回候选POI，过滤低评分点位"""
    pois = amap_poi_search(city=state["user_constraints"]["city"],
                          tags=state["user_constraints"]["prefer_tags"],
                          radius=3000)  # 优先召回住宿点3公里范围内点位
    state["poi_candidates"] = [p for p in pois if p["score"] >= 4.2]
    return state

def schedule_solve_node(state: TravelState):

workflow = StateGraph(TravelState)
workflow.add_node("constraint_extract", constraint_extract_node)
workflow.add_node("poi_recall", poi_recall_node)
workflow.add_node("schedule_solve", schedule_solve_node)
workflow.set_entry_point("constraint_extract")
workflow.add_edge("constraint_extract", "poi_recall")

# 核心模块2：实时行程调整触发逻辑
def realtime_monitor(schedule):
    """后台线程监控实时事件，触发行程调整"""
    for day in schedule:
        for point in day["points"]:
            # 检查天气：若遇暴雨则替换室外点位
            weather = weather_query(point["location"], point["time"])
            if weather["rainfall"] > 10 and point["type"] == "outdoor":
                trigger_adjust(point, reason="暴雨预警", replace_type="indoor")
            # 检查交通：若通勤路线拥堵时长超30分钟则替换路线
            route = route_plan(point["from"], point["to"], point["depart_time"])
            if route["duration"] > point["reserved_time"] * 1.5:
                trigger_adjust(point, reason="交通拥堵", reroute=True)

运行步骤

  1. 环境准备：安装Python 3.10+，创建虚拟环境并安装依赖：pip install langchain==0.2.11 langgraph==0.1.1 ortools==9.10.4067 streamlit==1.37.0 chromadb==0.5.3 requests python-dotenv
  2. 申请API密钥：分别注册高德开放平台、和风天气开发者账号，获取Web服务API Key，本地新建.env文件写入AMAP_KEY=你的密钥、WEATHER_KEY=你的密钥
  3. 初始化本地缓存：运行python init_db.py，自动创建SQLite缓存库并导入热门城市TOP200景点基础数据（项目仓库自带data/poi_base.json种子数据）
  4. 配置大模型：若使用本地Qwen2-7B，先启动Ollama服务并执行ollama run qwen2:7b-instruct；若使用云端GPT，在.env中追加OPENAI_API_KEY=你的密钥即可自动切换
  5. 启动应用：在项目根目录执行streamlit run app.py --server.port 8501，浏览器访问http://localhost:8501即可进入交互界面
  6. 功能验证：在输入框输入“国庆3天和朋友去杭州，预算2000/人，喜欢自然风景和本地美食，不要太赶”，等待3-5秒即可生成完整行程，可点击“实时检查”按钮触发天气/交通校验
  7. 导出测试：生成行程后点击“导出KML路书”，验证文件可正常导入高德地图APP查看路线

扩展思路

  • 多模态行程生成：接入Stable Diffusion文生图模型，为每个景点自动生成打卡攻略配图，同时支持用户上传旅行参考图，识别图中景点风格后匹配相似点位
  • 社交协同功能：加入多人协同编辑模块，支持同行人通过链接共同调整行程，自动合并多人偏好冲突（如有人想逛博物馆有人想逛街时，自动拆分半日自由活动时间）
  • 行程记忆模块：对接用户历史旅行记录，基于过往出行偏好（如常住酒店品牌、常选餐饮口味）做个性化推荐，避免重复推荐去过的点位
  • 端侧部署适配：将模型压缩为Qwen2-1.8B量化版本，适配手机端部署，无需云端服务即可在离线状态下生成基础行程，适合境外无网络场景使用
