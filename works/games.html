新人指引 · 四条路选一条，别都学

  • ① 完全没写过代码选 Python + Pygame。语法门槛最低，出错信息最好读，一个贪吃蛇 80 行就能动。
  • ② 会一点网页选 JavaScript + Canvas。不用装任何东西，浏览器里直接跑，MDN 有官方手把手教程。
  • ③ 想做完整游戏选 Godot。免费开源、不用写太多代码、能导出到手机，官方自带示例工程。
  • ④ 想练工程能力选 Rust + Bevy 或 TypeScript + Phaser。类型系统帮你少踩坑，但学习曲线陡。

最适合：完全零基础 · 2D 小游戏 · 教学演示

语法最宽容，出错信息直接告诉你哪一行错了。贪吃蛇、打砖块、俄罗斯方块这类「一个画面 + 几个方块」的游戏，一天能做完一个。缺点是不适合做 3D 和上手机。

LGPL 可分发官方示例 30+Windows/Mac 都能装

六类小游戏，各自的技术难点在哪

不是"推荐玩什么"，而是"做这类游戏会卡在哪"。知道难点，才不会做到一半放弃。

🐍

贪吃蛇 / 俄罗斯方块

难度：★☆☆☆☆ · 半天可完成

难点只有一个：网格坐标与碰撞判定。把画面切成格子，蛇身存成一个坐标数组，每次移动头进尾出。俄罗斯方块多一个「旋转后的边界检查」。这是最推荐用来练手的第一款。

网格逻辑无美术需求
🧱

打砖块 / 弹球

难度：★★☆☆☆ · 一到两天

难点是反弹角度：球撞到挡板的不同位置要给不同反射角，否则手感很怪。还要处理「高速球穿墙」——每帧位移大于砖块厚度时会漏检，得做细分检测。

向量反射连续碰撞检测
🏃

跑酷 / 横版过关

难度：★★★☆☆ · 三到五天

难点在手感：重力、跳跃初速、二段跳的宽容时间、落地缓冲，这几个数字要反复调。其次是地图滚动与相机跟随。代码量不大，但调参数占大半时间。

物理调参相机跟随
🔫

弹幕 / 射击

难度：★★★☆☆ · 三到七天

难点是性能：屏幕上同时几百发子弹时，逐对检测碰撞会卡。要用空间网格或环绕排序降复杂度。其次是弹幕模式设计——用公式生成比手摆坐标优雅得多。

碰撞优化对象池
🧩

解谜 / 三消 / 数独

难度：★★☆☆☆ · 一到三天

UI 和交互占大头，游戏逻辑反而简单。数独的关键是生成合法题面（先造完整解再挖洞，挖的时候校验唯一解）。三消的关键是消除后的下落补位与连锁判定。

算法为主无需物理
🌾

经营 / 种田 / 挂机

难度：★★★★☆ · 一周以上

难点不在画面，在数值系统：产出速率、资源消耗、解锁节奏要形成正反馈循环。再加上存档（离线收益要按时间差补算）。这类最容易做成"能跑但不好玩"。

数值平衡存档系统

第一个下午：三个「今天就能跑起来」的目标

不要一上手就做 RPG。先把这三件做成，你会知道自己适不适合继续。

1️⃣

让一个方块动起来

目标时长：30 分钟

画一个矩形，用方向键控制它移动，碰到边界就停。这一步打通了「输入 → 状态 → 渲染」这条循环，后面所有游戏都是它的扩展。

游戏循环键盘输入
2️⃣

做一个能结束的贪吃蛇

目标时长：2-3 小时

加上食物、变长、撞自己就结束、显示分数。做完这个你就掌握了「数组状态机」这个最核心的套路，后面能套到很多游戏上。

状态数组碰撞判定
3️⃣

加一个开始/结束界面

目标时长：1 小时

很多人卡在这：游戏能玩但没有开始和结束，就不算完成品。加上「点击开始 → 游戏 → 死了按 R 重开」这个循环，你就有第一个完整的作品了。

场景切换完整闭环

源码许可怎么读（这一步别省）

抄源码之前先看清许可，避免做出成品后才发现不能发布。

✅

MIT / Apache-2.0 / zlib

最常见于游戏引擎和小游戏仓库

可以商用、可以闭源、可以改。唯一要求是保留原作者的版权声明文件。做出来的游戏可以上架、可以卖。

可商用
⚠️

GPL / LGPL

Pygame 是 LGPL

LGPL 允许你的游戏闭源（只要你没改引擎本身），但如果你修改了引擎代码，那部分要开源。GPL 更严，整个作品都要开源。上架前要看清。

注意闭源边界
🚫

无许可 / 仅供学习

很多个人练手仓库属于这一类

仓库里没有 LICENSE 文件，默认就是「保留所有权利」——技术上你不能分发。可以读、可以学思路，但别整个抄下来发布。
